#### Cloud Spanner Viewer (`roles/spanner.viewer`)

- A principal with this role can: - View all Spanner instances (but cannot modify instances). - View all Spanner databases (but cannot modify or read from databases). For example, you can combine this role with the `roles/spanner.databaseUser` role to grant a user with access to a specific database, but only view access to other instances and databases. This role is recommended at the Google Cloud project level for users interacting with Cloud Spanner resources in the Google Cloud console. Lowest-level resources where you can grant this role: - Instance - Database

#### Cloud Spanner Database Role User (`roles/spanner.databaseRoleUser`)

- In conjunction with the IAM role Cloud Spanner Fine-grained Access User, grants permissions to individual Spanner database roles. Add a condition for each desired Spanner database role that includes the resource type of \`spanner.googleapis.com/DatabaseRole\` and the resource name ending with \`/YOUR_SPANNER_DATABASE_ROLE\`. Lowest-level resources where you can grant this role: - Instance - Database
- Permissions: none listed on the source page (the role takes effect through the IAM conditions described above).

### Example: grant a role

Generated example (not in the official docs) granting the first role on this page at one of its lowest-level resources (Instance; the role page lists Instance, Database):

```bash
gcloud spanner instances add-iam-policy-binding INSTANCE_ID \
  --member="user:EMAIL_ADDRESS" \
  --role="roles/spanner.admin"
```

The `service.resource.*` group headings of the official page are omitted from the per-role lists and counts, because they are collapsible headings, not permissions.
- The permissions table lists role IDs only (role names and links are on the official page) and gives service agent roles as a count; service agent roles must not be granted to principals other than service agents.
