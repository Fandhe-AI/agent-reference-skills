# Cloud Deploy deploy hooks (predeploy and postdeploy)

Deploy hooks run arbitrary programs before (`predeploy`) or after (`postdeploy`) a deploy. They run as predeploy and postdeploy jobs on the rollout, by default in the Cloud Deploy execution environment. For deployments to GKE they can optionally run on the application cluster through Skaffold `customActions`. Hooks are assumed to be idempotent: the user who provides the program is responsible for its behavior, including idempotency.

## Signature / Usage

### Hooks defined as tasks in a pipeline stage (standard strategy)

Tasks run serially in the order specified; the job fails at the first failing task and the remaining tasks do not run. `TASKS` is a list of one or more Cloud Deploy tasks.

```text
serialPipeline:
  stages:
  - targetId: hooks-staging
    profiles: []
    strategy:
      standard:
        predeploy:
          tasks: [TASKS]
        postdeploy:
          tasks: [TASKS]
```

### Hooks run on the application cluster (GKE only)

Reference custom actions by name with `actions` in the stage:

```yaml
serialPipeline:
  stages:
  - targetId: hooks-staging
    profiles: []
    strategy:
      standard:
        predeploy:
          actions: ["my-predeploy-action"]
        postdeploy:
          actions: ["my-postdeploy-action"]
```

Define the action in `skaffold.yaml` with `executionMode.kubernetesCluster`:

```text
customActions:
- name: ACTION_NAME
  containers:
  - name: CONTAINER_NAME
    image: IMAGE
    command: [COMMANDS_TO_RUN]
    args: [LIST_OF_ARGS]
  executionMode:
    kubernetesCluster: {}
```

Example that invokes the hook container on the application cluster:

```yaml
customActions:
- name: predeploy-action
  containers:
  - name: predeploy-echo
    image: ubuntu
    command: ["/bin/sh"]
    args: ["-c", 'echo "this is a predeploy action"' ]
  executionMode:
    kubernetesCluster: {}
```

## Options / Props

### Environment variables available in the execution environment

| Variable | Value |
|----------|-------|
| `ANTHOS_MEMBERSHIP` | For targets of type `ANTHOS`, the fully specified resource name of the Anthos membership. |
| `CLOUD_RUN_LOCATION` | For targets of type `RUN`, the region the Cloud Run service is deployed in. |
| `CLOUD_RUN_PROJECT` | For targets of type `RUN`, the project in which the Cloud Run service was created. |
| `CLOUD_RUN_SERVICE` | For targets of type `RUN`, the name of the Cloud Run service deployed. |
| `CLOUD_RUN_SERVICE_URLS` | For targets of type `RUN`, the URL or URLs (comma-separated) end users use to reach the service. Generated by Cloud Run after deploy, so only available in postdeploy hooks and verify jobs. |
| `CLOUD_RUN_REVISION` | For targets of type `RUN`, the specific revision of the Cloud Run service. |
| `GKE_CLUSTER` | For targets of type `GKE`, the fully specified cluster resource name, for example `projects/p/locations/us-central1/clusters/dev`. |
| `TARGET_TYPE` | The runtime type of the target: `GKE`, `ANTHOS`, or `RUN`. Not set for custom targets. |
| `CLOUD_DEPLOY_LOCATION` | The region containing the Cloud Deploy resources. |
| `CLOUD_DEPLOY_DELIVERY_PIPELINE` | The ID of the delivery pipeline. |
| `CLOUD_DEPLOY_TARGET` | The ID of the target. |
| `CLOUD_DEPLOY_PROJECT` | The project number of the project containing the Cloud Deploy resources. |
| `CLOUD_DEPLOY_PROJECT_ID` | The project ID of that project. |
| `CLOUD_DEPLOY_RELEASE` | The ID of the release in which the hooks run. |
| `CLOUD_DEPLOY_ROLLOUT` | The ID of the rollout that contains the jobs for the hooks. |
| `CLOUD_DEPLOY_JOB_RUN` | The ID of the job run for the current execution of the job. |
| `CLOUD_DEPLOY_PHASE` | The phase in the rollout that contains the job for the hook, verify job, or custom render or deploy. |

## Notes

- The environment variables are also usable in verify jobs and custom target render / deploy. Deploy parameters you have set can also be passed to custom containers as environment variables.
- `predeploy` always runs as the first job in the phase. `postdeploy` runs after the deploy job; if a `verify` job is configured for the stage, verification runs before `postdeploy`.
- Canary: configure hooks under `strategy.canary.canaryDeployment` or `strategy.canary.customCanaryDeployment.phaseConfigs`, not under `strategy.standard`. For an automated canary, `predeploy` runs before the deploy in the first phase only and `postdeploy` after the deploy in the last (stable) phase only.
- Hooks configured with `tasks` run only in the Cloud Deploy execution environment; to run on the cluster you must use `actions`. Running on the cluster is available for GKE only; Cloud Run deployments can only run hooks in the Cloud Deploy execution environment.
- Under `kubernetesCluster` you can also set `jobManifestPath` and `overrides` (Kubernetes inline JSON with the values to replace); `executionMode` is optional and if omitted Skaffold runs the container in the Cloud Deploy execution environment.
- The first two stanzas use `text` where they contain placeholders (`[TASKS]`, `IMAGE`, ...).
- Task `command` / `args` / `env` values are stored in plain text in the delivery pipeline configuration; do not put tokens or passwords in them.
