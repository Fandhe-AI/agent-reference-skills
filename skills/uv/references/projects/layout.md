# Structure and files

A uv project is identified by a `pyproject.toml`; uv manages a `.venv` project environment and a `uv.lock` lockfile next to it.

## Signature / Usage

```toml
[project]
name = "example"
version = "0.1.0"
```

## The `pyproject.toml`

- Python project metadata is defined in a `pyproject.toml` file. uv requires this file to identify the root directory of a project.
- `uv init` can be used to create a new project.
- Additional project metadata and configuration: Python version requirement, dependencies, build system, entry points (commands) (see config.md and dependencies.md).

## The project environment

- uv creates a virtual environment as needed. Some commands create a temporary environment (e.g., `uv run --isolated`); uv also manages a persistent environment with the project and its dependencies in a `.venv` directory next to the `pyproject.toml`.
- By default it is stored inside the project so editors can find it (they need the environment for code completions and type hints). Including `.venv` in version control is not recommended; it is automatically excluded from `git` with an internal `.gitignore` file.
- To run a command in the project environment, use `uv run`. Alternatively the environment can be activated as normal for a virtual environment.
- `uv run` creates the environment if it does not exist yet, or ensures it is up-to-date. It can also be explicitly created with `uv sync`.
- Modifying the project environment manually (e.g., with `uv pip install`) is not recommended. For project dependencies use `uv add`; for one-off requirements use `uvx` or `uv run --with`.
- To stop uv managing the project environment (automatic locking and syncing), set `managed = false`:

```toml
[tool.uv]
managed = false
```

### Centralized project environments

With the `centralized-project-envs` preview feature, uv stores the default project environment in its cache. uv attempts to maintain a `.venv` directory link to the cached environment so existing activation and editor workflows can continue to use the usual path. If link creation fails, uv attempts to write the cached environment path to `.venv` instead. If both attempts fail, uv continues using the cached environment directly, but tools relying on `.venv` may not discover it. Switching interpreters selects separate cached environments and can reuse them later.

Explicit project environment paths, including `UV_PROJECT_ENVIRONMENT` and environments selected with `--active`, are not centralized. The feature has no effect when `--no-cache` is enabled. The feature also applies to pathless `uv venv` invocations from a project or workspace root.

## The lockfile

- uv creates a `uv.lock` file next to the `pyproject.toml`.
- `uv.lock` is a _universal_ or _cross-platform_ lockfile that captures the packages that would be installed across all possible Python markers such as operating system, architecture, and Python version.
- Unlike the `pyproject.toml` (broad requirements), the lockfile contains the exact resolved versions installed in the project environment. It should be checked into version control for consistent and reproducible installations across machines.
- The lockfile is automatically created and updated during `uv sync` and `uv run`. It may also be explicitly updated using `uv lock`.
- `uv.lock` is a human-readable TOML file but is managed by uv and should not be edited manually. The format is specific to uv and not usable by other tools.

### Relationship to `pylock.toml`

PEP 751 standardized `pylock.toml`, a resolution output format intended to replace `requirements.txt` (e.g., a "locked" `requirements.txt` generated by `uv pip compile`). It is tool-agnostic. Some of uv's functionality cannot be expressed in the `pylock.toml` format; uv continues to use `uv.lock` within the project interface. uv supports `pylock.toml` as an export target and in the `uv pip` CLI:

```console
$ uv export -o pylock.toml
$ uv pip compile requirements.in -o pylock.toml
$ uv pip sync pylock.toml
$ uv pip install -r pylock.toml
```

## Notes

- Distinct from Cargo workspaces / `Cargo.lock` (see the rust skill) and JS monorepo tooling (see the turborepo and syncpack skills): `uv.lock` and `.venv` are Python-only uv artifacts.
