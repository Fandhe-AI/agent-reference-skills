# Settings: pip (m-z)

Settings specific to the `uv pip` command-line interface, in the `[tool.uv.pip]` table (`[pip]` in `uv.toml`). These values are ignored outside the `uv pip` namespace. This page covers `no-annotate` through `verify-hashes`.

## Signature / Usage

```toml
# pyproject.toml
[tool.uv.pip]
output-file = "requirements.txt"
python-version = "3.8"
universal = true
```

```toml
# uv.toml
[pip]
output-file = "requirements.txt"
python-version = "3.8"
universal = true
```

## Options / Props

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `no-annotate` | `bool` | `false` | Exclude comment annotations indicating the source of each package from the `uv pip compile` output. |
| `no-binary` | `list[str]` | `[]` | Do not install pre-built wheels for the given packages. Disable binaries for all packages with `:all:`; clear previous with `:none:`. |
| `no-build` | `bool` | `false` | Do not build source distributions. Alias for `--only-binary :all:`. uv may still build editable requirements. |
| `no-build-isolation` | `bool` | `false` | Disable isolation when building source distributions; assumes PEP 518 build dependencies are installed. |
| `no-build-isolation-package` | `list[str]` | `[]` | Disable build isolation for specific packages. |
| `no-deps` | `bool` | `false` | Ignore package dependencies; only add packages explicitly listed on the command line to the resulting requirements file. |
| `no-emit-package` | `list[str]` | `[]` | Package to omit from the output resolution (its dependencies are still included). Equivalent to pip-compile's `--unsafe-package`. |
| `no-extra` | `list[str]` | `[]` | Exclude the specified optional dependencies if `all-extras` is supplied. |
| `no-header` | `bool` | `false` | Exclude the comment header at the top of the `uv pip compile` output. |
| `no-index` | `bool` | `false` | Ignore all registry indexes (e.g., PyPI), relying on direct URL dependencies and `--find-links`. |
| `no-sources` | `bool` | `false` | Ignore the `tool.uv.sources` table when resolving dependencies. |
| `no-sources-package` | `list[str]` | `[]` | Ignore `tool.uv.sources` for the specified packages. |
| `no-strip-extras` | `bool` | `false` | Include extras in the output file. By default uv strips extras; output generated with `--no-strip-extras` cannot be used as constraints files in `install` and `sync`. |
| `no-strip-markers` | `bool` | `false` | Include environment markers in the output file. By default uv strips markers since the `compile` resolution is only guaranteed correct for the target environment. |
| `only-binary` | `list[str]` | `[]` | Only use pre-built wheels; do not build source distributions for the given packages. `:all:` / `:none:` supported. |
| `output-file` | `str` | `None` | Write the requirements generated by `uv pip compile` to the given `requirements.txt` file. If it exists, existing versions are preferred unless `--upgrade` is specified. |
| `prefix` | `str` | `None` | Install packages into `lib`, `bin`, and other top-level folders under the directory, as if a virtual environment were present. Prefer `--python`: scripts installed via `--prefix` reference the installing interpreter, rendering them non-portable. |
| `prerelease` | `"disallow" \| "allow" \| "if-necessary" \| "explicit" \| "if-necessary-or-explicit"` | `"if-necessary"` | Strategy when considering pre-release versions (`if-necessary-or-explicit` is a deprecated alias for `if-necessary`). |
| `python` | `str` | `None` | The Python interpreter into which packages should be installed. Formats: `3.10` (registry on Windows, `python3.10` on Linux and macOS), `python3.10` / `python.exe` (name in `PATH`), or an exact path. Intended for CI or automated workflows. |
| `python-platform` | `str` | `None` | Platform for which requirements should be resolved, as a target triple (e.g., `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`). |
| `python-version` | `str` | `None` | Minimum Python version supported by the resolved requirements (e.g., `3.8` or `3.8.17`). An omitted patch version maps to the minimum (`3.8` to `3.8.0`). |
| `reinstall` | `bool` | `false` | Reinstall all packages. Implies `refresh`. |
| `reinstall-package` | `list[str]` | `[]` | Reinstall a specific package. Implies `refresh-package`. |
| `require-build-hashes` | `bool` | `false` | Require hashes for all build dependencies in `uv pip` commands. Overrides `require-build-hashes` in `[tool.uv]`. Does not require hashes for runtime dependencies; use `require-hashes`. |
| `require-hashes` | `bool` | `false` | Require a matching hash for each requirement. All-or-nothing: all requirements must have hashes and be pinned to exact versions or direct URLs. Git dependencies, editable installations, and local directories are not supported (local wheel `.whl` or `.zip` / `.tar.gz` archive only). |
| `resolution` | `"highest" \| "lowest" \| "lowest-direct"` | `"highest"` | Strategy for selecting between compatible versions. |
| `strict` | `bool` | `false` | Validate the Python environment to detect packages with missing dependencies and other issues. |
| `system` | `bool` | `false` | Install packages into the system Python environment (the first Python found in `PATH`) instead of a virtual environment. WARNING: intended for CI; can modify the system Python installation. |
| `target` | `str` | `None` | Install packages into the specified directory, at its top level, rather than into the virtual or system Python environment. |
| `torch-backend` | `str` | `null` | Backend for fetching PyTorch-ecosystem packages (`cpu`, `cu126`, `auto`, ...). Only respected by `uv pip` commands. **In preview.** |
| `universal` | `bool` | `false` | Perform a universal resolution, generating a single `requirements.txt` compatible with all operating systems, architectures, and Python implementations. The current (or `--python-version`) Python version is a lower bound. |
| `upgrade` | `bool` | `false` | Allow package upgrades, ignoring pinned versions in any existing output file. |
| `upgrade-package` | `list[str]` | `[]` | Allow upgrades for a specific package (names or specifiers like `ruff<0.5.0`). |
| `verify-hashes` | `bool` | `true` | Validate any hashes provided in the requirements file. Unlike `--require-hashes`, does not require that all requirements have hashes. |

Examples from the reference:

```toml
[tool.uv.pip]
all-extras = true
no-extra = ["dev", "docs"]
no-binary = ["ruff"]
only-binary = ["ruff"]
no-emit-package = ["ruff"]
prefix = "./prefix"
python = "3.10"
python-platform = "x86_64-unknown-linux-gnu"
target = "./target"
torch-backend = "auto"
verify-hashes = true
```

## Notes

- Changed in 0.13.0: uv honors `--require-hashes` in constraints files included with `-c` from a requirements file (installs missing a hash can now fail), and rejects editable (`-e`) requirements in such constraints files; see the getting-started breaking-changes page.
- `system` and `break-system-packages` (previous page) are for CI-style use and can modify the system Python installation.
- `torch-backend` selects a PyTorch wheel index only; it does not configure GPU programming (see nvidia-cuda, amd-rocm).
