# Workers Binding API

Execute SQL on a D1 database from a Worker via the D1 binding: bind the database, prepare a statement, run it, and inspect the return object.

## Signature / Usage

```ts
// Row definition
type OrderRow = {
	Id: string;
	CustomerName: string;
	OrderDate: number;
};

// Elsewhere in your application
// env.MY_DB is the D1 database binding from your Wrangler configuration file
const result = await env.MY_DB.prepare(
	"SELECT Id, CustomerName, OrderDate FROM [Order] ORDER BY ShippedDate DESC LIMIT 100",
).run<OrderRow>();
```

## Options / Props

Type conversion on write (permanent and one-way):

| JavaScript (write) | D1 | JavaScript (read) |
| --- | --- | --- |
| null | `NULL` | null |
| Number | `REAL` | Number |
| Number <sup>2</sup> | `INTEGER` | Number |
| String | `TEXT` | String |
| Boolean <sup>3</sup> | `INTEGER` | Number (`0`,`1`) |
| ArrayBuffer | `BLOB` | Array <sup>4</sup> |
| ArrayBuffer View | `BLOB` | Array <sup>4</sup> |
| undefined | Not supported. <sup>5</sup> | - |

- <sup>2</sup> D1 supports 64-bit signed `INTEGER` values internally, however BigInts are not currently supported in the API yet. JavaScript integers are safe up to `Number.MAX_SAFE_INTEGER`.
- <sup>3</sup> Booleans will be cast to an `INTEGER` type where `1` is `TRUE` and `0` is `FALSE`.
- <sup>4</sup> `ArrayBuffer` and `ArrayBuffer` views are converted using `Array.from`.
- <sup>5</sup> Queries with `undefined` values will return a `D1_TYPE_ERROR`.

## Notes

- Steps: bind the D1 database, prepare a statement (`D1Database::prepare`), run the prepared statement, analyze the return object if necessary.
- The API is fully typed via runtime types generated by `wrangler types`, and supports generics. `D1PreparedStatement::run`, `raw` and `first` accept a row type parameter; passing `OrderRow` to `run` returns a `D1Result<OrderRow>` whose `results` is typed `OrderRow[]` (read it as `(await ...run<OrderRow>()).results`) instead of the default `Record<string, unknown>` row type.
- Corrected from the official docs: the official page says `run<OrderRow>()` "will return a typed `Array<OrderRow>` object". `run()` resolves with a `D1Result` (see Return objects); the type parameter only changes the element type of its `results` array.
- Use STRICT tables in your SQL schema to avoid mismatches between stored values and schema-defined types.
- The official page includes an "API playground" `index.js` (routes `/RUN`, `/RAW`, `/FIRST`, `/BATCH`, `/EXEC`, `/WITHSESSION`) built on the Get started code (JavaScript, binding `DB`); refer to the source page for it.
- For using D1 through Drizzle ORM (drizzle-orm/d1), see the drizzle skill.
- `env` and bindings in general are covered by the cloudflare-workers skill.
