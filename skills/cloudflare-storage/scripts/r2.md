# R2

Copy-paste `wrangler r2 ...` commands for buckets, CORS, lifecycle rules, bucket locks, event notifications, and objects. For the full flag tables see [wrangler-commands.md](../references/r2/wrangler-commands.md). S3-compatible clients (aws CLI, rclone) are in [r2-s3-clients.md](./r2-s3-clients.md). Installing Wrangler, logging in, `dev`, and `deploy` belong to the cloudflare-wrangler skill.

## Create and list buckets

```sh
npx wrangler r2 bucket create my-bucket
npx wrangler r2 bucket list
```

Optional flags on `create`: `--location`, `--storage-class` (`--s`), `--jurisdiction` (`--J`). Show details with:

```sh
npx wrangler r2 bucket info <BUCKET>
```

## Upload an object

```sh
wrangler r2 object put my-bucket/myfile.txt --file ./myfile.txt
```

The object path is `{bucket}/{key}`. Optional metadata flags: `--content-type`, `--content-disposition`, `--content-encoding`, `--content-language`, `--cache-control`, `--expires`, `--storage-class`. `--pipe` reads from stdin instead of `--file`.

## Download an object

```sh
wrangler r2 object get my-bucket/myfile.txt --file ./downloaded.txt
```

`--pipe` writes to stdout instead of `--file`.

## Local versus remote

`r2 object get|put|delete` accept `--local` (local storage), `--remote` (remote storage), and `--persist-to` (local persistence directory).

```sh
wrangler r2 object put my-bucket/myfile.txt --file ./myfile.txt --local
wrangler r2 object put my-bucket/myfile.txt --file ./myfile.txt --remote
```

The Wrangler `r2` commands page does not state which target is the default (unlike `kv` and `d1`, whose defaults are local). Pass `--local` or `--remote` explicitly when the target matters.

> **Warning**: `--remote` writes to the real bucket and overwrites an existing object with the same key.

## Delete an object

> **Warning**: Object deletion is permanent. Confirm the `{bucket}/{key}` path before running it, especially with `--remote`.

```sh
wrangler r2 object delete test-bucket/image.png
```

## Configure CORS from a JSON file

Create `cors.json`:

```json
{
  "rules": [
    {
      "allowed": {
        "origins": ["https://example.com"],
        "methods": ["GET"]
      }
    }
  ]
}
```

```sh
npx wrangler r2 bucket cors set <BUCKET_NAME> --file cors.json
npx wrangler r2 bucket cors list <BUCKET_NAME>
```

`--force` (`--y`) skips the confirmation prompt on `cors set`. The dashboard and the S3 API use a different JSON shape (`AllowedOrigins`, `AllowedMethods`, ...) from the Wrangler `rules` / `allowed` shape shown above.

## Delete the CORS configuration

> **Warning**: Clears all CORS rules on the bucket; browser access that depends on them stops working.

```sh
npx wrangler r2 bucket cors delete <BUCKET>
```

## Manage lifecycle rules

```sh
npx wrangler r2 bucket lifecycle add <BUCKET_NAME> [OPTIONS]
npx wrangler r2 bucket lifecycle list <BUCKET_NAME>
npx wrangler r2 bucket lifecycle remove <BUCKET_NAME> --id <RULE_ID>
```

`add` options: `--expire-days`, `--expire-date`, `--ia-transition-days`, `--ia-transition-date`, `--abort-multipart-days`; positional `[NAME]` (alias `--id`) and `[PREFIX]`.

## Set lifecycle configuration from a JSON file

> **Warning**: A lifecycle rule that expires objects deletes production data (objects are typically removed within 24 hours of expiry). `--force` (`--y`) skips the confirmation and Basin Catalog validation prompt.

```sh
npx wrangler r2 bucket lifecycle set <BUCKET_NAME> --file <FILE_PATH>
```

The JSON file follows the request body of the put object lifecycle configuration API.

## Manage bucket lock rules

```sh
npx wrangler r2 bucket lock add <BUCKET_NAME> [OPTIONS]
npx wrangler r2 bucket lock list <BUCKET_NAME>
npx wrangler r2 bucket lock remove <BUCKET_NAME> --id <RULE_ID>
npx wrangler r2 bucket lock set <BUCKET_NAME> --file <FILE_PATH>
```

`lock add` options: `--retention-days`, `--retention-date`, `--retention-indefinite`. A bucket with lock rules cannot be emptied until the rules are removed. `lock set` takes the request body of the put bucket lock configuration API.

## Create event notification rules

```sh
npx wrangler r2 bucket notification create <BUCKET_NAME> --event-type <EVENT_TYPE> --queue <QUEUE_NAME>
```

Filter by prefix and/or suffix:

```sh
npx wrangler r2 bucket notification create <BUCKET_NAME> --event-type <EVENT_TYPE> --queue <QUEUE_NAME> --prefix "<PREFIX_VALUE>"
npx wrangler r2 bucket notification create <BUCKET_NAME> --event-type <EVENT_TYPE> --queue <QUEUE_NAME> --suffix "<SUFFIX_VALUE>"
npx wrangler r2 bucket notification create <BUCKET_NAME> --event-type <EVENT_TYPE> --queue <QUEUE_NAME> --prefix "<PREFIX_VALUE>" --suffix "<SUFFIX_VALUE>"
```

`<EVENT_TYPE>` is `object-create` or `object-delete`. List and delete rules:

```sh
npx wrangler r2 bucket notification list <BUCKET>
npx wrangler r2 bucket notification delete <BUCKET> --queue <QUEUE_NAME> --rule <RULE_ID>
```

If `--rule` is omitted, all notification rules associated with the bucket and queue are deleted.

## Public access and custom domains

```sh
npx wrangler r2 bucket dev-url get <BUCKET>
npx wrangler r2 bucket dev-url enable <BUCKET>
npx wrangler r2 bucket dev-url disable <BUCKET>
```

> **Warning**: `dev-url enable` turns on public access to the bucket through its r2.dev URL.

```sh
npx wrangler r2 bucket domain add <BUCKET> --domain <DOMAIN> --zone-id <ZONE_ID>
npx wrangler r2 bucket domain list <BUCKET>
npx wrangler r2 bucket domain get <BUCKET> --domain <DOMAIN>
npx wrangler r2 bucket domain update <BUCKET> --domain <DOMAIN> --min-tls <VERSION>
npx wrangler r2 bucket domain remove <BUCKET> --domain <DOMAIN>
```

## Enable local uploads

```sh
npx wrangler r2 bucket local-uploads enable <BUCKET_NAME>
npx wrangler r2 bucket local-uploads disable <BUCKET_NAME>
```

These two commands appear in the official local-uploads guide but not on the Wrangler `r2` commands page; see [buckets-local-uploads.md](../references/r2/buckets-local-uploads.md).

## Enable Sippy incremental migration

```sh
npx wrangler r2 bucket sippy enable <NAME>
npx wrangler r2 bucket sippy get <NAME>
npx wrangler r2 bucket sippy disable <NAME>
```

`sippy enable` takes provider flags (`--provider` `AWS` or `GCS`, `--bucket`, `--region`, and credentials). Avoid passing secrets inline where they are recorded in shell history; see [data-migration-sippy.md](../references/r2/data-migration-sippy.md).

## Empty and delete a bucket

> **Warning**: Emptying a bucket permanently deletes every object and is irreversible. Deleting a bucket also removes its lifecycle rules, CORS settings, event notifications, and custom domains. Bucket lock rules must be removed first.

The Wrangler path to empty a bucket is a lifecycle rule that expires all objects after 1 day. Remove the rule as soon as the bucket is empty, otherwise newly uploaded objects are also expired.

```sh
npx wrangler r2 bucket lifecycle add <BUCKET_NAME> --expire-days 1
```

```sh
npx wrangler r2 bucket lifecycle remove <BUCKET_NAME> --id <RULE_ID>
```

Delete the (empty) bucket. The command fails if the bucket still contains objects.

```sh
npx wrangler r2 bucket delete <BUCKET_NAME>
```
