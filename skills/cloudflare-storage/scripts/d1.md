# D1

Copy-paste `wrangler d1 ...` commands for creating, querying, importing, exporting, and deleting D1 databases. For the full flag tables see [wrangler-commands.md](../references/d1/wrangler-commands.md). Migrations are in [d1-migrations.md](./d1-migrations.md) and Time Travel in [d1-time-travel.md](./d1-time-travel.md). Installing Wrangler, logging in, `dev`, and `deploy` belong to the cloudflare-wrangler skill.

## Create a database

```sh
npx wrangler@latest d1 create prod-d1-tutorial
```

`d1 create` acts on remote D1. When prompted, Wrangler can add the binding to your configuration file.

## Create a database with a location hint

```sh
wrangler d1 create new-database --location=weur
```

`--location` is a hint for the primary location of the new database. Options: `weur` (Western Europe), `eeur` (Eastern Europe), `apac` (Asia Pacific), `oc` (Oceania), `wnam` (Western North America), `enam` (Eastern North America).

## Create a database with a jurisdiction

```sh
npx wrangler@latest d1 create db-with-jurisdiction --jurisdiction=eu
```

`--jurisdiction` restricts where the database runs and stores data. Options: `eu` (European Union), `fedramp` (FedRAMP-compliant data centers), `us` (United States). If a jurisdiction is set, the location hint is ignored.

## List databases and show info

```sh
npx wrangler d1 list
npx wrangler d1 info <NAME>
```

Add `--json` for JSON output. In the `d1 info` output, `version: production` means the database supports Time Travel; `version: alpha` supports only the legacy snapshot backups.

## Local versus remote

`d1 execute` takes `--local` (local DB used by `wrangler dev`) or `--remote` (remote DB used by remote bindings or a deployed Worker). The official guide initializes the local DB first with `--local`, then repeats the steps with `--remote`.

```sh
npx wrangler d1 execute prod-d1-tutorial --local --file=./schema.sql
npx wrangler d1 execute prod-d1-tutorial --local --command="SELECT * FROM Customers"
```

```sh
npx wrangler d1 execute prod-d1-tutorial --remote --file=./schema.sql
npx wrangler d1 execute prod-d1-tutorial --remote --command="SELECT * FROM Customers"
```

> **Warning**: `--remote` runs against the deployed production database. The tutorial `schema.sql` begins with `DROP TABLE IF EXISTS Customers;`, which destroys existing production data. Review any SQL file and the target database before running it with `--remote`.

Either `--command` or `--file` is required. `--persist-to` sets the local persistence directory and is used with `--local`.

## Create a schema in a local database

```sh
wrangler d1 execute YOUR_DATABASE_NAME \
  --local --command "CREATE TABLE IF NOT EXISTS users ( user_id INTEGER PRIMARY KEY, email_address TEXT, created_at INTEGER, deleted INTEGER, settings TEXT);"
```

Without `--local` the command runs against the remote database. For Pages projects a minimal Wrangler configuration with `preview_database_id` is required (see [local-development.md](../references/d1/local-development.md)).

## Import a SQL file

```sh
npx wrangler d1 execute example-db --remote --file=users_export.sql
```

Verify the import:

```sh
npx wrangler d1 execute example-db --remote --command "SELECT name FROM sqlite_schema WHERE type='table' ORDER BY name;"
```

> **Warning**: `--remote` writes to the production database. Check the file for statements that conflict with existing tables (for example `CREATE TABLE` without `IF NOT EXISTS`) or that drop data.

`wrangler d1 execute --file` is limited to files of 5GiB; split larger imports into multiple files. Raw SQLite files (`.sqlite3`) cannot be imported directly.

## Convert a SQLite dump for D1

```sh
sqlite3 db_dump.sqlite3 .dump > db.sql
```

Then edit `db.sql`: remove `BEGIN TRANSACTION` and `COMMIT;`, and remove the `CREATE TABLE _cf_KV` statement if present. Feed the result to `d1 execute --file`. If an import violates foreign keys, call `PRAGMA defer_foreign_keys = true` before the offending changes.

## Export a database

```sh
npx wrangler d1 export <database_name> --remote --output=./database.sql
```

Single table (schema and data):

```sh
npx wrangler d1 export <database_name> --remote --table=<table_name> --output=./table.sql
```

Schema only (`--no-data`):

```sh
npx wrangler d1 export <database_name> --remote --output=./schema.sql --no-data
npx wrangler d1 export <database_name> --remote --table=<table_name> --output=./schema.sql --no-data
```

Data only (`--no-schema`):

```sh
npx wrangler d1 export <database_name> --remote --output=./data.sql --no-schema
npx wrangler d1 export <database_name> --remote --table=<table_name> --output=./data.sql --no-schema
```

Export is not supported for databases with virtual tables (such as FTS5), and a running export blocks other database requests.

## Query insights (experimental)

```sh
npx wrangler d1 insights <NAME>
```

Options: `--time-period` (default `1d`), `--sort-type`, `--sort-by`, `--sort-direction`, `--limit` (default 5), `--json`.

## Delete a database

> **Warning**: Deletes the database and all of its data; applications bound to it stop working. `--skip-confirmation` (`--y`) skips the prompt. Take a `d1 export` backup of production databases first.

```sh
npx wrangler d1 delete prod-d1-tutorial
```
