# ASAR Archives

After creating an application distribution, the app's source code is usually bundled into an ASAR archive, a simple extensive archive format designed for Electron apps. Bundling mitigates long path names on Windows, speeds up `require` and conceals your source code from cursory inspection.

## Signature / Usage

With special patches in Electron, Node APIs like `fs.readFile` and `require` treat ASAR archives as virtual directories.

```js
const fs = require('node:fs')

fs.readFileSync('/path/to/example.asar/file.txt')
fs.readdirSync('/path/to/example.asar')
```

Display a web page in an archive with `BrowserWindow`:

```js
const { BrowserWindow } = require('electron')

const win = new BrowserWindow()

win.loadURL('file:///path/to/example.asar/static/index.html')
```

In a web page, files in an archive can be requested with the `file:` protocol, treated as directories like in the Node API.

## Treating an ASAR archive as a normal file

Use the built-in `original-fs` module, which provides the original `fs` APIs without `asar` support:

```js
const originalFs = require('original-fs')

originalFs.readFileSync('/path/to/example.asar')
```

Or set `process.noAsar` to `true` to disable `asar` support in the `fs` module:

```js
const fs = require('node:fs')

process.noAsar = true
fs.readFileSync('/path/to/example.asar')
```

## Adding unpacked files

Some Node APIs unpack the file to the filesystem when called; apart from performance issues, various anti-virus scanners might be triggered. Leave files unpacked using the `--unpack` option; for example, shared libraries of native Node.js modules:

```sh
$ asar pack app app.asar --unpack *.node
```

This creates a folder `app.asar.unpacked` together with `app.asar`. It contains the unpacked files and should be shipped together with the `app.asar` archive.

## Notes

Limitations of the Node API:

- Archives are read-only: all Node APIs that can modify files will not work with ASAR archives.
- The working directory cannot be set to directories in an archive; passing them as the `cwd` option of some APIs will cause errors.
- APIs requiring extra unpacking (the needed file is extracted to a temporary file, adding a little overhead): `child_process.execFile`, `child_process.execFileSync`, `fs.open`, `fs.openSync`, `process.dlopen` (used by `require` on native modules).
- The `Stats` object returned by `fs.stat` and friends on files in `asar` archives is generated by guessing; only trust it for file size and file type.
- Only `execFile` is supported to execute binaries inside an ASAR archive; `exec` and `spawn` accept `command` instead of `file` and run under a shell, so there is no reliable way to determine whether a command uses a file in the archive.
