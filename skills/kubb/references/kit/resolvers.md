# Kit: Resolvers

`createResolver` builds a plugin resolver for names, paths, and imports. It controls file naming and path resolution, with auto-injected defaults under `resolver.default` and `Resolver.merge` for layering overrides.

## Signature / Usage

```typescript
import { createResolver } from 'kubb/kit'
import type { PluginType, Resolver } from 'kubb/kit'

// Extend the base Resolver with plugin-specific naming namespaces.
type MyResolver = Resolver & {
  schema: {
    name(node: { name: string }): string
  }
}

type MyPlugin = PluginType<'plugin-example', object, object, MyResolver>

export const resolver = createResolver<MyPlugin>({
  pluginName: 'plugin-example',
  name(name) {
    return `${name.charAt(0).toUpperCase()}${name.slice(1)}`
  },
  schema: {
    name(node) {
      return this.name(node.name)
    },
  },
})
```

Provide `pluginName`. Methods use `this` to reach the merged resolver, so namespaced methods call `this.name(...)` for active casing.

## Auto-injected resolver defaults

| Method | Default behavior |
| --- | --- |
| `name` | Active top-level identifier casing. Delegates to `default.name` when omitted |
| `file` | Top-level `FileNode` builder, delegates to `default.file` |
| `default.name` | The core `camelCase` generated-identifier casing |
| `default.options` | Applies `exclude`, `include`, and `override` filters |
| `default.path` | Resolves to `output.path`, with optional tag/path-based subdirectories |
| `default.file` | Constructs a full `FileNode` using the resolver's `file.baseName` casing (camelCase by default, with `pet.petId` becoming `pet/petId`) |
| `default.banner` | Returns `output.banner` or the standard "Generated by Kubb" header |
| `default.footer` | Returns `output.footer` when set |

## `resolver.imports`

Builds one import entry per `$ref` in a schema tree. Each import uses the ref's `targetName` when set, otherwise the last segment of its pointer. Names and paths go through the resolver's own `name` and `file` conventions; `extname` defaults to `.ts`.

```typescript
const imports = resolver.imports({ node, root, output })
// → [{ kind: 'Import', name: ['pet'], path: '/src/types/pet.ts' }]

// Override how a referenced schema name becomes the imported identifier
const suffixed = resolver.imports({
  node,
  root,
  output,
  name: (schemaName) => `${resolver.name(schemaName)}Type`,
})
```

## `Resolver.merge`

`Resolver.merge(base, patch)` returns a new resolver with `patch`'s fields layered over `base`'s and every helper re-bound.

```typescript
const patched = Resolver.merge(resolver, {
  name(name) {
    return `Custom${this.default.name(name)}`
  },
})
```

## Resolver overrides

```typescript
type ResolverPatch = {
  name?: (name: string) => string
  file?: {
    baseName?: (params: { name: string; extname: string }) => string
    path?: (params: { baseName: string; output: Output }) => string
  }
  // plugin-specific namespaces, such as query.keyName or schema.typeName
}
```

## Notes

- 出典: https://kubb.dev/docs/5.x/reference/kit/resolvers （kubb@5.11.0 の docs/5.x/reference/kit/resolvers.md）
- A top-level `name` replaces on merge, while `file` and each namespace merge per member, so overriding `query.name` keeps the base `query.keyName`.
- Type a patch with `ResolverPatch<T>` to keep `this` and namespace shapes checked against the target resolver.
- Methods run with a `this` bound to the full, merged resolver; write them as regular functions, not arrow functions. `this.default.name(name)` always applies Kubb's core `camelCase` default.
- From a namespaced method, `this.name(name)` calls the active top-level `name` and follows any user override. Calling `this.name` from the top-level `name` itself recurses; call an exported preset resolver such as `resolverTs.name` to wrap its casing.
