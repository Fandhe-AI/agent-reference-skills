# Kit: Resolvers

`createResolver` builds a plugin resolver for names, paths, and imports. It controls file naming and path resolution, with auto-injected defaults under `resolver.default` and `Resolver.merge` for layering overrides.

## Signature / Usage

```typescript
import { createResolver } from 'kubb/kit'
import type { PluginType, Resolver } from 'kubb/kit'

// Extend the base Resolver with plugin-specific naming namespaces.
type MyResolver = Resolver & {
  schema: {
    name(node: { name: string }): string
  }
}

type MyPlugin = PluginType<'plugin-example', object, object, MyResolver>

export const resolver = createResolver<MyPlugin>({
  pluginName: 'plugin-example',
  name(name) {
    return `${name.charAt(0).toUpperCase()}${name.slice(1)}`
  },
  schema: {
    name(node) {
      return this.name(node.name)
    },
  },
})
```

`pluginName` is required. Methods use `this` to reach the merged resolver, so namespaced methods call `this.name(...)` for the active casing.

## Auto-injected resolver defaults

Every resolver has these members without declaring them.

| Method | Default behavior |
| --- | --- |
| `name` | Active top-level identifier casing. Delegates to `default.name` when omitted |
| `file` | Top-level `FileNode` builder, delegates to `default.file` |
| `default.name` | The core `camelCase` generated-identifier casing |
| `memo` | Caches a value under a string key for the rest of the build. Wrap repeated casing in it |
| `default.options` | Applies `exclude`, `include`, and `override` filters |
| `default.path` | Resolves to `output.path`. In `mode: 'directory'` it appends the base name, inside a tag or path subdirectory when `group` is set |
| `groupDir` | The folder a `group` puts a file in: the custom `group.name`, the camelCased tag in its `parent` tag folders, or the first path segment |
| `default.file` | Constructs a full `FileNode` using the resolver's `file.baseName` casing (camelCase by default, with `pet.petId` becoming `pet/petId`) |
| `default.banner` | Returns `output.banner` or the standard "Generated by Kubb" header |
| `default.footer` | Returns `output.footer` when set |

## `resolver.imports`

Builds one import entry per `$ref` in a schema tree. Each import uses the ref's `targetName` when set, otherwise the last segment of its pointer. Names and paths go through the resolver's own `name` and `file` conventions; `extname` defaults to `.ts`.

```typescript
const imports = resolver.imports({ node, root, output })
// → [{ kind: 'Import', name: ['pet'], path: '/src/types/pet.ts' }]

// Override how a referenced schema name becomes the imported identifier
const suffixed = resolver.imports({
  node,
  root,
  output,
  name: (schemaName) => `${resolver.name(schemaName)}Type`,
})
```

Refs inside `conditionals`, `contains` and a string's `content` are left out, because most plugins do not print those checks. A plugin that prints them passes `checks: true`. Checks that cannot fail are still left out: a `contains` with `min: 0` and no `max`, and `content` that is not JSON or is encoded.

### Name reservations

`resolver.resolveName({ key, name })` keeps the preferred name when available and adds `2`, `3`, and so on when it is taken. Use the same key for a declaration and its references.

Use an array to separate the declaration's owner and role. Core compares array values in order and keeps segment boundaries distinct. Segments can be strings or `undefined`. String keys also work and are distinct from array keys.

The driver reserves component names after applying each plugin's macros and filters. `resolver.name` only applies casing. Reserve extra identifiers, such as enum type aliases, with `resolver.reserveNames` before allocating names that can collide with them.

```typescript
resolver.reserveNames(['CreateContainerBody', 'CreateContainerBody2'])
const name = resolver.resolveName({
  key: ['operation', 'POST', '/containers', 'body'],
  name: 'CreateContainerBody',
})
// 'CreateContainerBody3'
```

Pass `normalize` when a node's raw name differs from its emitted identifier. The returned name stays in its raw form. The callback must keep numeric suffixes distinct so allocation can find an unused identifier.

```typescript
const name = resolver.resolveName({
  key: ['enum', owner, node.pointer],
  name: node.name,
  normalize: (candidate) => resolver.name(candidate),
})
```

Allocate names only for declarations the generator emits. `Resolver.merge` creates a resolver with no reservations.

## `Resolver.merge`

`Resolver.merge(base, patch)` returns a new resolver with `patch`'s fields layered over `base`'s and every helper re-bound.

```typescript
import { createResolver, Resolver } from 'kubb/kit'
import type { PluginType } from 'kubb/kit'

const resolver = createResolver<PluginType>({ pluginName: 'plugin-example' })

const patched = Resolver.merge(resolver, {
  name(name) {
    return `Custom${this.default.name(name)}`
  },
})
```

## Resolver overrides

Kubb resolves the path `file.path` returns against the root `output.path` directory, and the result must stay inside that directory. The `output` argument is the plugin's own `output`.

`resolver.imports` keeps each import path for the rest of the build, so `file.baseName` and `file.path` must return the same result for the same arguments.

```typescript
type ResolverPatch = {
  name?: (name: string) => string
  file?: {
    baseName?: (params: { name: string; extname: string }) => string
    path?: (params: { baseName: string; output: Output }) => string
  }
  // plugin-specific namespaces, such as query.keyName or schema.typeName
}
```

## Notes

- Source: https://kubb.dev/docs/5.x/reference/kit/resolvers (docs/5.x/reference/kit/resolvers.md at kubb@5.20.0, retrieved 2026-11-14)
- Migration (5.11 → 5.20): `Resolver.reserveNames` and `Resolver.resolveName` were added in v5.14.4 (#4474), `resolveName`'s `normalize` may return several names since v5.14.5 (#4475), `this.memo(key, compute)` was added to every resolver in v5.15.0 (#4501), and `resolver.groupDir` plus `casing` / `text` from `kubb/kit` in v5.18.6 (#4583); `camelCase` and `pascalCase` from `@kubb/kit` are deprecated in favor of `casing.camel` and `casing.pascal`.
- A top-level `name` replaces on merge, while `file` and each namespace merge per member, so overriding `query.name` keeps the base `query.keyName`.
- Type a patch with `ResolverPatch<T>` to keep `this` and namespace shapes checked against the target resolver.
- Methods run with a `this` bound to the full, merged resolver; write them as regular functions, not arrow functions. `this.default.name(name)` always applies Kubb's core `camelCase` default. `this.memo(key, compute)` returns the same value for a key for the rest of the build, so a resolver computes each name once. A key is `prefix:rest`; register the prefix and its value type in `Kubb.MemoRegistry`, next to `Kubb.PluginRegistry`, and the value is typed. For casing helpers, import `casing` from `kubb/kit` and call `casing.camel` or `casing.pascal`.
- From a namespaced method, `this.name(name)` calls the active top-level `name` and follows any user override. Calling `this.name` from the top-level `name` itself recurses; call an exported preset resolver such as `resolverTs.name` to wrap its casing.
