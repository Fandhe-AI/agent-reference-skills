# Cross Platform Implementation

The React Native renderer utilizes a core render implementation to be shared across platforms. In the previous render system, the React Shadow Tree, layout logic, and View Flattening algorithm were implemented once for each platform. The current renderer shares a core C++ implementation.

## Signature / Usage

The renderer provides two sides of its C++ APIs (original text):

```text
(i) to communicate with React
(ii) to communicate with the host platform

For (i), React communicates with the renderer to render a React Tree and to "listen" for events (e.g. onLayout, onKeyPress, touch, etc).

For (ii), the React Native renderer communicates with the host platform to mount host views on the screen (create, insert, update or delete of host views) and it listens for events that are generated by the user on the host platform.
```

## Notes

- The team intends to incorporate an animation system into the render system and extend it to new platforms such as Windows, and operating systems in game consoles, televisions, and more.
- Advantages of C++ for the core: a single implementation reduces development and maintenance cost; creating React Shadow Trees and layout calculation are faster because Yoga integration overhead is minimized on Android (no more JNI for Yoga); the memory footprint of each React Shadow Node is smaller in C++ than if allocated from Kotlin or Swift. C++ features that enforce immutability prevent concurrent-access issues.
- On Android the renderer still incurs JNI cost for two use cases: layout calculation of complex views (e.g. `Text`, `TextInput`) requires sending props over JNI, and the mount phase requires sending mutation operations over JNI.
- The team is exploring replacing `ReadableMap` with a new mechanism to serialize data using `ByteBuffer`; the stated goal is to reduce JNI overhead by 35-50%.
- The page is marked in the source with the caution: "This document refers to the New Architecture, that is in active roll-out."
