# Native Modules: Introduction

Write a Turbo Native Module to interact with native platform APIs that are not provided by React Native or an existing library. The guide builds a `localStorage` implementation (Web Storage API) on Android `SharedPreferences` and iOS `NSUserDefaults`.

## Signature / Usage

Steps: (1) define a typed JavaScript specification using Flow or TypeScript; (2) configure your dependency management system to run Codegen, which converts the specification into native language interfaces; (3) write your application code using your specification; (4) write your native platform code using the generated interfaces.

**shell**

```bash
npx @react-native-community/cli@latest init TurboModuleExample --version "<current React Native version>"
```

**TypeScript** (`specs/NativeLocalStorage.ts`)

```typescript
import type {TurboModule} from 'react-native';
import {TurboModuleRegistry} from 'react-native';

export interface Spec extends TurboModule {
  setItem(value: string, key: string): void;
  getItem(key: string): string | null;
  removeItem(key: string): void;
  clear(): void;
}

export default TurboModuleRegistry.getEnforcing<Spec>(
  'NativeLocalStorage',
);
```

**Flow** (`NativeLocalStorage.js`)

```flow
import type {TurboModule} from 'react-native';
import {TurboModuleRegistry} from 'react-native';

export interface Spec extends TurboModule {
  setItem(value: string, key: string): void;
  getItem(key: string): ?string;
  removeItem(key: string): void;
  clear(): void;
}

export default (TurboModuleRegistry.getEnforcing<Spec>(
  'NativeLocalStorage',
): Spec);
```

Application code (`App.tsx`):

```tsx
import {useEffect, useState, type JSX} from 'react';
import {
  SafeAreaView,
  StyleSheet,
  Text,
  TextInput,
  Button,
} from 'react-native';

import NativeLocalStorage from './specs/NativeLocalStorage';

const EMPTY = '<empty>';

function App(): JSX.Element {
  const [value, setValue] = useState<string | null>(null);

  const [editingValue, setEditingValue] = useState<string | null>(
    null,
  );

  useEffect(() => {
    const storedValue = NativeLocalStorage?.getItem('myKey');
    setValue(storedValue ?? '');
  }, []);

  function saveValue() {
    NativeLocalStorage?.setItem(editingValue ?? EMPTY, 'myKey');
    setValue(editingValue);
  }

  function clearAll() {
    NativeLocalStorage?.clear();
    setValue('');
  }

  function deleteValue() {
    NativeLocalStorage?.removeItem('myKey');
    setValue('');
  }

  return (
    <SafeAreaView style={{flex: 1}}>
      <Text style={styles.text}>
        Current stored value is: {value ?? 'No Value'}
      </Text>
      <TextInput
        placeholder="Enter the text you want to store"
        style={styles.textInput}
        onChangeText={setEditingValue}
      />
      <Button title="Save" onPress={saveValue} />
      <Button title="Delete" onPress={deleteValue} />
      <Button title="Clear" onPress={clearAll} />
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  text: {
    margin: 10,
    fontSize: 20,
  },
  textInput: {
    margin: 10,
    height: 40,
    borderColor: 'black',
    borderWidth: 1,
    paddingLeft: 5,
    paddingRight: 5,
    borderRadius: 5,
  },
});

export default App;
```

## Options / Props

`TurboModuleRegistry` retrieval modes:

| Name | Type | Description |
| --- | --- | --- |
| get | `get<T>(name: string): T \| null` | Returns `null` if the Turbo Native Module is unavailable. |
| getEnforcing | `getEnforcing<T>(name: string): T` | Throws an exception if the Turbo Native Module is unavailable. Assumes the module is always available. |

## Notes

- `SafeAreaView` from react-native used in this sample is deprecated in the 0.87 docs; use react-native-safe-area-context in real apps.
- Deviation: command output shown in the same block on the official page is split into a separate text block.
- Corrected: the official Flow spec imported TurboModule twice and omitted the default export.
- Docusaurus highlight markers from the official page are removed; snippets show the final code.
- The specification declares the methods and data types that pass back and forth between native code and the React Native JavaScript runtime. A Turbo Native Module is both the specification, the native code you write, and the Codegen interfaces generated from the specification.
- To create a specs file: inside the root folder of the app, create a folder called `specs` and a file called `NativeLocalStorage.ts`. If you rename the module and its specs file, always use `Native` as prefix (e.g. `NativeStorage` or `NativeUsersDefault`).
- All types usable in a specification and the native types generated from them are listed in the Appendix page.
- Step 4 (native platform code) is split by platform; the official page embeds the Android and iOS guides. See the Android and iOS pages linked below.
- This guide creates a Turbo Native Module that only works with the New Architecture. Supporting both the New Architecture and the Legacy Architecture requires the backwards compatibility guide in the React Native New Architecture working group repository.
- Cross-skill: for the native-side APIs themselves, see the apple-uikit / apple-swift and android-architecture skills; this page covers only the JS-to-native boundary.
