# Security

A catalogue of options for storing sensitive information, authentication, network security, and tools that help secure your app. It is not a preflight checklist.

## Signature / Usage

```text
**Do** use async storage when...              | **Don't** use async storage for...
Persisting non-sensitive data across app runs | Token storage
Persisting Redux state                        | Secrets
Persisting GraphQL state                      |
Storing global app-wide variables             |
```

Libraries named for secure storage and native OAuth: expo-secure-store, react-native-keychain, react-native-app-auth.

## Options / Props

| Topic | Option | Description |
|-------|--------|-------------|
| Storing sensitive info | Orchestration layer | Never store sensitive API keys in your app code. If you must have an API key or a secret, build an orchestration layer (e.g. AWS Lambda or Google Cloud Functions) that forwards the request with the required key. |
| Persisted data | Async Storage | Community-maintained asynchronous, unencrypted, key-value store; not shared between apps. |
| Secure storage | iOS Keychain Services | Securely store small chunks of sensitive info such as certificates, tokens, passwords. |
| Secure storage | Android Encrypted Shared Preferences | Wraps Shared Preferences and automatically encrypts keys and values. Data in Shared Preferences is not encrypted by default. |
| Secure storage | Android Keystore | Store cryptographic keys in a container to make it more difficult to extract from the device. |
| Authentication | OAuth2 with PKCE | `code_verifier` (a large random string generated by the client) and `code_challenge` (the SHA 256 of the code_verifier). |
| Network security | SSL encryption | APIs should always use SSL encryption (`https://`). |
| Network security | SSL pinning | Embed (pin) a list of trusted certificates in the client during development so only requests signed with a trusted certificate are accepted. |

## Notes

- Anything included in your code could be accessed in plain text by anyone inspecting the app bundle. Tools like react-native-dotenv and react-native-config add environment-specific variables but should not be confused with server-side environment variables, which can contain secrets.
- Persisted data is written to the device's disk and is more vulnerable to being accessed by attackers; unpersisted data is never written to disk.
- Async Storage is the React Native equivalent of Local Storage from the web.
- React Native does not come bundled with any way of storing sensitive data. To use iOS Keychain services or Android Secure Shared Preferences you can write a bridge yourself or use a library which wraps them at your own risk.
- Caution: be mindful of unintentionally storing or exposing sensitive info, e.g. saving sensitive form data in redux state and persisting the whole state tree in Async Storage, or sending user tokens and personal info to an application monitoring service such as Sentry or Crashlytics.
- Deep links (`app://`) are not secure and you should never send any sensitive information in them: there is no centralized method of registering URL schemes, so a malicious application can hijack your deep link by registering the same scheme. Android shows a Disambiguation dialog; on iOS the operating system makes the choice. Using universal links allows linking to content within your app securely in iOS.
- In OAuth2, the redirect step is not secure in apps for the same reason, so an additional check in the form of PKCE (Proof of Key Code Exchange) must be added. During the initial `/authorize` request the client sends the `code_challenge`; afterward it sends the `code_verifier`, and the IDP only sends the access token if they match. `react-native-app-auth` wraps AppAuth-iOS and AppAuth-Android and can support PKCE only if your Identity Provider supports it.
- Caution on SSL pinning: certificates expire every 1-2 years and when one does, it needs to be updated in the app as well as on the server; as soon as the server certificate is updated, apps with the old certificate embedded cease to work.
- Invest in security proportional to the sensitivity of the data stored in your application, the number of users, and the damage a hacker could do when gaining access to their account.
