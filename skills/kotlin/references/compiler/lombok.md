# Lombok compiler plugin

Allows the generation and use of Java's Lombok declarations by Kotlin code in the same mixed Java/Kotlin module. It cannot replace Lombok: configure Lombok as usual as well. Modules that merely call such declarations from another module don't need the plugin.

## Signature / Usage

```kotlin
plugins {
    kotlin("plugin.lombok") version "2.4.21"
    id("io.freefair.lombok") version "9.5.0"
}
```

Lombok configuration file (path relative to the module directory):

```kotlin
kotlinLombok {
    lombokConfigurationFile(file("lombok.config"))
}
```

Maven:

```xml
<plugin>
    <groupId>org.jetbrains.kotlin</groupId>
    <artifactId>kotlin-maven-plugin</artifactId>
    <version>${kotlin.version}</version>
    <configuration>
        <compilerPlugins>
            <plugin>lombok</plugin>
        </compilerPlugins>
        <pluginOptions>
            <option>lombok:config=${project.basedir}/lombok.config</option>
        </pluginOptions>
    </configuration>
    <dependencies>
        <dependency>
            <groupId>org.jetbrains.kotlin</groupId>
            <artifactId>kotlin-maven-lombok</artifactId>
            <version>${kotlin.version}</version>
        </dependency>
        <dependency>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
            <version>1.18.20</version>
        </dependency>
    </dependencies>
</plugin>

<!-- project-level dependencies (not inside kotlin-maven-plugin) -->
<dependencies>
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <version>1.18.20</version>
        <scope>provided</scope>
    </dependency>
</dependencies>
```

Command-line compiler:

```bash
-Xplugin="${KOTLIN_HOME}/lib/lombok-compiler-plugin.jar"
-P plugin:org.jetbrains.kotlin.lombok:config=<PATH_TO_CONFIG_FILE>
```

## Notes

- Supported annotations: `@Getter`, `@Setter`, `@Builder`, `@SuperBuilder`, `@NoArgsConstructor`, `@RequiredArgsConstructor`, `@AllArgsConstructor`, `@Data`, `@With`, `@Value`. `@Tolerate` is not planned.
- The Kotlin compiler ignores Lombok annotations used in Kotlin code.
- The official Maven example sets `<scope>provided</scope>` on the Lombok dependency inside `kotlin-maven-plugin` `<dependencies>`; Maven only accepts compile/runtime/system for plugin dependencies, so `provided` is declared in the project-level `<dependencies>` here instead.
- With kapt: kapt disables javac annotation processing by default. To run Lombok along with kapt, set `kapt { keepJavacAnnotationProcessors = true }` (Gradle) or launch Lombok through `maven-compiler-plugin` `annotationProcessorPaths` (Maven). It works correctly if annotation processors don't depend on code generated by Lombok.
