# Custom compiler plugins

How to build your own compiler plugin. The Kotlin compiler plugin API is unstable and introduces breaking changes in every release.

## Signature / Usage

Backend (IR) extension point: override `generate()` in `IrGenerationExtension` to add bodies to declarations generated by the frontend or change existing bodies.

Debug backend plugin code with compiler options:

```bash
-Xverify-ir
-Xphases-to-dump-before=ExternalPackageParentPatcherLowering
-Xdump-directory=<your-file-directory>
```

## Options / Props

Frontend (FIR) extension points:

| Extension name | Description |
| --- | --- |
| `FirAdditionalCheckersExtension` | Adds custom compiler checkers. |
| `FirDeclarationGenerationExtension` | Generates new declarations. |
| `FirExtensionSessionComponent` | Registers custom components in the `FirSession` to be used by other parts of the plugin. |
| `FirFunctionTypeKindExtension` | Defines new families of functional types. |
| `FirMetadataSerializerPlugin` | Reads and writes information to declaration metadata. |
| `FirStatusTransformerExtension` | Modifies declaration status attributes such as visibility or modality. |
| `FirSupertypeGenerationExtension` | Adds new supertypes to an existing class. |
| `FirTypeAttributeExtension` | Adds special attributes to certain types based on their type annotations. |

## Notes

- Check the list of available plugins, KSP, or an external linter such as Android lint first; custom plugins need significant ongoing maintenance.
- Compiler stages: parse into a syntax tree, analyze and resolve, generate IR, progressively lower the IR, translate to target output (JVM bytecode, JavaScript, native). Frontend plugins change resolution (visible in the IDE); backend plugins change declaration behavior in binaries. The Kotlin serialization plugin is the reference example (frontend adds a companion object and serializer function; backend implements behavior through `KSerializer` objects).
- Start from the Kotlin compiler plugin template (`Kotlin/compiler-plugin-template`). Currently custom compiler plugins can be developed only with Gradle.
- IDE integration: each IntelliJ IDEA / Android Studio version bundles an IDE-specific development version of the compiler that is not binary compatible with the released one, so the plugin must be updated and tested against each IDE version; community plugins aren't loaded by default.
- Backend changes are not checked by the compiler; ensure you don't introduce invalid types, incorrect function references, or references outside the correct scope. Verify with `-Xverify-ir` (performance impact; testing only), compare IR dumps, or debug `convertToIrAndActualize()` in `convertToIr.kt`.
- Tests: the template uses the Kotlin compiler test framework with `compiler-plugin/testData`, `testData/box` (code generation tests) and `testData/diagnostics` (diagnostic tests); FIR / IR text dumps are compared with golden files.
- Help: `#compiler` channel in Kotlin Slack.
