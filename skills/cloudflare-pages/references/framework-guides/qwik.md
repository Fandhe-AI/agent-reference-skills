# Qwik

Qwik City on Pages uses a generated `functions/[[path]].ts` catch-all; bindings are on `platform.env` inside `routeLoader$` and actions.

## Signature / Usage

```
npm create cloudflare@latest -- my-qwik-app --framework=qwik --platform=pages
```

Run locally from the project directory:

```sh
npm start
```

Access a KV namespace in a route loader:

Adapted (not in the official docs): the page's snippet has an unbalanced parenthesis (`(platform.env as {...}));`) and omits the import; both fixed (see Notes).

```typescript
import { routeLoader$ } from "@builder.io/qwik-city";

export const useGetServerTime = routeLoader$(({ platform }) => {
  // the type `KVNamespace` comes from runtime types generated by running `wrangler types`
  const { MY_KV } = platform.env as { MY_KV: KVNamespace };

  return {
    // ....
  };
});
```

## Notes

- For new projects Cloudflare recommends Workers; see cloudflare-workers framework-guides.
- Corrected from the official docs: removed the stray `)` after `platform.env as { MY_KV: KVNamespace }` and added the `routeLoader$` import from `@builder.io/qwik-city` so the snippet compiles; the import path is the standard Qwik City package, not stated on the Cloudflare page.
- As part of the `cloudflare-pages` adapter installation, `functions/[[path]].ts` is created; `[[path]]` handles requests to all incoming URLs. See [routing.md](../functions/routing.md).
- Server-side code in Qwik City goes in `routeLoader$` and actions.
- Qwik APIs themselves are out of scope for this skill.
