# Cloud Run functions deployment architecture overview

Deploying a Cloud Run function automatically coordinates Cloud Storage, Cloud Build, and Artifact Registry to package and run your code. Knowing these interactions helps with IAM permissions, resource dependencies, and troubleshooting build issues.

## Signature / Usage

### Flow

Source code is stored in a Cloud Storage bucket. Cloud Build builds it into a container image (Google Cloud's buildpacks and the Functions Framework) and pushes it to an Artifact Registry image registry. Cloud Run functions pulls the image to run the container. Newer functions are typically deployed using the Cloud Run Admin API; older ones using the Cloud Functions API.

### Resource names created, by API used

```text
Cloud Run Admin API
  source bucket (default encryption): run-sources-PROJECT_ID-REGION
  source bucket (CMEK):               you must provide a bucket name
  image repository:                   REGION-docker.pkg.dev/PROJECT_ID/cloud-run-source-deploy

Cloud Functions API (v2)
  source bucket (default encryption): gcf-v2-sources-PROJECT_NUMBER-REGION
  source bucket (CMEK):               gcf-sources-PROJECT_NUMBER-REGION-CMEK_KEY_HASH
  image repository:                   REGION-docker.pkg.dev/PROJECT_ID/gcf-artifacts
```

## Options / Props

| Step | Detail |
| --- | --- |
| Upload | Source goes to a Cloud Storage bucket that has no retention period |
| Build | Submitted to Cloud Build; the Cloud Build service account builds the image; default machine type `e2-standard-2` |
| Image | Uploaded to Artifact Registry (repositories above) |
| Deploy | The image is deployed to Cloud Run as a service |
| Invoke | Trigger with Eventarc, Pub/Sub, or other HTTP triggers |

## Notes

- The Cloud Run Admin API source bucket name is autogenerated only with default encryption; with CMEK you must provide a bucket name.
