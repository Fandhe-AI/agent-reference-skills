# DeviceInformationPairing / DeviceInformationCustomPairing

Pairs a `DeviceInformation` object with the local system. `DeviceInformationPairing` (via `DeviceInformation.Pairing`) drives basic, Windows-handled pairing; `DeviceInformationCustomPairing` (via `Pairing.Custom`) lets the app participate in the pairing ceremony itself (PIN entry, confirmation, etc.) — commonly needed for Bluetooth/BLE and USB devices that require user interaction to pair.

## Signature / Usage

```csharp
using Windows.Devices.Enumeration;

DeviceInformation deviceInfo = /* from FindAllAsync / DeviceWatcher */;

// Basic pairing: let Windows handle the ceremony end-to-end.
if (deviceInfo.Pairing.CanPair && !deviceInfo.Pairing.IsPaired)
{
    DevicePairingResult basicResult = await deviceInfo.Pairing.PairAsync();
}

// Custom pairing: the app participates in the ceremony.
DeviceInformationCustomPairing customPairing = deviceInfo.Pairing.Custom;
customPairing.PairingRequested += (sender, args) =>
{
    switch (args.PairingKind)
    {
        case DevicePairingKinds.ConfirmOnly:
            args.Accept();
            break;
        case DevicePairingKinds.DisplayPin:
            // Show args.Pin to the user; they enter it on the remote device.
            break;
        case DevicePairingKinds.ProvidePin:
            args.Accept("000000"); // PIN obtained from the user.
            break;
        case DevicePairingKinds.ConfirmPinMatch:
            // Show args.Pin; Accept() if the user confirms it matches the remote device's display.
            args.Accept();
            break;
        case DevicePairingKinds.ProvidePasswordCredential:
            args.AcceptWithPasswordCredential(new Windows.Security.Credentials.PasswordCredential("res", "user", "pass"));
            break;
    }
};

DevicePairingResult customResult = await customPairing.PairAsync(
    DevicePairingKinds.ConfirmOnly | DevicePairingKinds.DisplayPin | DevicePairingKinds.ProvidePin | DevicePairingKinds.ConfirmPinMatch);

// Unpairing (same call regardless of basic or custom pairing).
await deviceInfo.Pairing.UnpairAsync();
```

## Options / Props

| Name | Type | Description |
|------|------|-------------|
| `DeviceInformationPairing.IsPaired` | `bool` | Whether the device is currently paired. |
| `DeviceInformationPairing.CanPair` | `bool` | Whether the device supports pairing. |
| `DeviceInformationPairing.Custom` | `DeviceInformationCustomPairing` | Gets the object used to drive a custom pairing ceremony. |
| `DevicePairingRequestedEventArgs.PairingKind` | `DevicePairingKinds` | Which ceremony the system is requesting for this pairing attempt. |
| `DevicePairingRequestedEventArgs.Pin` | `string` | PIN to display to the user (`DisplayPin`/`ConfirmPinMatch`). |

### DevicePairingKinds values

| Value | Ceremony |
|------|-------------|
| `ConfirmOnly` | User confirms a Yes/No prompt; no PIN involved. |
| `DisplayPin` | App displays a PIN generated by the system for the user to enter on the remote device. |
| `ProvidePin` | App prompts the user for a PIN and passes it via `args.Accept(pin)`. |
| `ConfirmPinMatch` | App displays a PIN and the user confirms it matches what the remote device shows. |
| `ProvidePasswordCredential` | App collects a username/password and passes it via `args.AcceptWithPasswordCredential(...)` (Windows 10 1903+). |

### Key methods

| Name | Description |
|------|-------------|
| `DeviceInformationPairing.PairAsync()` | Attempts basic pairing, letting Windows own the ceremony/UI. |
| `DeviceInformationCustomPairing.PairAsync(DevicePairingKinds)` | Attempts custom pairing, restricted to the specified ceremony kinds. |
| `DeviceInformationPairing.UnpairAsync()` | Unpairs the device. |
| `DevicePairingRequestedEventArgs.Accept()` / `Accept(string pin)` | Accepts the pairing request, optionally supplying a PIN. |
| `DevicePairingRequestedEventArgs.AcceptWithPasswordCredential(PasswordCredential)` | Accepts a `ProvidePasswordCredential` request. |

### Events

| Name | Description |
|------|-------------|
| `DeviceInformationCustomPairing.PairingRequested` | Raised during `PairAsync` for each ceremony step the app must handle. |

## Notes

- Namespace: `Windows.Devices.Enumeration` (WinRT/UWP). Used across Bluetooth Classic/RFCOMM, Bluetooth LE, and USB device flows that require pairing.
- Automatic pairing (no `DeviceInformationPairing` interaction at all) is also possible: some device-specific APIs (e.g. certain camera/webcam APIs) perform pairing internally and the app never touches these types.
- Custom pairing is always a system-level operation; on Desktop, a system dialog is shown for `ConfirmOnly` automatically, so the app does not need its own UI for that case, but does need explicit handling for the other `DevicePairingKinds`.
- The `PairingRequested` handler must cover every `DevicePairingKinds` value passed to `PairAsync`, or the ceremony will stall for kinds it doesn't handle.
