# Haptic feedback (InputHapticsManager)

Drives active haptic feedback — waveforms generated by the device and controlled through software — on input devices (mice, touchpads, pens) that support it, through `Windows.Devices.Haptics.InputHapticsManager`. The manager always targets the input device that most recently delivered input to the thread it was created on; there is no separate device-enumeration step for the common case.

## Signature / Usage

```csharp
using Windows.Devices.Haptics;
using Windows.Foundation.Metadata;

// Guard against older OS versions where the type is absent, then confirm a
// haptic-capable device is present.
bool apiPresent = ApiInformation.IsTypePresent("Windows.Devices.Haptics.InputHapticsManager");
bool supported = apiPresent && InputHapticsManager.IsSupported();

if (supported)
{
    // Call GetForCurrentThread() from the UI thread (or whichever thread owns
    // input focus) — calling it from a background thread will not route
    // feedback to the correct device.
    var mgr = InputHapticsManager.GetForCurrentThread();

    // Second parameter is a fallback waveform used if the first is
    // unsupported; 0 lets the system pick a device-appropriate fallback.
    // Returns false (non-fatal) if neither waveform is supported.
    bool sent = mgr.TrySendHapticWaveform(KnownSimpleHapticsControllerWaveforms.Align, 0);

    // Stop any ongoing playback, e.g. when a drag interaction ends.
    mgr.TryStopFeedback();
}
```

## Options / Props

| Member | Type | Description |
| --- | --- | --- |
| `InputHapticsManager.IsSupported()` | static method → `bool` | Whether `InputHapticsManager` functionality is supported on the system at all. |
| `InputHapticsManager.IsHapticDevicePresent()` | static method → `bool` | Whether a haptics-capable device is present on the system, independent of which device last delivered input to the calling thread. |
| `InputHapticsManager.GetForCurrentThread()` | static method → `InputHapticsManager` | Returns the manager instance for the calling thread; must be called from the thread that owns input focus (typically the UI thread). |
| `InputHapticsManager.TryGetForThread(UInt32)` | static method → `InputHapticsManager` | Retrieves the manager for the specified thread ID, if one exists. |
| `TrySendHapticWaveform(waveform, fallbackWaveform)` | method → `bool` | Triggers `waveform` on the device that most recently delivered input to the thread, falling back to `fallbackWaveform` (`0` = system-chosen default) if unsupported. |
| `TrySendHapticWaveform(waveform, fallbackWaveform, intensity)` | method → `bool` | Same as above with an explicit `intensity` (`double`, `0.0`–`1.0`). |
| `TrySendHapticWaveformForDuration(waveform, fallbackWaveform, intensity, duration)` | method → `bool` | Triggers a waveform for a specific `TimeSpan` duration at the given intensity. |
| `TrySendHapticWaveformForPlayCount(waveform, fallbackWaveform, intensity, playCount, replayPauseInterval)` | method → `bool` | Triggers a waveform `playCount` times, each separated by `replayPauseInterval` (`TimeSpan`), at the given intensity. |
| `TryStopFeedback()` | method → `bool` | Stops any ongoing haptic playback previously started by this manager on the device that received it. |
| `SetOverrideHapticsController(HapticDeviceType, SimpleHapticsController)` | method | Forces the manager to use a specific `SimpleHapticsController`/`HapticDeviceType` instead of auto-detecting from recent input; returns a `HapticsControllerOverrideToken` used with `ClearOverrideHapticsController`. |
| `CurrentHapticsController` | `SimpleHapticsController` | The controller for the device that most recently delivered input (or the active override). |
| `CurrentHapticsControllerDeviceType` | `HapticDeviceType` | Device type of `CurrentHapticsController`. |
| `ThreadId` | `UInt32` | ID of the thread that owns this manager instance. |
| `KnownSimpleHapticsControllerWaveforms.Align` / `.Collide` / `.Step` / `.Grow` | `UInt16` constants | Interaction-feedback waveforms: snap-to-guide, boundary reached, discrete step, and motion/transition, respectively. Introduced in Windows 11, version 24H2 (build 10.0.26100.0). |
| `KnownSimpleHapticsControllerWaveforms.Click` / `.Hover` / `.Press` / `.Release` | `UInt16` constants | Pointer/press interaction waveforms available since the class's original introduction (SDK 15063). |
| `KnownSimpleHapticsControllerWaveforms.Success` / `.Error` | `UInt16` constants | Process-confirmation waveforms for a completed or failed action. |

## Notes

- Namespace: `Windows.Devices.Haptics`. Minimum OS: Windows 11, version 24H2, build `10.0.26100.0` (UniversalApiContract v19.0) for both `InputHapticsManager` itself and the `Align`/`Collide`/`Step`/`Grow` waveforms. Guard all calls with `ApiInformation.IsTypePresent` to target earlier OS versions.
- Haptics availability depends on the physical input device (mouse/touchpad/pen model and manufacturer) in addition to the OS/SDK version — always check `InputHapticsManager.IsSupported()` (and, where relevant, `IsHapticDevicePresent()`) before calling waveform methods.
- This page covers the implementation-side API only. For when/why to use each waveform, recommended intensity/decay/sharpness characteristics, and the full waveform catalog including pen-specific continuous waveforms, see the design guidance for haptics (`develop/input/haptics` guide and the design/signature-experiences haptics documentation) — the same `InputHapticsManager` API also drives pen-specific `SimpleHapticsController` scenarios (see Pen and Windows Ink in this category) which are out of scope here.
