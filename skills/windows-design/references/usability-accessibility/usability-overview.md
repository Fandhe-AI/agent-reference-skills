# Usability overview

Guidance for making a Windows app more usable by addressing accessibility, bidirectional text support, a well-designed settings experience, and in-app help.

## Signature / Usage

The usability section of the Windows app design guidance covers four pillars:

- **Accessibility** — making the app usable by people with limitations that prevent or impede the use of conventional user interfaces. See [Accessibility overview](./accessibility-overview.md) and [Designing inclusive software](./designing-inclusive-software.md).
- **App settings** — a dedicated settings page that lets users customize the app. See [Guidelines for app settings](./app-settings.md).
- **Bidirectional text** — supporting right-to-left (RTL) and left-to-right (LTR) writing systems. See [Design your app for bidirectional text](./bidirectional-text.md).
- **In-app help** — instructional UI and in-app/external help content for users who need extra guidance. See [Guidelines for app help](./app-help-guidelines.md), [Instructional UI](./instructional-ui.md), [In-app help](./in-app-help.md), and [External help](./external-help.md).

## Notes

- Accessibility requirements are sometimes imposed by law, but addressing them is worthwhile regardless because it lets the app reach the largest possible audience.
- For accessibility implementation guidance (keyboard navigation, screen reader support, contrast themes), see the linked accessibility topics.
