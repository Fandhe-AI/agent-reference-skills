# Direct3D 11 on 12: D3D11On12CreateDevice, ID3D11On12Device, wrapped resources

D3D11On12 lets D3D11 interfaces and objects drive the D3D12 API, so D3D11-based components (for example D2D text and UI) can work together with D3D12 components, and apps can be ported from D3D11 to D3D12 incrementally.

## Signature / Usage

The source page has no code sample; this is its outline of the typical D2D-over-D3D12 flow (API names as given, arguments omitted):

```text
Setup:
  D3D12CreateDevice + IDXGIFactory::CreateSwapChain (ID3D12CommandQueue as input)
  D3D11On12CreateDevice (same D3D12 device and command queue)
  QueryInterface device -> ID3D11On12Device
  ID3D11On12Device::CreateWrappedResource   // per back buffer; in-state = last D3D12 use (e.g. RENDER_TARGET), out-state = next use (e.g. PRESENT)
  initialize D2D with the wrapped resources

Per frame:
  render with a D3D12 command list, execute it
  ID3D11On12Device::AcquireWrappedResources
  issue D2D rendering commands
  ID3D11On12Device::ReleaseWrappedResources
  flush the D3D11 immediate context
  IDXGISwapChain1::Present1
```

## Options / Props

| Name | Type | Description |
|------|------|-------------|
| D3D11On12CreateDevice | function | Creates a D3D11 device (imaginary driver type `D3D_DRIVER_TYPE_11ON12`) from a D3D12 device and command queue. |
| ID3D11On12Device | interface | Primary D3D11/D3D12 interop interface; obtained by `QueryInterface` on the D3D11 device. |
| CreateWrappedResource | method | Promotes a D3D12 resource so D3D11 can use it; the wrapped resource starts in the "acquired" state. |
| AcquireWrappedResources / ReleaseWrappedResources | methods | Manipulate the acquired state and keep resource state tracking coherent with the app's needs. |

## Notes

- The D3D11 immediate context must be flushed before additional D3D12 work is submitted to the same queue. The queue given to D3D11On12 must be drainable at all times (any waits must eventually be satisfied). Do not depend on when D3D11On12 inserts flushes or waits (may change).
- D3D11On12 tracks and manipulates resource states itself; use acquire/release to keep state transitions coherent.
- Releasing a wrapped resource: first release all references including views, then ensure deferred destruction (simplest: immediate context `Flush`). D3D12 still needs GPU completion before final release, so hold a reference first unless the GPU is known to be done. Releasing the D3D11On12 device while the GPU is executing may block.
- Limitations: shader interfaces work only on Windows 10 version 1809 (Build 17763) or later with a Shader Model 6.0+ driver; swap chains supported on D3D11On12 devices from Windows 10 version 1803 (Build 17134). Not optimized: moderate CPU overhead, minimal GPU overhead, significant memory overhead; recommended for simple scenes or 2D rendering, not complicated 3D scenes. Fixed-function operations such as `GenerateMips` and `DrawAuto` are emulated with shaders and extra resources.
- Check `RenderPassesTier` before relying on render passes when using D3D11On12.
- Namespace: Win32 COM (`d3d11on12.h`).
- Source: https://learn.microsoft.com/en-us/windows/win32/direct3d12/direct3d-11-on-12 (learn.microsoft.com win32 docs at commit `ca8274d`).
