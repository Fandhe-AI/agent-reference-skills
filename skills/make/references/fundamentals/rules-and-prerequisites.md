# Rules and Prerequisites

A rule appears in the makefile and says when and how to remake certain files, called the rule's targets. It lists the other files that are the rule's prerequisites, and the recipe to use to create or update the target. This page covers Source-backed behavior only. Verified against "This is Edition 0.77, last updated 26 February 2023, of The GNU Make Manual, for GNU make version 4.4.1." (checked 2026-09-26).

## Signature / Usage

```makefile
target: normal-prerequisites | order-only-prerequisites
	recipe-line-1
	recipe-line-2
```

```makefile
program.o: program.c program.h
	cc -c program.c
```

## Options / Props

| Element | Meaning | Description |
| --- | --- | --- |
| target | file name (usually) | "A target is usually the name of a file that is generated by a program; examples of targets are executable or object files." |
| prerequisite (normal) | file name | "A prerequisite is a file that is used as input to create the target." Normal prerequisites both order recipe invocation and impose a dependency: "if any prerequisite is newer than the target, then the target is considered out-of-date and must be rebuilt." |
| prerequisite (order-only) | file name, after `\|` | Establishes build order only. "Order-only prerequisites are never checked when determining if the target is out of date; even order-only prerequisites marked as phony will not cause the target to be rebuilt." |
| recipe | shell commands | "A recipe is an action that `make` carries out." Recipe lines must start with a tab (see `recipes-and-shell.md`). |

## Notes

- Normal prerequisite ordering rule (two statements in one): it imposes an order in which recipes will be invoked, and it imposes the out-of-date dependency relationship described above (`Prerequisite-Types.html`).
- Syntax for mixing both kinds: `targets : normal-prerequisites | order-only-prerequisites`.
- Phony targets are names for a recipe to run on explicit request, not real file names: "A phony target is one that is not really the name of a file; rather it is just a name for a recipe to be executed when you make an explicit request." Two reasons to use `.PHONY`: "to avoid a conflict with a file of the same name, and to improve performance."
- File-target vs phony-target risk: a target with no prerequisites (like a naive `clean:`) is always considered up to date once a same-named file exists in the directory, so its recipe stops running — "clean would always be considered up to date and its recipe would not be executed." Declare it phony with `.PHONY: clean` to avoid this.
- Design guidance (this skill, not the manual): reserve real file targets for artifacts you want incremental rebuilds for, and reserve `.PHONY` targets for developer-facing operations (`help`, `check`, `test`) that should always run — see the architecture category's command-contracts page for the contract design.
