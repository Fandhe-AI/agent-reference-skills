# Ignore files via .easignore

Learn how to configure Expo Build to ignore unnecessary files during the build process.

## Signature / Usage

A **.easignore** file defines which files Expo Services should ignore when uploading your project to the Expo Build servers. Ignoring unnecessary files can help reduce your app's archive size and upload time.

By default, EAS CLI refers to the **.gitignore** file (if it exists) to determine which files to ignore. If you create a **.easignore** file in the root of your Git repository, EAS CLI uses it instead of all **.gitignore** files in your repository. Include all files and directories from your **.gitignore** and add the additional files you want to ignore.

```bash
# Copy everything from your .gitignore file here

# Ignore files and directories that Expo Build doesn't need to build your app
/docs

# Ignore native directories (if you are using Expo Build)
/android
/ios

# Ignore test coverage reports
/coverage
```

Save the file and trigger a new build:

```sh
eas build --platform ios --profile development
```

### Adding files to your project upload

Use the `!` prefix to upload files that are not committed to source control (for example, temporary files generated by a script just before the build). The `!` prefixed file should be last, so it takes precedence over any prior rules that would ignore it.

```bash
# Copy everything from your .gitignore file here

/android
/ios

# Include a file not in source control
!temp_file.json
```

If the file contains secrets, use a file environment variable instead of adding it to your project archive.

### Check which files EAS CLI uploads

Run `eas build:inspect` with the `archive` stage to copy the files that EAS CLI uploads into a directory on your computer. The command does not start a build.

```sh
eas build:inspect --platform android --stage archive --output ./eas-archive
```

- Log in to your Expo account with `eas login` before you run this command.
- The output directory must not exist. To delete an existing output directory first, add `--force`.
- In the full Git workflow, commit your changes before you run this command. The command does not offer to commit them.

Open the output directory and confirm that it contains the files your build needs and none of the files you want to ignore.

## Notes

### How EAS CLI applies .easignore

- EAS CLI reads **.easignore** only from the root of your Git repository. In a monorepo, the repository root can be above your project directory.
- In the No VCS workflow (see project-upload.md), EAS CLI reads **.easignore** from the directory in the `EAS_PROJECT_ROOT` environment variable. If it is not set, EAS CLI reads it from the root of your Git repository, or from the current directory if there is no repository.
- To exclude the shallow **.git** directory from the project archive, add `.git` to **.easignore**.
- In the full Git workflow (see project-upload.md), EAS CLI still applies **.easignore** and deletes the matching files from the clone. The project on Expo Build no longer matches your commit, so EAS CLI shows a warning. To hide the warning, set the `EAS_SUPPRESS_REQUIRE_COMMIT_EASIGNORE_WARNING` environment variable to `1`.

### Other notes

- Ignore `/android` and `/ios` only when the project uses Continuous Native Generation (native directories are generated by Prebuild and listed in **.gitignore**). If you manage native code manually (existing React Native project), do not ignore them; otherwise Expo Build runs Prebuild and generates different native projects.
- If the project does not contain **android** and **ios** directories, Expo Build runs Prebuild to generate them before compilation.
