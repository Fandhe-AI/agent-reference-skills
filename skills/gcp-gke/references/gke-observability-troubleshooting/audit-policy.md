# GKE audit policy

Describes the two policies that shape GKE audit logs: the Kubernetes audit policy (which API server events are recorded and with what data) and the GKE audit policy (whether an entry goes to the Admin Activity log or the Data Access log).

## Signature / Usage

### Rule format

The first rule in the policy file that matches an event sets its audit level. The following rule logs matching events at the `Request` level.

```yaml
- level: Request
  userGroups: ["system:nodes"]
  verbs: ["update","patch"]
  resources:
    - group: "" # core
      resources: ["nodes/status", "pods/status"]
  omitStages:
    - "RequestReceived"
```

An event matches if it matches no previous rule, the caller is in the `system:nodes` group, the verb is `update` or `patch`, the resource is `nodes/status` or `pods/status`, and the stage is not `RequestReceived`.

### Rules that suppress events

Adapted (not in the official docs): fixed the YAML indentation so `resources` nests under the `group` list item; the source shows it at the dash level, which does not parse.

```yaml
- level: None
  users: ["kubelet"] # legacy kubelet identity
  verbs: ["get"]
  resources:
    - group: "" # core
      resources: ["nodes", "nodes/status"]
```

### Special-case rules

Adapted (not in the official docs): fixed the YAML indentation of `resources` and `omitStages`; the source indents them by four spaces under `level`, which does not parse.

```yaml
- level: Metadata
  resources:
    - group: "" # core
      resources: ["secrets", "configmaps"]
    - group: authentication.k8s.io
      resources: ["tokenreviews"]
  omitStages:
    - "RequestReceived"
```

### General rules

Reads (`get`, `list`, `watch`) on the listed API groups are logged at `Request` (in effect `Metadata`, because reads have no request body):

```yaml
- level: Request
  verbs: ["get", "list", "watch"]
  resources:
    - group: "" # core
    - group: "admissionregistration.k8s.io"
    - group: "apiextensions.k8s.io"
    - group: "apiregistration.k8s.io"
    - group: "apps"
    - group: "authentication.k8s.io"
    - group: "authorization.k8s.io"
    - group: "autoscaling"
    - group: "batch"
    - group: "certificates.k8s.io"
    - group: "extensions"
    - group: "metrics.k8s.io"
    - group: "networking.k8s.io"
    - group: "policy"
    - group: "rbac.authorization.k8s.io"
    - group: "settings.k8s.io"
    - group: "storage.k8s.io"
  omitStages:
    - "RequestReceived"
```

Writes (`create`, `update`, `delete`) on the same groups use `level: RequestResponse` with the same `resources` list and `omitStages: ["RequestReceived"]`.

## Options / Props

### Request stages

| Stage | Description |
|---|---|
| RequestReceived | The audit handler has received the request. |
| ResponseStarted | Response headers sent, body not yet sent. |
| ResponseComplete | Response body completed, no more bytes will be sent. |
| Panic | Internal server error; the request did not complete. |

### Audit levels

| Level | Description |
|---|---|
| None | Do not create a log entry. |
| Metadata | Log entry with metadata, without request or response body. |
| Request | Metadata and request body, without response body. |
| RequestResponse | Metadata, request body, and response body. |

### Data Access log types

| Type | Meaning |
|---|---|
| `ADMIN_READ` | Reads of Kubernetes resource metadata, such as listing Pods. |
| `DATA_READ` | Reads of data in resources, such as reading Pod logs. |
| `DATA_WRITE` | Writes of data, such as updating Pod status. |

### GKE routing to logs

| Request | Log |
|---|---|
| `create`, `delete`, `update` | Admin Activity (no charge) |
| `get`, `list`, `updateStatus` | Data Access (Google Cloud Observability pricing; depends on your audit log configuration) |

## Notes

- Summary: writes are generally logged at `RequestResponse`; `get` / `list` / `watch` at `Metadata`. Special cases: `kubelet`, `system:node-problem-detector`, and `system:nodes` updates/patches on `nodes/status` and `pods/status` at `Request`; `deletecollection` by `system:serviceaccount:kube-system:namespace-controller` at `Request`; `secrets`, `configmaps`, `tokenreviews` at `Metadata`.
- Not logged: `system:kube-proxy` watches on endpoints/services; get by `system:unsecured` on `kube-system` configmaps; get by `kubelet` or `system:nodes` on nodes and `nodes/status`; get/update by `system:kube-controller-manager`, `system:kube-scheduler`, or `system:serviceaccount:endpoint-controller` on `kube-system` endpoints; get by `system:apiserver` on `namespaces`, `namespaces/status`, `namespaces/finalize`; get/list by `system:kube-controller-manager` on `metrics.k8s.io`; URLs matching `/healthz*`, `/version`, `/swagger*`.
- The policy file is generated by `configure-helper.sh` in the open source Kubernetes repository; the definitive list of special cases is in that script.
- Corrected from the official docs: the `level: None` example showed `resources: ["nodes", "nodes/status"]` at the same indentation as `- group: "" # core`, and the `level: Metadata` example indented `resources:` / `omitStages:` four spaces under `- level: Metadata`; both were re-indented so the YAML parses.
- The `RequestResponse` write rule block in the source repeats the same group list as the read rule without a `verbs` field; it is summarized in prose above rather than repeated.
