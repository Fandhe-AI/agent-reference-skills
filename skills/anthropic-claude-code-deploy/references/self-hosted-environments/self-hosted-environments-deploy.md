# Deploy self-hosted environments to production

Security hardening, network egress control, git credentials, Kubernetes/Compose recipes, and troubleshooting for running self-hosted runners in production.

## Signature / Usage

```dockerfile
FROM debian:bookworm-slim
ARG CLAUDE_CODE_VERSION
RUN apt-get update && apt-get install -y --no-install-recommends git curl ca-certificates openssh-client jq python3 \
 && rm -rf /var/lib/apt/lists/*
RUN curl -fsSL "https://downloads.claude.ai/claude-code-releases/${CLAUDE_CODE_VERSION:?set with --build-arg CLAUDE_CODE_VERSION}/linux-x64/claude" \
      -o /usr/local/bin/claude && chmod +x /usr/local/bin/claude
RUN git config --system user.name "Claude" \
 && git config --system user.email "noreply@anthropic.com" \
 && git config --system --add safe.directory '*'
ENTRYPOINT ["claude"]
```

```bash
# If your model needs a newer release, change stable to latest in the URL
docker build \
  --build-arg CLAUDE_CODE_VERSION="$(curl -fsSL https://downloads.claude.ai/claude-code-releases/stable)" \
  -t <your-registry>/claude-runner:latest .
```

## Options / Props

| Name | Type | Description |
|------|------|-------------|
| `--configure-git` / `SELF_HOSTED_RUNNER_CONFIGURE_GIT=1` | runner flag | Writes global git config at startup: `user.name=Claude`, `user.email=noreply@anthropic.com`, SSH-format commit/tag signing via a runner-managed shim (git 2.34+ required, runner exits if older), `push.negotiate = true` (v2.1.257+), and `core.hooksPath` hooks adding a `Co-authored-by:` trailer from `CCR_SESSION_ACCOUNT_EMAIL`. Doesn't configure push credentials |
| `--use-anthropic-git-proxy` / `CLAUDE_RUNNER_USE_GIT_PROXY=1` | runner flag | Anthropic-managed git: clone and session fetch/push go through Anthropic using the session's short-lived token; no git credentials in the image. Needs v2.1.267+, `--capacity 1` (runner exits at startup otherwise), git 2.32+; github.com repositories only; branch pushes only; ignores `--git-host-rewrite` / `--git-ssh-rewrite`; deletes and replaces the global git config of the runner's user |
| `--git-host-rewrite <from>=<to>` | runner flag (repeatable) | Rewrites HTTPS source URLs before clone, for split-horizon DNS |
| `--git-ssh-rewrite <host>` | runner flag (repeatable) | Rewrites `https://<host>/owner/repo` to `git@<host>:owner/repo`, for SSH-only git hosts; runs after host rewriting |
| `--proxy-authorization-command <command>` / `--proxy-authorization-file <path>` | runner flag | Adds a `Proxy-Authorization` header to egress-proxy connections via a loopback listener (v2.1.238+). Mutually exclusive; needs `HTTPS_PROXY`/`HTTP_PROXY` set to an `http(s)://` URL; not accepted by the orchestrator subcommand |
| `--confine-repo-settings` | runner flag | `warn` (default, logs and still spawns), `enforce` (refuses the session), `off`; scans committed repo settings for grants outside the workspace (`additionalDirectories`, `Edit`/`Write`/`NotebookEdit` allow rules, `sandbox.filesystem.allowWrite`/`allowRead`), non-empty `env`, and overrides like `sandbox.enabled: false`. Doesn't cover repo hooks, `.mcp.json`, or Bash rules |
| `--drain-wait-sec` / `--session-stop-grace-sec` / `--post-session-hook-timeout-sec` | runner flag | Shutdown-drain components: 0 / 5 / 60 seconds by default, plus fixed 15 s headroom and 30 s more with `--push-outcome-on-release` (= 80 s at defaults; capacity doesn't add to it) |
| `--defer-shutdown-max-min <n>` | runner flag | Keep serving held sessions for `n` minutes after the first `SIGTERM`/`SIGINT` before releasing them (v2.1.238+); stop timeout must cover `n` minutes + post-release grace (75 s default, or `--drain-wait-sec` + 15 s when above 60 s) + drain (80 s) = `n` min + 155 s at defaults |
| `--release-idle-session-min <n>` / `--kill-session-after-min <n>` | runner flag | Release sessions idle for `n` minutes; backstop that ends runaway sessions (v2.1.260+: grace window of 15 min by default, `SELF_HOSTED_RUNNER_MAX_LIFETIME_GRACE_MS`, before terminating) |
| `--hold-idle-file <path>` / `--max-hold-min <n>` | runner flag | Keep an idle session while a file is touched more often than every 3 minutes (v2.1.311+); hold cap defaults to one day; set above `--release-idle-session-min` |
| `--push-outcome-on-release` | runner flag | Best-effort push of the session's outcome branches before release, so a resumed session starts from them; uses the runner host's own git credentials (git 2.29+ to resume) |
| `--remove-session-state` | runner flag | Delete each session's per-session directories (`<base-dir>/_sessions/...`) when it ends (best-effort) |
| `--base-dir <path>` / `--capacity <n>` | runner flag | Keep identical across all runners in an environment (capacity 1 checks out directly under base dir; above 1 uses per-session worktrees); pass explicitly |
| `terminationGracePeriodSeconds` / `stop_grace_period` | orchestrator config | Kubernetes/Compose stop timeout; must be at least the runner's startup-logged `This runner needs up to` time (80 s at defaults); Kubernetes' 30 s default is too short |

## Notes

- Hardening checklist: ephemeral per-session containers (`--capacity 1`, default `--drain-grace-sec 0`; destroying the container ends daemonized processes); no broad credentials in the image (mint per session via the wrapper script; the initial clone happens before the wrapper, so use a `checkout` hook or `--use-anthropic-git-proxy`); keep the host's own GitHub credentials (PAT, `gh auth login` token, `GH_TOKEN`) away from sessions; keep the environment secret off session-running hosts (prefer on-demand runners; on a fixed fleet treat it as readable by every session); default-deny egress at your own boundary; least-privilege host IAM; block the cloud metadata endpoint in the session container itself (IMDSv2 hop limit one, GKE Workload Identity with metadata concealment, or deny `169.254.169.254` in the container's network namespace); per-runner filesystem isolation with `--hooks-dir`, the wrapper script, and `~/.claude/` read-only to the session; dispatch has no per-environment ACL (any org member, and anyone Claude Tag admits for channels routed to the environment, can dispatch; `--lock-to-account` doesn't narrow who can dispatch); enforce the repo-settings guard.
- After a suspected compromise: first select **Revoke token** in the session's menu on the **Activity** tab, then have an Owner create a new secret and revoke the old one from the **Configuration** tab and roll it out (runners on the old secret exit, interrupting sessions).
- IP allowlisting: if enabled, add public egress addresses of runners and session containers (and the orchestrator host for on-demand runners); don't rely on it as a network control.
- Network requirements, always: `api.anthropic.com` (443; WSS for Anthropic-managed git) and your git host (443/22; not needed for github.com with `--use-anthropic-git-proxy`, unless you set `--push-outcome-on-release` or push from a `post-session` hook). Conditional: `api.github.com` (image includes GitHub CLI and sessions get a github.com credential), `downloads.claude.ai` (install time; plugin installs from the official marketplace at runtime; `install.sh` itself is served from `claude.ai`), `storage.googleapis.com` (plugin install counts), `code.claude.com` and `claude.com` (documentation lookups only), `*.frame.claudeusercontent.com` (Artifact tool; `CLAUDE_CODE_DISABLE_ARTIFACT=1` keeps it disabled), `registry.npmjs.org` (plugins, `npx` MCP servers), package registries or an internal mirror, `http-intake.logs.us5.datadoghq.com` (only with `CLAUDE_CODE_BYOC_ENABLE_DATADOG=1`), `browser-intake-us5-datadoghq.com` (error reports; suppressed by `DISABLE_ERROR_REPORTING=1` / `DISABLE_TELEMETRY=1`), and your cloud provider's endpoints when sending model requests to Bedrock / Agent Platform. Not needed: `statsig.anthropic.com`, `*.sentry.io`, `claude.ai`, `platform.claude.com`, `mcp-proxy.anthropic.com`. Host-side flows that do reach `claude.ai`: the installer, and interactive `claude auth login` (also `claude.com`, `platform.claude.com`, `hcaptcha.com`, `*.hcaptcha.com`, `challenges.cloudflare.com`, and `sso.claude.com` with SSO) — used by guided setup, `doctor` signed-in mode, and CI dispatch.
- Egress proxy authentication: with either proxy-authorization flag, the runner starts a loopback forward proxy, rewrites `HTTPS_PROXY`/`HTTP_PROXY` to point at it (for itself, hooks, and sessions), re-runs your command / re-reads your file for each new connection (open connections keep the old token), and in sessions removes `ALL_PROXY` and unset proxy-variable spellings and pins `NO_PROXY`. It never logs the header value; a failing/empty/30 s-timeout source yields `502 Bad Gateway` on that connection.
- Git config: use `--configure-git`, or ship your own via `git config --system` in the image (identity is required, otherwise `git commit` fails with `Please tell me who you are`). Push credentials at image level only if tightly scoped: a one-repo SSH deploy key with `url.<base>.insteadOf`, a `credential.helper` returning a minimal token, or `GIT_SSH_COMMAND` with a narrow key — and they must work without a prompt (the runner sets `GIT_TERMINAL_PROMPT=0`, SSH `BatchMode=yes`, `GCM_INTERACTIVE=never`, and clears `core.askPass`; use `GIT_ASKPASS` instead). Keep programs named in `GIT_SSH_COMMAND` / `GIT_ASKPASS` unwritable by sessions. Git floors: 2.24 baseline; 2.34 for `--configure-git` signing; 2.32 for the git proxy; 2.29 for resume from `--push-outcome-on-release` branches. From v2.1.280, commits from `checkout` / `post-session` hooks are signed as the session. Claude Code adds a `Claude-Session: <url>` commit trailer and PR-description URL; set `attribution.sessionUrl` to `false` in the runner host's `~/.claude/settings.json` to omit them.
- Anthropic git proxy: per-session decision by Anthropic; logs `Registering as opted in to Anthropic-managed git (--use-anthropic-git-proxy)` at startup and `governed git ACTIVE` per served session, or a `[runner:warn]` `the server withheld Anthropic-managed git for this session` (for example a session with any non-github.com repository; GitHub Enterprise Server unsupported). Credentials only for the session's own repositories (private submodules, git-fetched dependencies, plugin marketplaces in other repos get none). User sessions use the creator's GitHub OAuth token (creator must connect GitHub; otherwise `GitHub authentication required`); bot/agent sessions use the org's GitHub App installation token. `remote: access denied by the git proxy` means policy or authorization refused. To turn it off: remove the flag / unset `CLAUDE_RUNNER_USE_GIT_PROXY`, provide prompt-free credentials for every git host (github.com included; the old global config is gone), open ports 443/22 to the git hosts, restart runners. Adding it to the capacity-4 recipes without `--capacity 1` makes the runner exit at startup (`[runner:fatal] --use-anthropic-git-proxy requires --capacity 1 ...`).
- `gh` access: without the GitHub CLI in the image, Claude Code provides a built-in `gh` (v2.1.287+; only `gh api`, routed through Anthropic-managed git; install `jq` for `--jq`; absent when `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set or the session isn't served; log shows `gh_path_shim=true`). With the GitHub CLI in the image, mint a short-lived least-scoped `GH_TOKEN` per session in the wrapper script and allow `api.github.com`.
- Private CA with Anthropic-managed git (v2.1.283+): prefer installing the CA in the system store or `GIT_SSL_CAINFO=<PEM file>`; `GIT_SSL_NO_VERIFY` doesn't help behind a re-signing proxy for the runner's own clone. The runner builds a per-session cert file from the system bundle (`/etc/ssl/certs/ca-certificates.crt` or `/etc/pki/tls/certs/ca-bundle.crt`) plus your PEM file (readable, `CERTIFICATE` blocks, at most 1 MiB), warning `did not build the certificate file` otherwise. For `NODE_EXTRA_CA_CERTS` (TLS errors at `RegisterRunner failed:` / orchestrator `poll failed:`), git doesn't read it — set `GIT_SSL_CAINFO` too.
- Claude Tag channel repositories: install the Claude GitHub App on the owning org with the repository included, link the GitHub org under **Organization settings > Git providers**, and grant the repository in Claude Tag admin settings (Owner or Claude Tag Admin; a channel manager who administers the repo can add it to their channel), then name the repository in a new thread.
- Repositories outside GitHub: start the session from a terminal checkout with `claude -p "<prompt>" --environment <ccpool_...> --output-format json`; runner needs prompt-free HTTPS credentials for `https://<host>/<owner>/<name>` (or `--git-ssh-rewrite`), the git proxy off, an `origin` host that's a domain name with a path of the form `<owner>/<name>` (nested paths fail with `requires a git source, but no GitHub remote was detected`), and the branch pushed.
- Runner image: Anthropic doesn't publish one; add your toolchain. Keep `python3` in images that serve Claude Tag sessions (its supplied hooks run it). Swap `linux-x64` for `linux-arm64`, `linux-x64-musl`, or `linux-arm64-musl`; verify the binary per Binary integrity and code signing. Needs Claude Code 2.1.224+ (2.1.229+ for Claude Tag). The recipes use `--capacity 4`, which isn't per-session isolation: use `--capacity 1` with one container per session, or on-demand runners.
- Sizing (starting point per session): 4 GiB memory request = limit, 2 CPU request / 4 CPU limit; multiply by `--capacity` (and the sum across runners on one host); `--capacity` caps concurrency only, it doesn't divide resources. For per-session memory isolation use `--capacity 1` in its own container (`limits.memory` / `--memory` / `mem_limit`) or one runner per host under systemd `MemoryMax`; `ulimit -v` and kubelet `singleProcessOOMKill` don't separate sessions. Process/thread limits: `podPidsLimit` (kubelet), `--pids-limit` / `pids_limit`, `TasksMax`, `ulimit -u`; measure a session's peak via `pids.peak` / `pids.current` in the runner's cgroup, multiply by sessions sharing the limit; `fork rejected by pids controller` in `dmesg` shows a reached limit.
- Kubernetes: the recipe now passes `--base-dir /workspace`; runner serves `GET /healthz` on port 8080 (`--health-port`), which only reports the process is alive (nothing answers until startup checks finish; raise `initialDelaySeconds` or add a `startupProbe`); alert on `last_poll_age_seconds` to catch a stuck runner. The manifest sets no CPU/memory `resources`. Create the Secret from a file made with `(umask 077 && cat > ./environment-secret)`. Docker Compose: `restart: always` reuses the writable layer (evaluation only; Docker backs off between restarts). Compose also passes `--base-dir /workspace`.
- Shutdown timing: on `SIGTERM` the runner stops taking sessions, waits up to `--drain-wait-sec` for turns, terminates session process trees (not processes that outlived their shell command), then runs the `post-session` hook, polling throughout so the sessions stay assigned. To let turns finish before a rolling restart set `--drain-wait-sec` and raise the stop timeout to that plus 80 s (for example `--drain-wait-sec 120` → 200). If the stop timeout runs out, no `post-session` hook runs and requeue can take minutes. A second `SIGTERM` force-exits; the hook and session child run in their own process groups; hook timeout sends `SIGTERM` to the group then `SIGKILL` 2 s later. An Owner can post a status message on the environment from the Cloud environments page before a restart.
- Pre-warmed checkout: the runner keeps one clone per repository at `<base-dir>/<repo-owner>/<repo>`; supply it in the image or (with `--lock-to-account`, never for Claude Tag) on a persistent volume. Build it without `--depth`; `CLAUDE_RUNNER_FETCH_DEPTH` (default 50) is not passed when fetching into an existing clone. At `--capacity 1` a hard reset wipes tracked changes but untracked files persist (no `git clean`); per-session entries under `<base-dir>/_sessions/` persist unless `--remove-session-state`. With the git proxy the runner deletes the index (full checkout each session) and removes `.git/reftable/` (pre-warm in `files` ref format; no submodule pre-warms). Git operations use a 120 s no-progress watchdog and 30 min hard cap. Confirm with `--log-level debug` (`Prefetched repo found at` vs `No prefetched repo, fresh init at`).
- Pin the version: sessions run the runner's own binary and the runner turns off auto-update inside them; check model-required Claude Code versions before pinning (otherwise `Claude Code does not support this model`); upgrade on-demand runners by changing the `spawn-runner` image (don't restart existing ones — single-use work order); `--exec-path` or a `command` hook can start a different binary; `FORCE_AUTOUPDATE_PLUGINS=1` lets plugins auto-update.
- Scale: minimum replicas = concurrently active owners. Fixed fleet scaled on Prometheus metrics, or on-demand runners via `claude self-hosted-runner orchestrator` + `spawn-runner` hook. If sessions stay queued while runners are online, check `claude_code_self_hosted_runner_session_idle_seconds` and set `--release-idle-session-min` (and `--kill-session-after-min` for sessions that never count as idle: background task running, approval from a non-MCP tool, or MCP `elicitation/create`). `--hold-idle-file`: file in a directory sessions can't write, `touch` more often than every 3 minutes (for example a root crontab line `* * * * * pgrep -x nightly-build > /dev/null && touch /var/lib/claude-hold/hold-idle`); log lines `idle release held` / `idle release no longer held`.
- Known issues: connector (GitHub/Slack/Linear) traffic is called from Anthropic's infrastructure through `api.anthropic.com` — filter via `allowedMcpServers` / `deniedMcpServers`, and with a URL allowlist add `https://api.anthropic.com/v2/ccr-sessions/*`, `https://api.anthropic.com/v1/code/sessions/*`, `https://api.anthropic.com/v1/code/mcp/*` to keep delivered connectors; resumed sessions lose unpushed work (set `--push-outcome-on-release` on every runner, after restricting who can push `claude/*` refs; uncommitted changes, `checkout`-hook repos, and archived/deleted sessions still need a `post-session` hook); a command cut off by a lost runner can run again; a repository added mid-session clones over HTTPS and can fail with an auth error (a `checkout` hook runs with `CLAUDE_RUNNER_REPO_REF` empty); connectors not yet connected in claude.ai Settings, or added mid-session, need a fresh session. Report issues to your Anthropic account team.
- Troubleshooting: `claude self-hosted-runner doctor` starts an interactive read-only diagnosis session (needs `claude auth login` on the host for environment/runner/queue state; otherwise limited to health endpoint, metrics, and the log when `--log-file` is set; can requeue a stuck session). Startup failures print `[runner:fatal]` or `error:` lines (to stderr before `--log-file` opens): `cannot create or write to base directory` (or a base-directory check timeout on a hung NFS/CSI mount; checked at startup since v2.1.225), `RegisterRunner auth failed` (revoked or mistyped secret), TLS errors behind inspecting proxies (`NODE_EXTRA_CA_CERTS`). Start scripts that share the runner's stdout may hit `Resource temporarily unavailable` — redirect with `>> "$HOME/claude-runner.log" 2>&1`. Sessions stay queued: every online runner may be locked to a different owner (check `claude_code_self_hosted_runner_locked_account` / `locked_account` in `[runner:health]`). `rejecting the malformed poll response` means a proxy/captive portal altered responses (counted under the `transport` kind of `claude_code_self_hosted_runner_poll_errors_total`). A missing branch fails with `couldn't be found in the remote repository ... (couldn't find remote ref)`; sources a session only reads from can be skipped (`could not access context source`, `could not read context source` for HTTP 429 / exit 75; `This runner couldn't read` on not-found). Turns failing with a 401 trigger a `CLAUDE_CODE_OAUTH_TOKEN` refresh (`inference_token refresh failed`; failures ~30 minutes in suggest a wrapper severed stdin); `The server has refused to renew this session's access to the model` means renewals got HTTP 400; `This model needs a newer version of Claude Code` means upgrade the runners. Claude Tag not replying in Slack: runner v2.1.229+, `python3` in the image, no settings disabling hooks. Sessions slow to start: fresh clone — use a pre-warmed checkout or lower `CLAUDE_RUNNER_FETCH_DEPTH`; watch `claude_code_self_hosted_runner_session_init_duration_seconds`.
- When the runner exits: normal exit (restart it; never restart an on-demand runner), failed start (exits seconds after starting every time; fix the cause, no exit code distinguishes it), or lost contact (`runner record gone server-side` / `poll auth failed`; restart manually). Use a supervisor that restarts with growing waits (Kubernetes and Docker do by default; systemd doesn't — five starts in 10 s hits the rate limit; shell loop: start at 5 s, double after runs under a minute up to five minutes). `kubectl logs --previous -n claude-runners deploy/claude-runner` reads the last run; `docker inspect --format '{{.RestartCount}}' <container>`. An environment can read **Healthy** for a few minutes after the process died.
- Claude never answers the first message: a proxy is likely buffering or ending `GET https://api.anthropic.com/v1/code/sessions/<session-id>/worker/events/stream` (`text/event-stream`, open up to an hour, keep-alive at least every 15 s by default). Confirm on runner v2.1.287+ after `--startup-timeout-min` (15 min default) via `no child output for ... — releasing` and `SDKStartup: SSE` lines (`SSE connect failed (no response in 30s)` / `SSE liveness timeout`: proxy not forwarding; `SSE connect failed (HTTP <status>`: check proxy log; `SSE stream ended by server` repeatedly: proxy time limit; `SSE reconnected after`: look for other lines). Archive the session in claude.ai/code to stop retries.
