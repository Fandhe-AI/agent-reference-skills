# Rust 2024

**Released with Rust 1.85.0 (February 20, 2025). RFC [#3501](https://rust-lang.github.io/rfcs/3501-edition-2024.html).**

## Signature / Usage

```toml
[package]
edition = "2024"
```

Migrate with:

```bash
cargo fix --edition
```

---

## Breaking Changes — Language

### 1. `if let` Temporary Scope

Temporaries from the scrutinee of an `if let` expression are now dropped earlier: at the end of the then-block (or when the `else` branch is entered), rather than after the entire `if let` expression.

```rust
// Before 2024 — DEADLOCK RISK
fn f(value: &RwLock<Option<bool>>) {
    if let Some(x) = *value.read().unwrap() {
        println!("value is {x}");
    } else {
        let mut v = value.write().unwrap();  // Deadlock! Read lock still held
    }
    // <-- Read lock dropped here (2021 behavior)
}

// In 2024: read lock is dropped before the else block — no deadlock
```

Detected by the `if_let_rescope` lint. Automated by `cargo fix --edition` (rewrites to `match` where needed).

---

### 2. `let` Chains in `if` and `while`

`let` expressions can now be chained with `&&` in `if` and `while` conditions. This is a pure extension — no existing code breaks.

```rust
fn sum_first_two(nums: &[u8]) -> Option<u8> {
    let mut iter = nums.iter();
    if let Some(first) = iter.next()
        && let Some(second) = iter.next()
    {
        first.checked_add(*second)
    } else {
        None
    }
}
```

Parenthesized `let` chains (`if (let Some(x) = foo || let Some(y) = bar)`) remain invalid.

---

### 3. Match Ergonomics Restrictions

To reserve design space for future improvements, patterns mixing explicit and implicit reference modes are now restricted:

```rust
// 2021 — allowed
let [x, mut y] = &[(), ()]; // x: &(), y: () (mut)

// 2024 — must be fully explicit
let &[ref x, mut y] = &[(), ()];
```

Similarly, redundant `ref` / `ref mut` bindings and `&` / `&mut` patterns inside implicitly-dereferenced patterns are disallowed. Detected by `rust_2024_incompatible_pat`. Automated by `cargo fix --edition`.

---

### 4. RPIT Lifetime Capture Rules

Return-position `impl Trait` (RPIT) now **captures all in-scope generic parameters by default**, including lifetime parameters.

```rust
// In 2021:  lifetimes captured only if they appear syntactically in a bound
// In 2024:  ALL in-scope lifetimes captured unconditionally

fn f<'a>(x: &'a ()) -> impl Sized { *x }
// 2021 equivalent: impl Sized + use<>
// 2024 equivalent: impl Sized + use<'a>
```

Use the explicit `use<..>` bound (stable since 1.82) to control capturing precisely:

```rust
// Opt out of capturing 'a in 2024
fn f<'a>(x: &'a ()) -> impl Sized + use<> { *x }
```

**Migrating away from the `Captures` trick**:

```rust
// Old pattern (all editions)
pub trait Captures<T: ?Sized> {}
impl<T: ?Sized, U: ?Sized> Captures<T> for U {}
fn f<'a, T>(x: &'a (), y: T) -> impl Sized + Captures<(&'a (), T)> { (x, y) }

// Modern (all editions since 1.82)
fn f<'a, T>(x: &'a (), y: T) -> impl Sized + use<'a, T> { (x, y) }

// Rust 2024 (simplified — captures everything by default)
fn f<'a, T>(x: &'a (), y: T) -> impl Sized { (x, y) }
```

**APIT (argument-position `impl Trait`) requires manual naming**:

```rust
// Before (overcaptures in 2024)
fn f<'a>(x: &'a (), y: impl Sized) -> impl Sized { (*x, y) }

// After (name the type parameter explicitly)
fn f<'a, T: Sized>(x: &'a (), y: T) -> impl Sized + use<T> { (*x, y) }
```

Detected by the `impl_trait_overcaptures` lint. Automated by `cargo fix --edition` except for APIT cases.

---

### 5. Tail Expression Temporary Scope

Temporaries in **tail expressions** (the last expression in a function, closure, or block) are now **dropped before local variables** instead of after.

```rust
use std::cell::RefCell;

fn f() -> usize {
    let c = RefCell::new("..");
    c.borrow().len()
    // 2021: Ref temporary dropped AFTER `c` → "does not live long enough" error
    // 2024: Ref temporary dropped BEFORE `c` → compiles fine
}
```

Temporaries may also no longer extend outside a block expression:

```rust
// Fails in 2024, works in 2021
let x = { &String::from("1234") }.len();

// Fix: extract to a local variable
let s = String::from("1234");
let x = s.len();
```

Detected by the `tail_expr_drop_order` lint. **No automated fix** — manual review required.

---

### 6. `unsafe` on `extern` Blocks

`extern` blocks must now be marked `unsafe`:

```rust
// 2021
extern "C" {
    fn strlen(s: *const i8) -> usize;
}

// 2024
unsafe extern "C" {
    // Items can now be individually marked safe or unsafe
    pub safe fn sqrt(x: f64) -> f64;
    pub unsafe fn strlen(p: *const std::ffi::c_char) -> usize;
    pub fn free(p: *mut core::ffi::c_void); // defaults to unsafe
}
```

`safe` items in `unsafe extern` blocks can be called without an `unsafe` block.

Detected by `missing_unsafe_on_extern`. Automated by `cargo fix --edition` (but cannot verify signature correctness — manual review required).

---

### 7. `unsafe_op_in_unsafe_fn` Warning Promoted

In 2024 `unsafe_op_in_unsafe_fn` is **warn by default**. Unsafe operations inside `unsafe fn` must be wrapped in an explicit `unsafe` block:

```rust
// 2021 — allowed
unsafe fn get<T>(x: &[T], i: usize) -> &T {
    x.get_unchecked(i)
}

// 2024 — must use explicit unsafe block
unsafe fn get<T>(x: &[T], i: usize) -> &T {
    unsafe { x.get_unchecked(i) }
}
```

RFC [#2585](https://rust-lang.github.io/rfcs/2585-unsafe-block-in-unsafe-fn.html). Automated by `cargo fix --edition`.

---

### 8. Unsafe Attributes

The attributes `export_name`, `link_section`, and `no_mangle` must now be marked `unsafe`:

```rust
// 2021
#[no_mangle]
pub fn example() {}

// 2024
// SAFETY: no other global function named `example`
#[unsafe(no_mangle)]
pub fn example() {}
```

Detected by `unsafe_attr_outside_unsafe`. Automated by `cargo fix --edition`.

---

### 9. `gen` Keyword Reserved

`gen` is now a reserved keyword (RFC [#3513](https://rust-lang.github.io/rfcs/3513-gen-blocks.html)) in preparation for generator/coroutine blocks in a future release.

```rust
// 2021 — allowed as identifier
fn gen() { println!("generating!"); }

// 2024 — must use raw identifier
fn r#gen() { println!("generating!"); }
r#gen();
```

Detected by `keyword_idents_2024`. Automated by `cargo fix --edition`.

---

### 10. Disallow References to `static mut`

Taking shared or mutable references to `static mut` variables is now a hard error (`static_mut_refs` lint is `deny` by default). This was always instant UB.

```rust
static mut X: i32 = 23;

unsafe {
    let y = &X;          // ERROR in 2024
    let ref x = X;       // ERROR in 2024
    println!("{X}");     // ERROR in 2024 (implicit reference)
}
```

**Recommended alternatives:**

| Use case | Alternative |
|----------|-------------|
| Simple integers / booleans | `static X: AtomicI32 = AtomicI32::new(23)` |
| Complex types | `Mutex<T>` / `RwLock<T>` |
| One-time initialization | `OnceLock<T>` / `LazyLock<T>` |
| Must use `static mut` | `&raw const X` / `&raw mut X` raw pointer operators |

No automated fix — manual rewrite required.

---

### 11. Never Type Fallback Changes

When the compiler needs a fallback for an unconstrained `!` (never type) at a coercion site, it now falls back to `!` instead of `()`.

```rust
// Pattern that breaks in 2024:
fn f<T: Default>() -> Result<T, ()> { Ok(T::default()) }
f()?;  // T was inferred as () in 2021; now inferred as !, which may not impl Default
```

**Fixes**:

```rust
// Explicit type annotation
f::<()>()?;

// Or use turbofish / type ascription
() = f()?;

// For closures returning !
run(|| -> () { panic!() });
```

The `never_type_fallback_flowing_into_unsafe` lint is `deny` by default in 2024. **No automated fix** — manual type annotation required.

---

### 12. Macro Fragment Specifiers

The `expr` fragment specifier now also matches `const` and `_` expressions. The `expr_2021` fragment specifier is added for backwards compatibility (it does not match the new expressions).

```rust
macro_rules! example {
    ($e:expr) => { println!("first rule"); };
    (const $e:expr) => { println!("second rule"); };
}

fn main() {
    example!(const { 1 + 1 });
}
```

In the 2021 Edition this matches the *second* rule; in 2024 `expr` matches `const { .. }`, so the *first* rule matches. Detected by the `edition_2024_expr_fragment_specifier` lint, which rewrites `expr` to `expr_2021`. Automated by `cargo fix --edition`; in most cases revert the rewrite to keep the new `expr` behavior after checking other rules for conflicts.

---

### 13. Missing Macro Fragment Specifiers

The `missing_fragment_specifier` lint is now a hard error: an unused rule in a `macro_rules!` definition with a meta-variable lacking a fragment specifier is rejected.

```rust
macro_rules! foo {
   () => {};
   ($name) => { }; // ERROR: missing fragment specifier
}
```

Migration: remove the unused matcher rule. **No automatic migration.** The lint was future-incompatible since Rust 1.17, deny-by-default since 1.20, warned about dependencies using the pattern since 1.82, and became a hard error in **all editions** in Rust 1.89.

---

### 14. Reserved Syntax

Unprefixed guarded strings of the form `#"foo"#` and two or more consecutive `#` characters are reserved for future use (RFC [#3593](https://rust-lang.github.io/rfcs/3593-unprefixed-guarded-strings.html)). The 2021 Edition already reserved prefixed forms such as `ident##"foo"##`.

```rust
macro_rules! demo {
    ( $a:tt ) => { println!("one token") };
    ( $a:tt $b:tt $c:tt ) => { println!("three tokens") };
}

demo!("foo");
demo!(r#"foo"#);
demo!(#"foo"#);   // compile error in 2024
demo!(###)        // compile error in 2024
```

Detected by `rust_2024_guarded_string_incompatible_syntax`, which suggests inserting spaces. Automated by `cargo fix --edition`.

## Breaking Changes — Standard Library

### Changes to the Prelude

`Future` and `IntoFuture` are added to the 2024 prelude. A trait method call such as `x.poll()` from a user trait can become ambiguous when `Future` is also in scope; fix with fully qualified syntax (`<_ as MyPoller>::poll(..)`).

Detected by `rust_2024_prelude_collisions`. Automated by `cargo fix --edition`.

### `IntoIterator` for `Box<[T]>`

Boxed slices implement `IntoIterator` in all editions (since Rust 1.80). In editions before 2024, method-call syntax `boxed_slice.into_iter()` still resolves to `(&(*boxed_slice)).into_iter()` (yielding `&T`); in 2024 it calls `IntoIterator::into_iter` (yielding `T`). `for x in my_boxed_slice` yields values in all editions.

Detected by `boxed_slice_into_iter` (warn by default in all editions). Automated by `cargo fix --edition` (rewrites calls to `.iter()` to keep the old behavior).

### Newly Unsafe Functions

`std::env::set_var`, `std::env::remove_var`, and `std::os::unix::process::CommandExt::before_exec` are `unsafe` in 2024 (not required in earlier editions). `before_exec` was deprecated in 1.37 in favor of `pre_exec`.

```rust
fn main() {
    // TODO: Audit that the environment access only happens in single-threaded code.
    unsafe { std::env::set_var("FOO", "123") };
}
```

Detected by `deprecated_safe_2024`. Automated by `cargo fix --edition` (wraps calls in `unsafe`; correctness must be reviewed manually — do not call `set_var` / `remove_var` while other threads may run).

## Breaking Changes — Cargo

### Rust-version Aware Resolver

`edition = "2024"` implies `resolver = "3"`, which implies `resolver.incompatible-rust-versions = "fallback"` (Rust-version aware dependency resolution; opt-in since Rust 1.84). The setting is workspace-global and honored only for the top-level package; a virtual workspace must still set `resolver` explicitly in `[workspace]`. No automated migration.

### Table and Key Name Consistency

Removed in 2024: `[project]` (use `[package]`), `default_features` (use `default-features`), `crate_type` (use `crate-type`), `proc_macro` (use `proc-macro`), `dev_dependencies` (use `dev-dependencies`), `build_dependencies` (use `build-dependencies`).

```toml
[dev-dependencies]
rand = { version = "0.8.5", default-features = false }
```

Automated by `cargo fix --edition`.

### Reject Unused Inherited default-features

`default-features = false` is not allowed on an inherited workspace dependency unless the workspace dependency itself specifies `default-features = false`.

```toml
[dependencies]
regex = { workspace = true, default-features = false }  # ERROR if workspace.dependencies.regex does not set default-features = false
```

Automated by `cargo fix --edition` (removes the key).

## Breaking Changes — Rustdoc

### Combined Tests

Doctests are combined into a single binary (tests still run in independent processes). Rustdoc combines only if the whole crate is Edition 2024+. Tests using `compile_fail`, an `edition` tag, global attributes (e.g. `global_allocator`), crate-wide attributes (`#![feature(..)]`), or a macro using `$crate` are not combined. Add the `standalone_crate` tag to force a separate executable:

```rust
//! ```standalone_crate
//! let location = std::panic::Location::caller();
//! assert_eq!(location.line(), 5);
//! ```
```

No automatic migration. Watch for `std::panic::Location` values and `std::any::type_name` module paths, which change under combining.

### Nested `include!` Change

When Markdown pulled in via `#[doc=include_str!(..)]` has a doctest that uses `include!`, `include_str!`, or `include_bytes!`, the path is resolved relative to the Markdown file instead of the Rust source file (e.g. `"../examples/data.bin"` becomes `"examples/data.bin"` for a `README.md` at the crate root). No automatic migration.

## Breaking Changes — Rustfmt

### Style Edition

Rustfmt introduces a `style_edition` that tracks Rust editions. With `edition = "2024"`, `cargo fmt` uses the 2024 style by default:

```bash
cargo fmt           # uses 2024 style when edition = "2024" in Cargo.toml
rustfmt --edition 2024 src/lib.rs
```

Override via `rustfmt.toml`:

```toml
style_edition = "2024"
```

### Formatting Fixes

Fixes to various formatting scenarios, e.g. long array / slice patterns are now wrapped, and single-expression closures with a loop body become block closures:

```rust
// Style edition 2024
fn main() {
    let [
        aaaaaaaaaaaaaaaaaaaaaaaaaa,
        bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb,
        cccccccccccccccccccccccccc,
        ddddddddddddddddddddddddd,
    ] = panic!();
}
```

Other fixes include: unrelated trailing comments are no longer aligned, empty lines in `where` clauses are removed, nested tuple indexing is `.0.0`, and `format_macro_matchers` / enum-variant doc comment wrapping off-by-one errors are fixed.

### Raw Identifier Sorting

Sorting uses the identifier without the `r#` prefix:

```rust
use websocket::r#async::futures::Stream;
use websocket::client::ClientBuilder;
use websocket::result::WebSocketError;
```

### Version Sorting

Sorting changes from "ASCIIbetical" to a version-sort-like algorithm that compares Unicode characters lexicographically and handles ASCII digits better:

```rust
use std::io::{self, Read, Write, stdout};
use std::num::{NonZeroU8, NonZeroU16, NonZeroU32, NonZeroU64};
```

All rustfmt changes are applied by running `cargo fmt` / `rustfmt` with the 2024 Edition.
