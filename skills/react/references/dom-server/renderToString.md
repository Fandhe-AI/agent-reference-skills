# renderToString

`renderToString` renders a React tree to an HTML string. It does not support streaming or waiting for data.

## Signature / Usage

```js
import { renderToString } from 'react-dom/server';

// The route handler syntax depends on your backend framework
app.use('/', (request, response) => {
  const html = renderToString(<App />);
  response.send(html);
});
```

Signature: `const html = renderToString(reactNode, options?)`. Returns an HTML string. On the client, call `hydrateRoot` to make the server-generated HTML interactive.

Removing `renderToString` from the client code (use `createRoot` and read HTML from the DOM):

```js
import { createRoot } from 'react-dom/client';
import { flushSync } from 'react-dom';

const div = document.createElement('div');
const root = createRoot(div);
flushSync(() => {
  root.render(<MyIcon />);
});
console.log(div.innerHTML); // For example, "<svg>...</svg>"
```

## Options / Props

| Name | Type | Description |
|------|------|-------------|
| reactNode | React node | A React node you want to render to HTML. For example, a JSX node like `<App />`. |
| options.identifierPrefix | string | (optional) A string prefix React uses for IDs generated by `useId`. Useful to avoid conflicts when using multiple roots on the same page. Must be the same prefix as passed to `hydrateRoot`. |

## Notes

- `renderToString` has limited Suspense support. If a component suspends, `renderToString` immediately sends its fallback as HTML.
- `renderToString` works in the browser, but using it in the client code is not recommended. Importing `react-dom/server` on the client unnecessarily increases your bundle size.
- `renderToString` does not support streaming or waiting for data. If you use Node.js, use `renderToPipeableStream`; if you use Deno or a modern edge runtime with Web Streams, use `renderToReadableStream`. You can continue using `renderToString` if your server environment does not support streams.
- For static site generation, use `prerenderToNodeStream` (Node.js) or `prerender` (Web Streams), which wait for data to load. You can continue using `renderToString` if your static site generation environment does not support streams.
- The `flushSync` call in the client example is necessary so that the DOM is updated before reading its `innerHTML` property.
- When a component suspends (for example, because it's defined with `lazy` or fetches data), `renderToString` will not wait; it renders the `fallback` of the closest `<Suspense>` boundary above it in the HTML. The content will not appear until the client code loads.
