# renderToPipeableStream

`renderToPipeableStream` renders a React tree to a pipeable Node.js Stream. This API is specific to Node.js; environments with Web Streams, like Deno and modern edge runtimes, should use `renderToReadableStream` instead.

## Signature / Usage

```js
import { renderToPipeableStream } from 'react-dom/server';

// The route handler syntax depends on your backend framework
app.use('/', (request, response) => {
  const { pipe } = renderToPipeableStream(<App />, {
    bootstrapScripts: ['/main.js'],
    onShellReady() {
      response.setHeader('content-type', 'text/html');
      pipe(response);
    }
  });
});
```

Signature: `const { pipe, abort } = renderToPipeableStream(reactNode, options?)`.

Returns an object with two methods:

- `pipe` outputs the HTML into the provided Writable Node.js Stream. Call `pipe` in `onShellReady` if you want to enable streaming, or in `onAllReady` for crawlers and static generation.
- `abort` lets you abort server rendering and render the rest on the client.

Your root component should return the entire document including the root `<html>` tag. React injects the doctype and your bootstrap `<script>` tags into the stream. On the client, hydrate the entire `document`:

```js
import { hydrateRoot } from 'react-dom/client';
import App from './App.js';

hydrateRoot(document, <App />);
```

Streaming more content with `<Suspense>`:

```js
function ProfilePage() {
  return (
    <ProfileLayout>
      <ProfileCover />
      <Sidebar>
        <Friends />
        <Photos />
      </Sidebar>
      <Suspense fallback={<PostsGlimmer />}>
        <Posts />
      </Suspense>
    </ProfileLayout>
  );
}
```

Error handling and status code (`onShellError` / `onError`):

```js
const { pipe } = renderToPipeableStream(<App />, {
  bootstrapScripts: ['/main.js'],
  onShellReady() {
    response.statusCode = 200;
    response.setHeader('content-type', 'text/html');
    pipe(response);
  },
  onShellError(error) {
    response.statusCode = 500;
    response.setHeader('content-type', 'text/html');
    response.send('<h1>Something went wrong</h1>');
  },
  onError(error) {
    console.error(error);
    logServerCrashReport(error);
  }
});
```

Waiting for all content for crawlers and static generation (`onAllReady`):

```js
const { pipe } = renderToPipeableStream(<App />, {
  bootstrapScripts: ['/main.js'],
  onShellReady() {
    if (!isCrawler) {
      response.statusCode = didError ? 500 : 200;
      response.setHeader('content-type', 'text/html');
      pipe(response);
    }
  },
  onAllReady() {
    if (isCrawler) {
      response.statusCode = didError ? 500 : 200;
      response.setHeader('content-type', 'text/html');
      pipe(response);
    }
  },
  onError(error) {
    didError = true;
    console.error(error);
    logServerCrashReport(error);
  }
});
```

Aborting server rendering:

```js
const { pipe, abort } = renderToPipeableStream(<App />, {
  // ...
});

setTimeout(() => {
  abort();
}, 10000);
```

## Options / Props

| Name | Type | Description |
|------|------|-------------|
| reactNode | React node | A React node you want to render to HTML. For example, a JSX element like `<App />`. It is expected to represent the entire document, so the `App` component should render the `<html>` tag. |
| options.bootstrapScriptContent | string | (optional) If specified, this string will be placed in an inline `<script>` tag. |
| options.bootstrapScripts | string[] | (optional) An array of string URLs for the `<script>` tags to emit on the page. Use this to include the `<script>` that calls `hydrateRoot`. Omit it if you don't want to run React on the client at all. |
| options.bootstrapModules | string[] | (optional) Like `bootstrapScripts`, but emits `<script type="module">` instead. |
| options.formState | object | (optional) The form state from a form submission handled by a Server Function. If the page is rendered in response to a submission of a form that uses `useActionState` with a `permalink`, pass the resulting form state so that React embeds it into the HTML for hydration. The same value must be passed to `hydrateRoot` on the client. This is typically passed through by your framework. |
| options.identifierPrefix | string | (optional) A string prefix React uses for IDs generated by `useId`. Useful to avoid conflicts when using multiple roots on the same page. Must be the same prefix as passed to `hydrateRoot`. |
| options.importMap | object | (optional) An import map object with `imports` and `scopes` properties. React emits it as an inline `<script type="importmap">` tag before any module scripts, so that `<script type="module">` tags (for example, from `bootstrapModules`) can use bare module specifiers. Canary only. When `nonce` is set, it is also applied to the import map script. |
| options.maxHeadersLength | number | (optional) The maximum total length of the header content passed to `onHeaders`, measured in UTF-16 code units. Defaults to 2000. Once the limit is reached, React stops adding resource hints to the headers. |
| options.namespaceURI | string | (optional) The root namespace URI for the stream. Defaults to regular HTML. Pass `'http://www.w3.org/2000/svg'` for SVG or `'http://www.w3.org/1998/Math/MathML'` for MathML. |
| options.nonce | string \| { script, style } | (optional) A `nonce` string to allow scripts for `script-src` Content-Security-Policy. To use different nonces for scripts and styles, pass an object with `script` and `style` properties instead. |
| options.onAllReady | function | (optional) Fires when all rendering is complete, including both the shell and all additional content. You can use this instead of `onShellReady` for crawlers and static generation. If you start streaming here, you won't get any progressive loading. The stream will contain the final HTML. |
| options.onBrowserBailout | function | (optional) Called when React recovers from `browser()` by leaving a Suspense fallback for the browser to replace. Receives an `Error` describing the browser-only render and an `errorInfo` object containing the `componentStack`. If a reason was passed to `browser`, it is available as `error.cause`. By default, React does nothing. |
| options.onError | function | (optional) Fires whenever there is a server error, whether recoverable or not. By default, this only calls `console.error`. If you override it to log crash reports, make sure that you still call `console.error`. You can also use it to adjust the status code before the shell is emitted. |
| options.onHeaders | function | (optional) Fires when React has determined the resource hints for the document, such as preconnects and stylesheet, font, or high-priority image preloads. It receives an object with a `Link` property containing the corresponding `Link` header value, so you can send it as an HTTP response header or as a 103 Early Hints response. React calls it even when there are no resource hints to send. The header content is capped by `maxHeadersLength`. |
| options.onShellReady | function | (optional) Fires right after the initial shell has been rendered. You can set the status code and call `pipe` here to start streaming. React will stream the additional content after the shell along with the inline `<script>` tags that replace the HTML loading fallbacks with the content. |
| options.onShellError | function | (optional) Fires if there was an error rendering the initial shell. It receives the error as an argument. No bytes were emitted from the stream yet, and neither `onShellReady` nor `onAllReady` will get called, so you can output a fallback HTML shell. |
| options.progressiveChunkSize | number | (optional) The number of bytes in a chunk. |

## Notes

- The part of your app outside of any `<Suspense>` boundaries is called the shell. It determines the earliest loading state that the user may see. `onShellReady` fires when the entire shell has been rendered; components in nested `<Suspense>` boundaries might still be loading data.
- Place `<Suspense>` boundaries so that the shell feels minimal but complete, like a skeleton of the entire page layout.
- Only data read from a source that activates a Suspense boundary, such as a Promise read with `use`, will suspend during rendering. Suspense does not detect data fetched inside an Effect or event handler.
- If an error occurs inside the shell, both `onError` and `onShellError` fire. Use `onError` for error reporting and `onShellError` to send the fallback HTML document.
- If a component outside the shell (inside a `<Suspense>` boundary) throws, React emits the closest fallback, gives up server rendering that content, and retries on the client. `onError` fires but you still get `onShellReady` instead of `onShellError`. If the client retry also fails, the closest parent error boundary determines what the user sees; if it succeeds, the server `onError` and client `onRecoverableError` callbacks still fire.
- Once you start streaming, you can no longer set the response status code. Errors outside the shell captured via `onError` are not exhaustive for status code purposes; move content into the shell if knowing about its errors is critical.
- With `onAllReady` for crawlers, the crawler waits for all data, some of which might be slow to load or error.
- `importMap` option: Canary only.
- Distinct from framework SSR: nextjs-app, tanstack-start and react-router wrap these APIs in their own skills; this page documents the raw `react-dom/server` API.
