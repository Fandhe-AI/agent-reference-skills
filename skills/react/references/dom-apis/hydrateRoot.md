# hydrateRoot

`hydrateRoot` lets you display React components inside a browser DOM node whose HTML content was previously generated by `react-dom/server`.

## Signature / Usage

```js
import { hydrateRoot } from 'react-dom/client';

hydrateRoot(document.getElementById('root'), <App />);
```

`const root = hydrateRoot(domNode, reactNode, options?)`. React will attach to the HTML that exists inside the `domNode`, and take over managing the DOM inside it. Returns an object with two methods: `render` and `unmount`.

- `root.render(reactNode)`: updates a React component inside a hydrated root. Returns `undefined`.
- `root.unmount()`: destroys the rendered tree inside the root. Takes no parameters, returns `undefined`.

Hydrating an entire document:

```js
import { hydrateRoot } from 'react-dom/client';
import App from './App.js';

hydrateRoot(document, <App />);
```

Suppressing an unavoidable mismatch on one element:

```js
export default function App() {
  return (
    <h1 suppressHydrationWarning={true}>
      Current Date: {new Date().toLocaleDateString()}
    </h1>
  );
}
```

Error logging in production:

```js
import { hydrateRoot } from "react-dom/client";
import App from "./App.js";
import { reportCaughtError } from "./reportError";

const container = document.getElementById("root");
const root = hydrateRoot(container, <App />, {
  onCaughtError: (error, errorInfo) => {
    if (error.message !== "Known error") {
      reportCaughtError({
        error,
        componentStack: errorInfo.componentStack,
      });
    }
  },
});
```

## Options / Props

| Name | Type | Description |
| --- | --- | --- |
| `domNode` | DOM element | A DOM element that was rendered as the root element on the server. |
| `reactNode` | React node | The "React node" used to render the existing HTML, usually JSX like `<App />` rendered with a `react-dom/server` method such as `renderToPipeableStream(<App />)`. |
| `options.onCaughtError` | function | Callback called when React catches an error in an Error Boundary. Called with the `error` and an `errorInfo` object containing the `componentStack`. |
| `options.onUncaughtError` | function | Callback called when an error is thrown and not caught by an Error Boundary. Called with the `error` and an `errorInfo` object containing the `componentStack`. |
| `options.onRecoverableError` | function | Callback called when React automatically recovers from errors. Called with the `error` and an `errorInfo` object containing the `componentStack`. Some recoverable errors may include the original error cause as `error.cause`. |
| `options.identifierPrefix` | string | A string prefix React uses for IDs generated by `useId`. Must be the same prefix as used on the server. |
| `options.formState` | form state | The form state from a form submission handled by a Server Function. If the page was rendered on the server in response to a submission of a form that uses `useActionState` with a `permalink`, pass the resulting form state so that `useActionState` returns the submitted state instead of the `initialState`. Must be the same value as the `formState` passed to the server renderer. Typically passed through by your framework. |

## Notes

- `hydrateRoot()` expects the rendered content to be identical with the server-rendered content. Treat mismatches as bugs and fix them. In development mode React warns about mismatches; there are no guarantees that attribute differences will be patched up.
- Most common causes of hydration errors: extra whitespace (like newlines) around the React-generated HTML inside the root node; checks like `typeof window !== 'undefined'` in rendering logic; browser-only APIs like `window.matchMedia` in rendering logic; rendering different data on the server and the client.
- You'll likely have only one `hydrateRoot` call in your app. If you use a framework, it might do this call for you.
- If your app is client-rendered with no HTML rendered already, using `hydrateRoot()` is not supported. Use `createRoot()` instead.
- If you call `root.render` before the root has finished hydrating, React will clear the existing server-rendered HTML content and switch the entire root to client rendering.
- Once you call `root.unmount` you cannot call `root.render` again on the root ("Cannot update an unmounted root" error).
- `suppressHydrationWarning={true}` only works one level deep, is an escape hatch, and React will not attempt to patch mismatched text content.
- For intentionally different client and server content, a two-pass render (state variable such as `isClient` set to `true` in an Effect) makes hydration slower because components render twice. If a component should render only in the browser, call `use(browser())` instead of waiting for an Effect.
- `root.render` only takes one argument; pass root options to `hydrateRoot(...)`, not `root.render(...)`.
- Migration (18 -> 19): `ReactDOM.hydrate` was removed in React 19; use `hydrateRoot`.
