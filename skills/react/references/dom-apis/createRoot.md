# createRoot

`createRoot` lets you create a root to display React components inside a browser DOM node.

## Signature / Usage

```js
import { createRoot } from 'react-dom/client';

const root = createRoot(document.getElementById('root'));
root.render(<App />);
```

`const root = createRoot(domNode, options?)`. React will create a root for the `domNode`, and take over managing the DOM inside it. Returns an object with two methods: `render` and `unmount`.

- `root.render(reactNode)`: displays a piece of JSX ("React node") into the root's DOM node. Returns `undefined`. `reactNode` is usually JSX like `<App />`, but can also be an element from `createElement()`, a string, a number, `null`, or `undefined`.
- `root.unmount()`: destroys the rendered tree inside the root. Takes no parameters, returns `undefined`.

Error logging in production:

```js
import { createRoot } from "react-dom/client";
import { reportCaughtError } from "./reportError";

const container = document.getElementById("root");
const root = createRoot(container, {
  onCaughtError: (error, errorInfo) => {
    if (error.message !== "Known error") {
      reportCaughtError({
        error,
        componentStack: errorInfo.componentStack,
      });
    }
  },
});
```

## Options / Props

| Name | Type | Description |
| --- | --- | --- |
| `domNode` | DOM element | React will create a root for this DOM element and allow you to call functions on the root, such as `render`. |
| `options.onCaughtError` | function | Callback called when React catches an error in an Error Boundary. Called with the `error` caught by the Error Boundary, and an `errorInfo` object containing the `componentStack`. |
| `options.onUncaughtError` | function | Callback called when an error is thrown and not caught by an Error Boundary. Called with the `error` that was thrown, and an `errorInfo` object containing the `componentStack`. |
| `options.onRecoverableError` | function | Callback called when React automatically recovers from errors. Called with an `error` React throws, and an `errorInfo` object containing the `componentStack`. Some recoverable errors may include the original error cause as `error.cause`. |
| `options.identifierPrefix` | string | A string prefix React uses for IDs generated by `useId`. Useful to avoid conflicts when using multiple roots on the same page. |

## Notes

- If your app is server-rendered, using `createRoot()` is not supported. Use `hydrateRoot()` instead.
- You'll likely have only one `createRoot` call in your app. If you use a framework, it might do this call for you. A page that uses "sprinkles" of React for parts of the page may have as many separate roots as needed.
- To render JSX in a different part of the DOM tree that isn't a child of your component (a modal or a tooltip), use `createPortal` instead of `createRoot`.
- The first time you call `root.render`, React will clear all the existing HTML content inside the React root before rendering the component into it.
- Calling `render` on the same root more than once updates the DOM as necessary, similar to calling the `set` function on the root component; state is preserved when the tree structure matches.
- Although rendering is synchronous once it starts, `root.render(...)` is not. Code after `root.render()` may run before any effects of that render are fired. In rare cases where effect timing matters, wrap `root.render(...)` in `flushSync`.
- Once you call `root.unmount` you cannot call `root.render` again on the same root ("Cannot update an unmounted root" error). You can create a new root for the same DOM node after the previous root has been unmounted.
- `root.render` only takes one argument; passing root options to it gives the warning "You passed a second argument to root.render(...) but it only accepts one argument". Pass them to `createRoot(...)`.
- Troubleshooting: "Target container is not a DOM element" means the value passed to `createRoot` is not a DOM node (e.g. `getElementById` returned `null`, or `createRoot(<App />)` was written); "Functions are not valid as a React child" means `root.render(App)` was used instead of `root.render(<App />)`.
- Migration (18 -> 19): `ReactDOM.render(<App />, node)` was removed in React 19; use `createRoot(node).render(<App />)`. `unmountComponentAtNode` was removed; use `root.unmount()`.
