# Workload Identity Federation

Workload identity federation lets an application outside Google Cloud (AWS, Microsoft Azure, any OIDC or SAML provider, X.509 certificates) access Google Cloud resources by impersonating a service account, without service account keys. The credential configuration file generated by gcloud contains only non-sensitive metadata telling the library how to get external subject tokens and exchange them for service account access tokens. Pool and provider setup is covered by the `gcp-foundation` skill.

## Signature / Usage

### Generate the credential configuration (AWS example)

Other providers use the same command with `--azure`, `--credential-source-file`, `--credential-source-url`, `--executable-command` or `--credential-cert-path` (see Options). Variables: `$PROJECT_NUMBER`, `$POOL_ID`, `$AWS_PROVIDER_ID`, `$SERVICE_ACCOUNT_EMAIL`.

Adapted (not in the official docs): quoted the shell variables so values with spaces stay one argument.

```bash
# Generate an AWS configuration file.
gcloud iam workload-identity-pools create-cred-config \
    "projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/$POOL_ID/providers/$AWS_PROVIDER_ID" \
    --service-account "$SERVICE_ACCOUNT_EMAIL" \
    --aws \
    --output-file /path/to/generated/config.json
```

### Use external identities with ADC

Store the path to the generated file in `GOOGLE_APPLICATION_CREDENTIALS`; the library then chooses the right client type from the file.

```bash
export GOOGLE_APPLICATION_CREDENTIALS=/path/to/config.json
```

Adapted (not in the official docs): the README called `client.fetch(url)` although only `auth` is defined; it now calls `auth.fetch(url)`.

```js
const auth = new GoogleAuth({
  scopes: 'https://www.googleapis.com/auth/cloud-platform'
});
const projectId = await auth.getProjectId();
// List all buckets in a project.
const url = `https://storage.googleapis.com/storage/v1/b?project=${projectId}`;
const res = await auth.fetch(url);
console.log(res.data);
```

Pass the project ID explicitly to avoid the `roles/browser` requirement:

```js
const auth = new GoogleAuth({
  scopes: 'https://www.googleapis.com/auth/cloud-platform',
  // Pass the project ID explicitly to avoid the need to grant `roles/browser` to the service account
  // or enable Cloud Resource Manager API on the project.
  projectId: 'CLOUD_RESOURCE_PROJECT_ID',
});
```

Or initialize an external account client from the generated file:

Adapted (not in the official docs): added a null check after `ExternalAccountClient.fromJSON`, which returns `null` when the JSON is not an external account configuration.

```js
const {ExternalAccountClient} = require('google-auth-library');
const jsonConfig = require('/path/to/config.json');

const client = ExternalAccountClient.fromJSON(jsonConfig);
if (!client) throw new Error('Not an external account credential configuration');
client.scopes = ['https://www.googleapis.com/auth/cloud-platform'];
// List all buckets in a project.
const url = `https://storage.googleapis.com/storage/v1/b?project=${projectId}`;
const res = await client.fetch(url);
console.log(res.data);
```

### Executable-sourced credentials: response contract

The executable prints JSON to stdout. Success (OIDC):

```json
{
  "version": 1,
  "success": true,
  "token_type": "urn:ietf:params:oauth:token-type:id_token",
  "id_token": "HEADER.PAYLOAD.SIGNATURE",
  "expiration_time": 1620499962
}
```

Error (all four fields required):

```json
{
  "version": 1,
  "success": false,
  "code": "401",
  "message": "Caller not authorized."
}
```

## Options / Props

| Name | Description |
|------|-------------|
| Provider flags for `create-cred-config` | `--aws`; `--azure`; OIDC file: `--credential-source-file` (optional `--credential-source-type "json"` and `--credential-source-field-name "id_token"`, required for json; default type is text); OIDC URL: `--credential-source-url` with `--credential-source-headers "$HEADER_KEY=$HEADER_VALUE"`; executable: `--subject-token-type`, `--executable-command` (the full command to run, including arguments; must be an absolute path to the program), `--executable-timeout-millis`, `--executable-output-file`. |
| `--service-account-token-lifetime-seconds` | Optional. Default one hour; minimum 600 (10 minutes), maximum 43200 (12 hours). Over one hour requires the service account in an Organization Policy enforcing `constraints/iam.allowServiceAccountCredentialLifetimeExtension`. A short lifetime reruns the whole token exchange (and calls the third-party provider) at that interval. |
| `--executable-timeout-millis` | Default 30 seconds; minimum 5 seconds; maximum 2 minutes. |
| `--executable-output-file` | Caches the executable response; the library reads it first. The executable writes it; the library only reads. `expiration_time` is required in the response only when an output file is configured. |
| `GOOGLE_EXTERNAL_ACCOUNT_ALLOW_EXECUTABLES` | Must be `1` to use executable-sourced credentials. |
| Env vars set for the executable | `GOOGLE_EXTERNAL_ACCOUNT_AUDIENCE` (always), `GOOGLE_EXTERNAL_ACCOUNT_IMPERSONATED_EMAIL` (only with impersonation), `GOOGLE_EXTERNAL_ACCOUNT_OUTPUT_FILE` (only when configured), `GOOGLE_EXTERNAL_ACCOUNT_TOKEN_TYPE` (always). |
| Executable response fields | `version` (only 1) and `success` always. Success: `token_type` (`urn:ietf:params:oauth:token-type:jwt`, `urn:ietf:params:oauth:token-type:id_token` or `urn:ietf:params:oauth:token-type:saml2`) plus `id_token` or `saml_response`; exit code 0. `expiration_time` is the subject token expiration time in seconds (unix epoch time), required only with an output file. Error: `code`, `message`; non-zero exit. |
| OIDC file source | A background process must keep refreshing the file before the token expires (hourly for one-hour tokens). Text or JSON. |
| OIDC URL source | A local server hosts a GET endpoint returning the token (text or JSON), optional headers such as `Metadata-Flavor=Google`. |
| X.509 | `--credential-cert-path`, `--credential-cert-private-key-path`, `--credential-cert-trust-chain-path`, optional `--credential-cert-configuration-output-file`. Without the last flag gcloud writes `certificate_config.json` to the default gcloud config path (`~/.config/gcloud/` on Linux and macOS, `%APPDATA%\gcloud\` on Windows) and the main config has `"use_default_certificate_config": true`; with it, the main config has a `"certificate_config_location"` field. Certificates must be renewed before expiry. |
| AWS IMDSv2 | Add `--enable-imdsv2` to `create-cred-config --aws` ("Adds the AWS IMDSv2 session token Url to the credential source to enforce the AWS IMDSv2 flow", gcloud help), or add `"imdsv2_session_token_url": "http://169.254.169.254/latest/api/token"` to `credential_source` in the AWS config file (README). |

## Notes

- Applies to google-auth-library 11.3.4 (npm), `node>=22`.
- With external identities and ADC in Node.js, the service account needs `roles/browser` and the Cloud Resource Manager API must be enabled on the project, because the library auto-discovers the project ID with the impersonated credential. Set `projectId` explicitly to avoid both.
- Security: the library does not validate `token_url`, `token_info_url` or `service_account_impersonation_url`. Do not use a configuration you did not generate with gcloud unless you verify those URLs point to a `googleapis.com` domain. Validate any externally sourced credential configuration (see `jwt-service-account.md`).
- Executable-sourced security: restrict access to the executable (it prints credentials to stdout) and make the configuration file non-modifiable. Prefer file-sourced or URL-sourced credentials unless they do not meet your needs. Never log the executable output or the subject token.
- ADC with AWS supports EC2 natively only; use a custom supplier for ECS, EKS, Fargate and similar (see `external-account-custom-suppliers.md`).
- `ExternalAccountClient.fromJSON` returns `BaseExternalAccountClient | null` (null "if the options provided do not correspond to an external account credential"). Its JSDoc warns: "This method does not validate the credential configuration. A security risk occurs when a credential configuration configured with malicious URLs is used." (`externalclient.d.ts`).
- Source inconsistency: the README says "The gcloud create-cred-config command will be updated to support this soon" for IMDSv2; GA gcloud (Google Cloud SDK 593.0.0) already has `--enable-imdsv2`.
- Azure setup requires the tenant to be configured for identity federation; the organization policy must allow federation from the provider.
- Corrected from the official docs: original lines `const res = await client.fetch(url);` (README "Using External Identities"; `client` is undefined there), `const client = ExternalAccountClient.fromJSON(jsonConfig);` followed directly by `client.scopes = [...]` (no null check), `projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/$POOL_ID/providers/$AWS_PROVIDER_ID \` and `--service-account $SERVICE_ACCOUNT_EMAIL \` (unquoted).
- Fragments: the `ExternalAccountClient.fromJSON` block (undefined `projectId`, top-level `await`) and the `GoogleAuth` blocks (no imports, top-level `await`).
- Dropped: the README's multi-line gcloud blocks that place `#` comment lines between `\` continuations (the shell would end the command at the comment); their flags are listed in the table above. Samples links in the README point to unpinned `main`.
