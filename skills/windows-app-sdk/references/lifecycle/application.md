# Application

The `Application` class encapsulates a Windows App SDK app and provides its entry point, app-scoped resources, and unhandled exception detection. The `Application` object is created by the Windows App SDK framework and is accessible from `Microsoft.UI.Xaml.Application.Current`.

## Signature / Usage

```csharp
private Window m_window;

protected override void OnLaunched(Microsoft.UI.Xaml.LaunchActivatedEventArgs args)
{
    m_window = new MainWindow();
    m_window.Activate();
}
```

## Options / Props

| Name | Type | Description |
|------|------|-------------|
| `Current` | `Application` (static property) | Gets the `Application` object for the current application. |
| `OnLaunched(LaunchActivatedEventArgs args)` | method | Invoked when the application is launched. Override this method to perform application initialization and to create/activate a new window. |
| `Resources` | `ResourceDictionary` | App-scoped resources such as styles, templates, and brushes. |
| `RequestedTheme` | `ApplicationTheme` | Light/dark theme preference for the app. |
| `UnhandledException` | event | Occurs when an exception can be handled by app code, as forwarded from a native-level Windows Runtime error. |
| `Exit()` | method | Shuts down the app. |

## Notes

- Package: `Microsoft.UI.Xaml` (Windows App SDK / WinUI 3). Distinct from the UWP `Windows.UI.Xaml.Application` class and from `System.Windows.Application` (WPF).
- Unlike the UWP `Application` class, `Microsoft.UI.Xaml.Application` has only one activation-related lifecycle method: `OnLaunched`. It has no `OnActivated`, `OnBackgroundActivated`, `Suspending`, `Resuming`, `EnteredBackground`, or `LeavingBackground` — Windows App SDK apps are not suspended/resumed like UWP apps.
- `OnLaunched` is responsible for creating and activating the app's main `Window`. Because there is no `Suspending` event, use the main window's `Closed` event to save app state and clean up resources instead.
- The `App` class (generated by project templates) derives from `Application`, associates itself with `App.xaml` via `InitializeComponent`, and is where you typically wire the `UnhandledException` handler or set `RequestedTheme` in the constructor; other initialization belongs in the `OnLaunched` override.
- To handle rich activation kinds (file, protocol, startup task, etc.) beyond a plain launch, use `AppInstance.GetCurrent().GetActivatedEventArgs()` from `Microsoft.Windows.AppLifecycle` rather than an `Application` override.
