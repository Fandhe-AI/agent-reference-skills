# agents

| Name | Description | Path |
| --- | --- | --- |
| Agent (Interface) | The `Agent` interface defines a contract for agents that can generate or stream AI-generated responses in response to prompts. Implementations such as `ToolLoopAgent` fulfill the same contract and integrate with all SDK APIs and utilities that expect an agent; you can supply custom agent classes or wrappers. | [agent.md](./agent.md) |
| Building Agents | The ToolLoopAgent provides a structured way to encapsulate LLM configuration, tools, and behavior into reusable components. It handles the agent loop for you, allowing the LLM to call tools multiple times in sequence to accomplish complex tasks. Define agents once and use them across your application. | [building-agents.md](./building-agents.md) |
| Configuring Call Options | Call options allow you to pass type-safe structured inputs to your agent. Use them to dynamically modify any agent setting based on the specific request. | [configuring-call-options.md](./configuring-call-options.md) |
| createAgentUIStreamResponse | Executes an `Agent`, runs its streaming output as a UI message stream, and returns an HTTP `Response` whose body is the live UI message output. Designed for API routes that deliver real-time agent results (chat endpoints, streaming tool-use). | [create-agent-ui-stream-response.md](./create-agent-ui-stream-response.md) |
| createAgentUIStream | Executes an `Agent`, consumes an array of UI messages, and streams the agent's output as UI message chunks via an async iterable. Suited to chat APIs, dashboards, or bots powered by agents in your own runtime. | [create-agent-ui-stream.md](./create-agent-ui-stream.md) |
| hasToolCall | Creates a stop condition that stops when any specified tool is called in the most recent step. Used with `stopWhen` in `generateText` and `streamText` (and agents). | [has-tool-call.md](./has-tool-call.md) |
| isStepCount | Creates a stop condition that stops when the number of completed steps equals a specified count. Used with `stopWhen` in `generateText`, `streamText` and agents to control when a tool-calling loop should stop. | [is-step-count.md](./is-step-count.md) |
| Loop Control | Control both the execution flow and the settings at each step of the agent loop via `stopWhen` (stopping conditions) and `prepareStep` (modify settings such as model, tools, messages between steps). | [loop-control.md](./loop-control.md) |
| isLoopFinished | Creates a stop condition that never triggers, letting the agent loop run until it naturally finishes (the model stops making tool calls). | [loop-finished.md](./loop-finished.md) |
| Memory | Memory lets your agent save information and recall it later. Without memory, every conversation starts fresh. With memory, your agent builds context over time, recalls previous interactions, and adapts to the user. | [memory.md](./memory.md) |
| Agents | Agents are **large language models (LLMs)** that use **tools** in a **loop** to accomplish tasks. | [overview.md](./overview.md) |
| pipeAgentUIStreamToResponse | Runs an `Agent` and streams the resulting UI message output directly to a Node.js `ServerResponse`. Intended for real-time streaming endpoints in Node.js-based frameworks like Express, Hono, or custom Node servers. | [pipe-agent-ui-stream-to-response.md](./pipe-agent-ui-stream-to-response.md) |
| Policy-Based Tool Approvals | `@ai-sdk/policy-opa` moves tool approval rules out of code and into Open Policy Agent (OPA) policies written in `.rego`. It sits entirely on top of the public `toolApproval` callback; the wire flow (`tool-approval-request` / `tool-approval-response`) is unchanged. | [policy-tool-approvals.md](./policy-tool-approvals.md) |
| Experimental_SandboxSession | Describes an execution environment that tools can use to run commands. Pass it via the `experimental_sandbox` option to `generateText`, `streamText`, `ToolLoopAgent.generate`, `ToolLoopAgent.stream`, or agent UI stream helpers to make it available to tool description functions and tool execution. | [sandbox.md](./sandbox.md) |
| Subagents | A subagent is an agent that a parent agent can invoke. The parent delegates work via a tool, and the subagent executes autonomously before returning a result. | [subagents.md](./subagents.md) |
| Tool Approvals | By default, tools with an `execute` function run automatically when the model calls them. Use `toolApproval` on `ToolLoopAgent` to review, approve, or deny selected tool calls before they execute. | [tool-approvals.md](./tool-approvals.md) |
| ToolLoopAgent | Creates a reusable AI agent capable of generating text, streaming responses, and using tools over multiple steps (a reasoning-and-acting loop). Unlike single-step calls like `generateText()`, an agent can iteratively invoke tools, collect tool results, and decide next actions until completion or user approval is required. | [tool-loop-agent.md](./tool-loop-agent.md) |
| Workflow Patterns | Combine the building blocks from the agents overview with these patterns to add structure and reliability to your agents: Sequential Processing, Parallel Processing, Evaluation/Feedback Loops, Orchestration, Routing. | [workflows.md](./workflows.md) |
