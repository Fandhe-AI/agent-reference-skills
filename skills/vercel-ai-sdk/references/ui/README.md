|------|-------------|------|

| createUIMessageStreamResponse | Creates a `Response` object that streams UI messages to the client. | [create-ui-message-stream-response.md](./create-ui-message-stream-response.md) |
| createUIMessageStream | Creates a readable stream for UI messages with message merging, error handling, and finish callbacks. Returns `ReadableStream<UIMessageChunk>`. | [create-ui-message-stream.md](./create-ui-message-stream.md) |

| Error Handling and warnings | Warnings surface unsupported features, compatibility modes, and deprecations; each AI SDK UI hook also returns an `error` object and accepts an `onError` callback. | [error-handling.md](./error-handling.md) |
| InferUITool | Type helper that infers the input and output types of a single tool, for type-safe tool inputs and outputs in `UIMessage`s. | [infer-ui-tool.md](./infer-ui-tool.md) |

| experimental_MCPAppRenderer | Renders an MCP App for an AI SDK tool UI part. Detects MCP App metadata on the tool part, loads the app resource, renders the app in a sandbox proxy iframe, and bridges MCP Apps JSON-RPC messages between the iframe and your host application. For tool parts without MCP App metadata, it renders `fallback`. | [mcp-app-renderer.md](./mcp-app-renderer.md) |
| Message Metadata | Message metadata attaches custom information (timestamps, model information, token usage, user context) at the message level. It differs from data parts, which are part of the message content. | [message-metadata.md](./message-metadata.md) |
| AI SDK UI | AI SDK UI is a framework-agnostic toolkit for building interactive chat, completion, and assistant applications. It manages chat streams and UI updates on the frontend through three main hooks: `useChat`, `useCompletion`, and `useObject`. | [overview.md](./overview.md) |
| pipeUIMessageStreamToResponse | Pipes streaming UI message data to a Node.js `ServerResponse` object. Returns a `Promise<void>` that resolves when the stream has been written to the response and rejects when reading or writing the stream fails. | [pipe-ui-message-stream-to-response.md](./pipe-ui-message-stream-to-response.md) |
| pruneMessages | Prunes or filters an array of `ModelMessage` objects: reduces context (saves tokens), removes intermediate reasoning, or trims tool calls and empty messages before sending to an LLM. | [prune-messages.md](./prune-messages.md) |
| readUIMessageStream | Transforms a stream of `UIMessageChunk`s into an `AsyncIterableStream` of `UIMessage`s. Useful outside Chat use cases, e.g. terminal UIs, custom stream consumption on the client, or RSC. | [read-ui-message-stream.md](./read-ui-message-stream.md) |
| Reading UI Message Streams | `UIMessage` streams are useful outside chat: terminal UIs, custom client-side stream processing, or React Server Components. `readUIMessageStream` transforms a stream of `UIMessageChunk` objects into an `AsyncIterableStream` of `UIMessage` objects as they are constructed. | [reading-ui-message-streams.md](./reading-ui-message-streams.md) |
| safeValidateUIMessages | Async function that validates UI messages like `validateUIMessages`, but instead of throwing it returns an object with a `success` key and either `data` or `error`. | [safe-validate-ui-messages.md](./safe-validate-ui-messages.md) |
| Stream Protocols | AI SDK UI functions such as `useChat` and `useCompletion` support text streams and data streams. The protocol defines how data is streamed to the frontend over HTTP, so custom backends (for example in Python) can provide compatible endpoints. | [stream-protocol.md](./stream-protocol.md) |
| Transport | The `useChat` transport system controls how messages are sent to your API endpoints and how responses are processed. Useful for WebSockets, custom authentication patterns, or specialized backend integrations. | [transport.md](./transport.md) |
| UIMessage | `UIMessage` is the source of truth for application state: the complete message history including metadata, data parts, and all contextual information. In contrast to `ModelMessage` (state passed to the model), it holds the full state needed for UI rendering and client-side functionality. | [ui-message.md](./ui-message.md) |
| useChat | Creates a conversational user interface for a chatbot: streams chat messages from your AI provider, manages chat state, and updates the UI as new messages are received. | [use-chat.md](./use-chat.md) |
| useCompletion | Creates text completion capabilities: streams text completions from your AI provider, manages the state for input, and updates the UI as new content is received. | [use-completion.md](./use-completion.md) |
| useObject | Consumes text streams that represent a JSON object and parses them into a complete object based on a schema. Use it together with `streamText` and `Output.object()` in the backend. | [use-object.md](./use-object.md) |
| experimental_useRealtime | Creates a browser-side realtime session for bidirectional audio and text conversations with a realtime provider model. Supports token-based provider WebSockets, application-owned WebSocket relays, and optional WebRTC where the model declares support. Turn-based conversation messages use `UIMessage[]`; continuous transcript fragments remain in `session`. | [use-realtime.md](./use-realtime.md) |
| validateUIMessages | Async function that validates UI messages against schemas for metadata, data parts, and tools, ensuring type safety and data integrity before processing or rendering. It throws on invalid messages. | [validate-ui-messages.md](./validate-ui-messages.md) |
| WebSocketChatTransport | A `ChatTransport` implementation that sends chat requests and receives `UIMessageChunk` streams over one persistent WebSocket connection. | [websocket-chat-transport.md](./websocket-chat-transport.md) |
