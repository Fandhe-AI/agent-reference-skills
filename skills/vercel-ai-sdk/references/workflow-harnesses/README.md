# workflow-harnesses

| Name | Description | Path |
|------|-------------|------|
| Claude Code Harness | The Claude Code harness adapter connects `HarnessAgent` to Claude Code through `@anthropic-ai/claude-agent-sdk`. It runs a bridge inside the sandbox and streams Claude Code events back to the host over a sandbox-exposed WebSocket. | [claude-code-harness.md](./claude-code-harness.md) |
| Codex Harness | The Codex harness adapter connects `HarnessAgent` to the Codex app-server. It runs a bridge inside the sandbox and streams Codex thread events back to the host over a sandbox-exposed WebSocket. | [codex-harness.md](./codex-harness.md) |
| Harness Adapters | Harness adapters connect `HarnessAgent` to a specific agent runtime. They are the harness equivalent of AI SDK model providers: each wraps one runtime and normalizes sessions, stream events, tools, usage, lifecycle state, and configuration into the harness contract. | [harness-adapters.md](./harness-adapters.md) |
| HarnessAgent | `HarnessAgent` is an AI SDK `Agent` implementation backed by a harness adapter. `generate()` and `stream()` return AI SDK-compatible results while a preconfigured harness powers them. | [harness-agent.md](./harness-agent.md) |
| AI SDK Harnesses (providers index) | AI SDK harness adapters connect `HarnessAgent` to established agent runtimes. They are separate from model providers, but expose AI SDK-compatible stream and response primitives. | [harness-providers.md](./harness-providers.md) |
| Harness Skills | Skills are reusable instruction bundles (project conventions, workflow guidance, domain procedures) discoverable by the underlying harness runtime. Configure them for a `HarnessAgent` or replace them between completed turns. | [harness-skills.md](./harness-skills.md) |
| Harnesses with Terminal UI | `@ai-sdk/tui` can render harness streams, tool calls, reasoning sections, and approval prompts in a terminal. Because `HarnessAgent` requires a session for `generate` and `stream`, wrap it with a small `AgentTUIAgent` adapter that injects one session for the lifetime of the terminal UI. | [harness-terminal-ui.md](./harness-terminal-ui.md) |
| Harness Tools | Harnesses have three tool surfaces: built-in tools of the runtime (file reads, edits, shell, web search), AI SDK tools passed to `HarnessAgent` with `tools`, and external MCP tools configured through the adapter's `mcpServers` setting. | [harness-tools.md](./harness-tools.md) |
| Harnesses with AI SDK UI | Harness streams are compatible with AI SDK UI message streams: use `useChat()` on the client and stream `HarnessAgent` output from a server route. The key difference from model-based chat routes is session management; resume or create a `HarnessAgentSession` for the chat id instead of replaying the whole UI message history into a model. | [harness-ui.md](./harness-ui.md) |
| AI SDK Harnesses Overview | The AI SDK harness abstraction runs established agent harnesses (Claude Code, Codex, Pi, ...) through a single AI SDK surface. A harness is a complete agent runtime owning workspace access, built-in coding tools, native session state, compaction, permission flows, and runtime-specific configuration. | [harnesses-overview.md](./harnesses-overview.md) |
| runAgentTUI | Runs a local agent or chat transport in an interactive terminal UI. It reads prompts, streams assistant responses, renders markdown, displays tool and reasoning sections, and handles manual tool approvals. Runs until the user exits with `Esc` or `Ctrl+C`. | [run-agent-tui.md](./run-agent-tui.md) |
| Terminal UI | The `@ai-sdk/tui` package runs a local `ToolLoopAgent`, or connects to a remote agent through a `ChatTransport`, in an interactive terminal interface. It handles prompt input, streamed assistant responses, markdown rendering, tool cards, reasoning sections, scrolling, and tool approval prompts. | [terminal-ui.md](./terminal-ui.md) |
| WorkflowAgent (guide) | The `WorkflowAgent` from `@ai-sdk/workflow` builds durable, resumable agents that run inside a workflow. It provides the same agent loop as `ToolLoopAgent`, plus automatic state persistence, tool schema serialization, and tool approval flows that survive workflow step boundaries. | [workflow-agent-guide.md](./workflow-agent-guide.md) |
| WorkflowAgent | Creates a durable, resumable AI agent for use inside a workflow. `WorkflowAgent` handles the agent loop, tool schema serialization across workflow step boundaries, and built-in tool approval flows. | [workflow-agent.md](./workflow-agent.md) |
| WorkflowChatTransport | A `ChatTransport` implementation for `useChat` that enables automatic stream reconnection for workflow-based chat apps. It posts messages to a chat endpoint, extracts the `x-workflow-run-id` response header, and reconnects to a `/{runId}/stream` endpoint on interruption (network failures, page refreshes, function timeouts). | [workflow-chat-transport.md](./workflow-chat-transport.md) |
| generateVideo | Generates videos durably inside a workflow. The helper starts an asynchronous video generation job with a Workflow webhook URL, suspends the workflow until the provider sends a terminal notification, and then retrieves the completed result with one status request. | [workflow-generate-video.md](./workflow-generate-video.md) |
| Workflow Utilities | `@ai-sdk/workflow-harness` provides helpers for running `HarnessAgent` turns inside a workflow: a serializable state machine and runners for time-sliced and semantic agent step turns. You call the runner from your own `'use workflow'` and `'use step'` functions. | [workflow-utilities.md](./workflow-utilities.md) |
