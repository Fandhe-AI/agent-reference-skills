# Error Log Management

Driver and Runtime API for capturing and inspecting CUDA-internal error/warning log messages, either by directing them to a file/stream via the `CUDA_LOG_FILE` environment variable or by registering a callback (`cuLogsRegisterCallback` / `cudaLogsRegisterCallback`) to receive them programmatically. Both interfaces use the same underlying log buffer.

## Signature / Usage

```c
// Driver API callback type and registration (CPG 13.4)
typedef void (CUDA_CB *CUlogsCallback)(
    void *data, CUlogLevel logLevel, char *message, size_t length);
CUresult CUDAAPI cuLogsRegisterCallback(
    CUlogsCallback callbackFunc, void *userData, CUlogsCallbackHandle *callback_out);

// Runtime API counterpart (CPG 13.4)
typedef void (CUDART_CB *cudaLogsCallback_t)(
    void *data, cudaLogLevel logLevel, char *message, size_t length);
cudaError_t CUDARTAPI cudaLogsRegisterCallback(
    cudaLogsCallback_t callbackFunc, void *userData, cudaLogsCallbackHandle *callback_out);
```

```bash
# Alternative activation without code changes
export CUDA_LOG_FILE=stderr
```

## Options / Props

| Name | Description |
| --- | --- |
| `CUDA_LOG_FILE` | Environment variable set to `stdout`, `stderr`, or a path to a writable file; CUDA writes each generated log message to it. Not validated until a message is generated. |
| `cuLogsRegisterCallback` / `cuLogsUnregisterCallback` | Driver API: register/unregister a callback invoked for each log entry with `(data, logLevel, message, length)`. `callback_out` is optional but must be retained to unregister. |
| `cudaLogsRegisterCallback` / `cudaLogsUnregisterCallback` | Runtime API equivalents (new in CPG 13.4). |
| `cuLogsCurrent` / `cudaLogsCurrent` | Sets an iterator to the current end of the log buffer; a later dump with it returns only subsequently generated messages. `flags` must be 0. |
| `cuLogsDumpToFile` / `cudaLogsDumpToFile` | Export buffered log entries to a file. `flags` must be 0. |
| `cuLogsDumpToMemory` / `cudaLogsDumpToMemory` | Export buffered log entries to an in-memory buffer; `size` in = capacity, out = bytes written. `flags` must be 0. |
| `CU_LOG_LEVEL_ERROR` / `CU_LOG_LEVEL_WARNING` (Driver), `cudaLogLevelError` / `cudaLogLevelWarning` (Runtime) | Callback log levels; shown as `E` and `W` in formatted output. |
| `cuGetErrorString` | Converts a `CUresult` error code into a generic human-readable string (distinct from the log system itself). |

## Notes

- Log entries are formatted as `[Time][TID][Source][Severity] Message`, e.g. `[22:21:][25642][CUDA][E] buffer cannot be NULL` followed by `[22:21:][25642][CUDA][E] Returning 1 (CUDA_ERROR_INVALID_VALUE) from cuLogsDumpToMemory`. The earlier `[API Entry Point]` field is gone; the "Returning N (...) from fn" line identifies the API instead.
- Availability (changed in CPG 13.4): error log management is available through both the Driver and Runtime APIs. The Runtime interface operates on messages generated by both the Runtime and Driver APIs. The older statement that it was Driver-only is no longer in the guide.
- Dump behavior: a null iterator dumps all retained entries; a supplied iterator starts at that position and is advanced to the current end after a successful dump. The buffer retains at most 100 entries; when requested messages were overwritten, a truncation notice is added and the remaining entries are returned.
- `cuLogsDumpToMemory` / `cudaLogsDumpToMemory`: the buffer is null-terminated and entries are newline-separated; a 25,600-byte buffer is sufficient for all retained log data; on success `size` is the number of bytes written excluding the terminating null; with no messages to dump the call succeeds and sets `size` to 0; if only some messages fit, a truncation notice is prepended, the oldest messages that do not fit are omitted, and the most recent message is kept; if the buffer cannot hold any message, the call returns `CUDA_ERROR_INVALID_VALUE` / `cudaErrorInvalidValue` and sets `size` to 0.
- The callback receives message text and explicit byte length, without the timestamp / thread ID / source / severity prefix added to file and dump output. Do not rely on a particular callback thread or invocation timing unless the API reference guarantees it.
- Not all CUDA APIs generate descriptive messages yet; messages are not localized (US English).
