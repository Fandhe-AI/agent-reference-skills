# Move to C++/WinRT from C#

A catalog of the technical details involved in porting a C# project's source code to its equivalent in C++/WinRT, grouped into language-projection changes, language-syntax changes, language-procedure changes, and C++/WinRT-specific porting tasks (IDL authoring, boxing/unboxing, collections, events).

## Signature / Usage

```csharp
// C#
private async void SampleButton_Tapped(object sender, Microsoft.UI.Xaml.Input.TappedRoutedEventArgs e) { ... }
```

```cppwinrt
// C++/WinRT .h
fire_and_forget SampleButton_Tapped(IInspectable const&, RoutedEventArgs const&);
// C++/WinRT .cpp
fire_and_forget OcrFileImage::SampleButton_Tapped(IInspectable const&, RoutedEventArgs const&) {...}
```

## Options / Props

| C# | C++/WinRT | Notes |
|------|-------------|------|
| `object`, `System.Object` | `Windows::Foundation::IInspectable` | Untyped object. |
| `collection.Count` | `collection.Size()` | Size of a collection. |
| `IList<T>` + `Add` | `IVector<T>` + `Append` (or `std::vector` + `push_back`) | Typical collection type. |
| `IReadOnlyList<T>` | `IVectorView<T>` | Read-only collection type. |
| `IDictionary<K, V>` | `IMap<K, V>` | Associative container; `map[k] = v` / `v = map[k]` / `ContainsKey` become `Insert` / `Lookup` (throws if absent) / `HasKey`. |
| `x = v[i]; v[i] = x;` | `x = v.GetAt(i); v.SetAt(i, x);` | Vector member access. |
| `myObject.EventName += Handler;` | `token = myObject.EventName({ get_weak(), &Class::Handler });` | Register event handler as class member. |
| `myObject.EventName -= Handler;` | `myObject.EventName(token);` | Revoke by passing the token back. |
| `async Task ...` | `IAsyncAction ...` | Async action. |
| `async Task<T> ...` | `IAsyncOperation<T> ...` | Async operation. |
| `async void ...` | `winrt::fire_and_forget ...` | Fire-and-forget method. |
| `await ...` | `co_await ...` | Cooperative wait. |
| `null` | `nullptr` | |
| `typeof(MyType)` | `winrt::xaml_typename<MyType>()` | Obtain a type object. |
| `string`, `System.String` | `winrt::hstring` | |
| `"a string literal"` | `L"a string literal"` | |
| `@"verbatim string"` | `LR"(raw string literal)"` | |
| `var` | `auto` | |
| `catch (Exception ex)` / `ex.Message` | `catch (winrt::hresult_error const& ex)` / `ex.message()` | |
| `myObject.MyProperty` / `myObject.MyProperty = value;` | `myObject.MyProperty()` / `myObject.MyProperty(value);` | Get/set become function calls. |
| `myObject.ToString()` | `winrt::to_hstring(myObject)` | Enum overloads must be user-provided. |
| `(MyType)v` | `v.as<MyType>()` | Throws on failure. |
| `v as MyType` | `v.try_as<MyType>()` | Null on failure. |
| `(Value)o` | `unbox_value<Value>(o)` | Throws (crashes in C++/WinRT) if unboxing fails. |
| `o as Value? ?? fallback` | `unbox_value_or<Value>(o, fallback)` | Returns fallback if unboxing fails. |
| `o = 1;` (auto-boxes) | `o = box_value(1);` | Boxing is explicit. |
| `StringBuilder` + `Append` | `std::wostringstream` + `<<` | String-building; access result via `.str()`. |

## Notes

- Four categories of change: **language projection** (e.g. `IReadOnlyList<T>` back to `IVectorView<T>`, `+=` event syntax back to explicit registration), **language syntax** (mechanical symbol swaps, `.` to `::`), **language procedure** (e.g. `StringBuilder` to `std::wostringstream`), and **C++/WinRT-specific tasks** (e.g. authoring an `.idl` file, which C# does implicitly).
- Boxing a Windows Runtime string differs subtly from C#: a boxed null `HSTRING` becomes `hstring{}` (not identical to `""` conceptually in C#, but *is* identical to `""` in C++/WinRT); `s = hstring{}; s.size() == 0` is valid, whereas in C# `s = null; s.Length` raises `NullReferenceException`.
- A runtime class must be declared in IDL (`.idl`); after editing IDL and rebuilding, compare the generated stub files (`.h`/`.cpp`) against the current C# port and use the stub's exact function signatures to minimize build errors.
- To derive from a runtime class as a base class, the base must be declared `unsealed` in IDL (composability isn't automatic like in C#); the derived implementation type's header must `#include` the base class header **before** the derived class's autogenerated `.g.h` header, or you get "Illegal use of this type as an expression".
- All entities consumed via the XAML `{x:Bind}` markup extension must be exposed publicly in IDL (unlike C#, where private members/named elements are directly bindable); a `bool` bound this way shows as `Windows.Foundation.IReference<Boolean>` rather than `true`/`false`.
- It's good practice for the first line of an async method in a C++/WinRT runtime class to be `auto lifetime = get_strong();` to keep `this` alive across suspension.
- A companion case-study topic ("Porting the Clipboard sample to C++/WinRT from C#") ports a full UWP sample method-by-method and is referenced throughout this catalog for worked examples.
