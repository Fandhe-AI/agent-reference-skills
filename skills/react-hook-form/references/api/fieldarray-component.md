# FieldArray

Component based on the `useFieldArray` hook (Since 7.81.0), for working with dynamic field arrays as a headless/controlled component. All props are the same as `useFieldArray`, plus a `render` prop that receives the hook's return value.

## Signature / Usage

```tsx
import { useForm, FieldArray } from "react-hook-form"

type FormValues = {
  test: { value: string }[]
}

export default function App() {
  const { control, register, handleSubmit } = useForm<FormValues>({
    defaultValues: {
      test: [{ value: "" }],
    },
  })

  return (
    <form onSubmit={handleSubmit((data) => console.log(data))}>
      <FieldArray
        control={control}
        name="test"
        render={({ fields, append, remove }) => (
          <>
            {fields.map((field, index) => (
              <div key={field.id}>
                <input {...register(`test.${index}.value`)} />
                <button type="button" onClick={() => remove(index)}>
                  Delete
                </button>
              </div>
            ))}
            <button type="button" onClick={() => append({ value: "" })}>
              Append
            </button>
          </>
        )}
      />
      <input type="submit" />
    </form>
  )
}
```

## Options / Props

`FieldArray: FieldArrayProps`

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `render` | `Function` | Yes | Render prop receiving the object `useFieldArray` returns (`fields`, `append`, `prepend`, `insert`, `remove`, `swap`, `move`, `update`, `replace`) and returning a React element. |
| `name` | `string` | Yes | Name of the field array. Dynamic names are not supported. |
| `control` | `Object` | No | `control` object from `useForm`. Optional with `FormProvider`. |
| `shouldUnregister` | `boolean` | No | Whether the Field Array is unregistered after unmount. The official Rules state `shouldUnregister: true` is not supported (newly added fields are unregistered on re-render and their values lost); do not set it to `true`. |
| `disabled` | `boolean` | No | Disables the entire field array: `fields` remains populated, every entry's `disabled` is `true`, mutation methods become no-ops. |
| `keyName` | `string = "id"` | No | Attribute name of the autogenerated identifier used as `key`. No longer required and is removed in v8, where rows always use `key` (see [v8 migration notes](https://react-hook-form.com/migrate-v7-to-v8#useFieldArray)). |
| `rules` | `Object` | No | Same validation rules as `register`: `required`, `minLength`, `maxLength`, `validate`. On error, `root` is appended at `formState.errors?.<name>?.root`. Built-in validation only. |

The object passed to `render` is identical to what `useFieldArray` returns.

## Notes

- The same rules as `useFieldArray` apply: `field.id` (not `index`) must be the component `key`, and `shouldUnregister: true` is not supported. In v8, use `field.key` instead of `field.id`.
- `render` is called on every render, so keep it free of side effects.

- Source: https://react-hook-form.com/docs/usefieldarray/fieldarray (documentation master c0511c9, fetched 2026-11-14)

### Tips

- Use `FieldArray` when you cannot call a hook, for example when a field array is rendered conditionally or inside a loop. Hooks cannot be called conditionally, but components can be rendered conditionally.
- For nested arrays, render a `FieldArray` inside another one's `render`, and build the name from the parent index:

  ```javascript
  <FieldArray
    control={control}
    name="sections"
    render={({ fields }) =>
      fields.map((section, index) => (
        <FieldArray
          key={section.id}
          control={control}
          name={`sections.${index}.questions`}
          render={({ fields: questions, append }) => (
            <Questions fields={questions} append={append} />
          )}
        />
      ))
    }
  />
  ```

- Errors from `rules` are stored at `errors.<name>.root`, for example `errors.sections?.root?.message`. Show them next to the list, not next to one row.

### Troubleshooting

#### Rows show the wrong values after removing or moving an item

- Why: The rendered rows use the array index as their React key. After an item moves, React reuses the DOM for a different field, so inputs and their form state no longer line up.
- Fix: Use the generated field identifier as the key. In v8, use `field.key` instead of `field.id`.

```javascript
fields.map((field, index) => (
  <input key={field.id} {...register(`items.${index}.name`)} />
))
```

#### A newly appended row has missing or uncontrolled fields

- Why: `append`, `prepend`, `insert`, and `update` require complete row objects. Passing `{}` or a partial object leaves fields without initial values.
- Fix: Pass every field in the row, including empty defaults. Use [`setValue`](./useform-setvalue.md) when you only need to change one property of an existing row.

```javascript
append({ name: "", quantity: 1 })
```
