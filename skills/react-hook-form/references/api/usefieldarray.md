# useFieldArray

Custom hook for working with Field Arrays (dynamic forms), providing better user experience and performance.

## Signature / Usage

```tsx
import { useForm, useFieldArray } from "react-hook-form"

type FormValues = {
  test: { firstName: string; lastName: string }[]
}

function App() {
  const { register, control, handleSubmit } = useForm<FormValues>()
  const { fields, append, remove } = useFieldArray({
    control, // optional if you are using FormProvider
    name: "test", // unique name for your Field Array
  })

  return (
    <form onSubmit={handleSubmit((data) => console.log(data))}>
      <ul>
        {fields.map((item, index) => (
          <li key={item.id}>
            <input {...register(`test.${index}.firstName`)} />
            <button type="button" onClick={() => remove(index)}>
              Delete
            </button>
          </li>
        ))}
      </ul>
      <button
        type="button"
        onClick={() => append({ firstName: "bill", lastName: "luo" })}
      >
        append
      </button>
      <input type="submit" />
    </form>
  )
}
```

## Options / Props

`useFieldArray: UseFieldArrayProps`

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `name` | `string` | Yes | Name of the field array. Dynamic names are not supported. |
| `control` | `Object` | No | `control` object from `useForm`. Optional with `FormProvider`. |
| `shouldUnregister` | `boolean` | No | Whether the Field Array is unregistered after unmounting. |
| `disabled` | `boolean` | No | Since 7.79.0. Disables the entire field array: `fields` remains populated but every entry's `disabled` property is `true`, all mutation methods become no-ops, and internal subscriptions are not set up. |
| `keyName` | `string = "id"` | No | Attribute name of the autogenerated identifier used as `key`. An existing `id` property in field objects is overwritten unless a custom `keyName` is set. No longer required and will be removed in the next major version. |
| `rules` | `Object` | No | Since 7.34.0. Same validation rules as `register`: `required`, `minLength`, `maxLength`, `validate`. On error, `root` is appended at `formState.errors?.<name>?.root` (type `FieldError`). Built-in validation only. |

Return:

| Name | Type | Description |
|------|------|-------------|
| `fields` | `(object & { id: string })[]` | Entries containing the `defaultValue` and `key` for each row. Since 7.80.0, with hook-level `disabled`, every entry's `disabled` reflects it, but it is not forwarded to the registered input automatically. |
| `append` | `(obj: object \| object[], focusOptions) => void` | Append to the end and focus. Data is required and cannot be partial. `focusOptions`: `{ shouldFocus?: boolean = true, focusIndex?: number, focusName?: string }` (since 7.0.0). |
| `prepend` | `(obj: object \| object[], focusOptions) => void` | Prepend to the start and focus. Data is required and cannot be partial. |
| `insert` | `(index: number, value: object \| object[], focusOptions) => void` | Insert at a position and focus. Data is required and cannot be partial. |
| `swap` | `(from: number, to: number) => void` | Swap the positions of inputs. |
| `move` | `(from: number, to: number) => void` | Move an input to another position. |
| `update` | `(index: number, obj: object) => void` | Since 7.11.0. Update at a position; updated fields are unmounted and remounted (use `setValue` to avoid this). Data is required and cannot be partial. |
| `replace` | `(obj: object[]) => void` | Since 7.15.0. Replace the entire field array's values. |
| `remove` | `(index?: number \| number[]) => void` | Remove at a position, or remove all if no index is provided. |

## Notes

- Use `field.id` (not `index`) as the component `key`: `fields.map((field, index) => <input key={field.id} ... />)`.
- Do not stack actions in the same handler (e.g. `append(...)` then `remove(0)`); run the second action after the next render (e.g. in `useEffect`).
- Do not use multiple `useFieldArray` instances with the same `name`. Each input name must be unique; for checkbox/radio with the same name use `useController` or `Controller`.
- Flat field arrays are not supported: each entry must be an object (`{ test: [{ value: 'a' }] }`, not `{ test: ['a', 'b'] }`).
- `shouldUnregister: true` is not supported: newly added fields are unregistered on re-render and their values lost.
- There is no per-entry `disabled`; it mirrors the hook-level `disabled`. Wire it up yourself: `<input key={field.id} disabled={field.disabled} {...register(`test.${index}.value`)} />`.
- `append`/`prepend`/`insert`/`update` cannot take empty or `{}` objects; supply all inputs' default values: `append({ firstName: "bill", lastName: "luo" })`.
- TypeScript: cast input names as const (`` register(`test.${index}.test` as const) ``); circular references are not supported; for nested field arrays cast the name: `` useFieldArray({ name: `test.${index}.keyValue` as 'test.0.keyValue' }) ``.
- Focus options example: `prepend({ value: "" }, { focusIndex: 1 })`, `append({ value: "" }, { focusName: "test.0.value" })`.
- Controlled field array: merge `watch("fieldArray")` into `fields` (`{ ...field, ...watchFieldArray[index] }`).
