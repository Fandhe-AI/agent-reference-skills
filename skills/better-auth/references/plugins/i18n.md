# i18n

The i18n (internationalization) plugin enables translation of error messages returned by Better Auth based on the user's locale. Better Auth provides English messages by default, so only translations for additional languages are needed.

## Signature / Usage

### Installation

```bash
npm install @better-auth/i18n
```

### Setup (server side)

```typescript
import { betterAuth } from "better-auth"
import { i18n } from "@better-auth/i18n"

export const auth = betterAuth({
    plugins: [
        i18n({
            translations: {
                fr: {
                    USER_NOT_FOUND: "Utilisateur non trouvé",
                    INVALID_EMAIL_OR_PASSWORD: "Email ou mot de passe invalide",
                    INVALID_PASSWORD: "Mot de passe invalide",
                },
                de: {
                    USER_NOT_FOUND: "Benutzer nicht gefunden",
                    INVALID_EMAIL_OR_PASSWORD: "Ungültige E-Mail oder Passwort",
                    INVALID_PASSWORD: "Ungültiges Passwort",
                },
            },
        }),
    ],
})
```

Error response format:

```json
{
    "code": "INVALID_EMAIL_OR_PASSWORD",
    "message": "Email ou mot de passe invalide",
    "originalMessage": "Invalid email or password"
}
```

### Locale detection strategy

Default (header-based) — parses the `Accept-Language` HTTP header with quality values:

```
Accept-Language: fr-CA, fr;q=0.9, en;q=0.8
```

Cookie-based:

```typescript
i18n({
    translations: { /* ... */ },
    detection: ["cookie", "header"],
    localeCookie: "lang",  // default: "locale"
})
```

Session-based:

```typescript
export const auth = betterAuth({
    user: {
        additionalFields: {
            locale: { type: "string", required: false },
        },
    },
    plugins: [
        i18n({
            translations: { /* ... */ },
            detection: ["session", "header"],
            userLocaleField: "locale",  // default: "locale"
        }),
    ],
})
```

Custom detection callback:

```typescript
i18n({
    translations: { /* ... */ },
    detection: ["callback", "header"],
    getLocale: (ctx) => {
        if (!ctx.request) return null
        const url = new URL(ctx.request.url)
        return url.searchParams.get("lang")
    },
})
```

## Options / Props

| Option | Type | Default | Description |
|---|---|---|---|
| `translations` | `Record<string, Record<string, string>>` | required | Translation dictionary keyed by locale code |
| `defaultLocale` | string | `"en"` or the first locale | Fallback locale when detection fails |
| `detection` | `Array<"header" \| "cookie" \| "session" \| "callback">` | `["header"]` | Detection strategies in priority order |
| `localeCookie` | string | `"locale"` | Cookie name for cookie-based detection |
| `userLocaleField` | string | `"locale"` | User object field for session-based detection |
| `getLocale` | `(ctx) => string \| null \| Promise<string \| null>` | N/A | Custom locale detection function |

## Notes

- Falls back to the built-in English messages when no translation is available
- Unsupported locales fall back to English
- English messages are used when no locale is detected
- Non-error responses are unaffected
- `ctx.request` in custom callbacks may be undefined for non-HTTP calls, so null-safety checks are required

### Supported error codes

- `USER_NOT_FOUND`
- `INVALID_EMAIL_OR_PASSWORD`
- `INVALID_PASSWORD`
- `CREDENTIAL_ACCOUNT_NOT_FOUND`
- `EMAIL_NOT_VERIFIED`
- `SESSION_EXPIRED`

See the error code reference documentation for the complete list.
