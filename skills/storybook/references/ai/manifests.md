# Manifests (components / docs manifest)

Manifests are JSON objects describing your Storybook's contents in a form AI agents can use. They are generated automatically from CSF and MDX files. There are two types: components and docs.

## Signature / Usage

Enable the components manifest in `.storybook/main.ts`:

```ts
import type { StorybookConfig } from '@storybook/your-framework';

const config: StorybookConfig = {
  framework: '@storybook/your-framework',
  stories: ['../src/**/*.mdx', '../src/**/*.stories.@(js|jsx|mjs|ts|tsx)'],
  features: {
    componentsManifest: true,
  },
};

export default config;
```

Vue (`@storybook/vue3-vite`) needs both `componentsManifest: true` and `experimentalDocgenServer: true`.

Raw JSON endpoints (dev server or built Storybook):

- `http://localhost:6006/manifests/components.json`
- `http://localhost:6006/manifests/docs.json`
- Debugger: `http://localhost:6006/manifests/components.html`

Exclude a story, a component, or an MDX docs page by removing the `manifest` tag:

```ts
export const ForInstructionOnly = {
  tags: ['!manifest'], // exclude this story from the manifests
};
```

```mdx
import { Meta } from '@storybook/addon-docs/blocks';

<Meta title="Doc for Humans Only" tags={['!manifest']} />
```

## Notes

- Preview feature; the manifest schema is not stable and should not be considered a public API.
- Generated by the React frameworks, `@storybook/angular-vite`, and `@storybook/vue3-vite`. Other frameworks generate no components manifest; the docs manifest is generated for every framework, but the docs toolset stays unavailable without a components manifest. The development and testing toolsets work regardless.
- Components manifest: from static analysis of CSF files plus prop type extraction.
  - React: uses the `reactDocgen` option (`react-docgen` by default); `react-docgen-typescript` is recommended for more accurate props, `react-docgen` is faster but less detailed.
  - With `experimentalDocgenServer`, extraction runs server-side via React Component Meta, and manifests use a ref-based format with per-component JSON snapshots when combined with `componentsManifest`.
  - Angular (`@storybook/angular-vite`): API is delivered as a Markdown description (inputs and outputs listed separately with types, defaults, JSDoc). The Webpack-based `@storybook/angular` generates no components manifest.
- JSDoc comments on components and props enrich the manifest. In a Vue `<script setup>` SFC, attach the component docblock to a `defineOptions()` call; a docblock on its own at the top of the block is not picked up.
- If a story file declares `subcomponents`, the manifest includes a `subcomponents` object for that component.
- With `experimentalDocgenServer` enabled, the dev server returns 404 for both JSON routes (manifest assembled on demand); read it from a built Storybook or use the debugger. This affects `@storybook/angular-vite` and `@storybook/vue3-vite` always, and React projects that opt in.
- The debugger shows both manifests plus errors/warnings (filterable). It reads prop tables from React docgen data only, so Angular and Vue components are listed without prop types.
- By default all stories and independent docs pages carry the `manifest` tag; curate by removing it.
- Docs manifest entries include `id`, `name`, `path`, `title`, and `content` (raw MDX source).
