# Register an MCP server with an MCP bundle

How to register an MCP server on Windows using an MCP bundle (MCPB), a standardized package format for MCP server deployment, for apps without package identity.

## Signature / Usage

```powershell
dotnet tool install -g mcpb.cli
mcpb init
mcpb pack
```

## Options / Props

| Name | Type | Description |
|------|------|-------------|
| `_meta.com.microsoft.windows.static_responses` | object | Required section listing all capabilities/tools the server provides; must exactly match the server's runtime `initialize` and `tools/list` responses. |
| `_meta.com.microsoft.windows.package_family_name` | string | Generated by ODR; any value supplied during registration is ignored. |

## Notes

- Warning: MCP servers run in an agent session under its own user account by default; MCP bundles are **not** supported in the agent session and therefore not accessible from the ODR unless the user enables "Reduce protections for agent connectors" (testing only, has security caveats).
- If a packaged app (MSIX) can include registration metadata directly, prefer [Register with package identity](./mcp-windows-identity.md) instead.
- The MCPB manifest format itself is defined by the MCPB GitHub repo (`modelcontextprotocol/mcpb`); Windows-specific requirements live only in the `_meta.com.microsoft.windows` object.
- If server values (name, version, tools) change, the MCPB config must be regenerated to match, or the server will not run in default (contained) mode.
