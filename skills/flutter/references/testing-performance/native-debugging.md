# Use a native language debugger

How to connect a native debugger to your running Flutter app: one debugger for Dart and one for the native code (Xcode, Android Studio, Visual Studio).

## Signature / Usage

```console
$ flutter build appbundle --debug
$ flutter build ios --config-only --no-codesign --debug
$ flutter build macos --debug
C:\> flutter build windows --debug
```

Build the platform version first (the platform dependencies are generated by `flutter build`), then attach the native debugger to the running Flutter process, or start the native debugger first and attach VS Code to the Dart VM service URI.

If you write Flutter apps only with Dart code, you can debug your code using your IDE's debugger (the Flutter team recommends VS Code). If you write a platform-specific plugin or use platform-specific libraries, you can debug that portion with a native debugger:

- To debug iOS or macOS code written in Swift or Objective-C, you can use Xcode.
- To debug Android code written in Java or Kotlin, you can use Android Studio.
- To debug Windows code written in C++, you can use Visual Studio.

## Debug Dart code using VS Code

1. Create a basic Flutter app.

   ```console
   $ flutter create my_app
   $ cd my_app
   ```

2. Open `lib\main.dart` in VS Code.
3. Click the bug icon. This opens the **Debug**, **Debug Console**, and **Widget Inspector** panes. The first time you run the debugger takes the longest.
4. Test the debugger: click the `_counter++;` line in `main.dart`, press Shift + F9 to add a breakpoint, then click the **+** button in the app. The app pauses.

## Update test Flutter app

For the remainder of the guide, the test app adds native code to debug via the `url_launcher` package. Replace `lib/main.dart` with:

```dart
// Copyright 2023 The Flutter Authors. All rights reserved.
// Use of this source code is governed by a BSD-style license that can be
// found in the LICENSE file.

import 'package:flutter/material.dart';
import 'package:url_launcher/url_launcher.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'URL Launcher',
      theme: ThemeData(
        colorSchemeSeed: Colors.purple,
        brightness: Brightness.light,
      ),
      home: const MyHomePage(title: 'URL Launcher'),
    );
  }
}

class MyHomePage extends StatefulWidget {
  const MyHomePage({super.key, required this.title});
  final String title;

  @override
  State<MyHomePage> createState() => _MyHomePageState();
}

class _MyHomePageState extends State<MyHomePage> {
  Future<void>? _launched;

  Future<void> _launchInBrowser(Uri url) async {
    if (!await launchUrl(
      url,
      mode: LaunchMode.externalApplication,
    )) {
      throw Exception('Could not launch $url');
    }
  }

  Future<void> _launchInWebView(Uri url) async {
    if (!await launchUrl(
      url,
      mode: LaunchMode.inAppWebView,
    )) {
      throw Exception('Could not launch $url');
    }
  }

  Widget _launchStatus(BuildContext context, AsyncSnapshot<void> snapshot) {
    if (snapshot.hasError) {
      return Text('Error: ${snapshot.error}');
    } else {
      return const Text('');
    }
  }

  @override
  Widget build(BuildContext context) {
    final Uri toLaunch = Uri(
        scheme: 'https',
        host: 'docs.flutter.dev',
        path: 'testing/native-debugging');
    return Scaffold(
      appBar: AppBar(
        title: Text(widget.title),
      ),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: <Widget>[
            Padding(
              padding: const EdgeInsets.all(16),
              child: Text(toLaunch.toString()),
            ),
            FilledButton(
              onPressed: () => setState(() {
                _launched = _launchInBrowser(toLaunch);
              }),
              child: const Text('Launch in browser'),
            ),
            const Padding(padding: EdgeInsets.all(16)),
            FilledButton(
              onPressed: () => setState(() {
                _launched = _launchInWebView(toLaunch);
              }),
              child: const Text('Launch in app'),
            ),
            const Padding(padding: EdgeInsets.all(16.0)),
            FutureBuilder<void>(future: _launched, builder: _launchStatus),
          ],
        ),
      ),
    );
  }
}
```

Add the `url_launcher` package:

```console
$ flutter pub add url_launcher
```

Installing `url_launcher` added config files and code files for all target platforms in the Flutter app directory (for example `ios/Flutter/Debug.xcconfig`, `linux/flutter/generated_plugin_registrant.cc`, `macos/Flutter/GeneratedPluginRegistrant.swift`, `pubspec.lock`, `pubspec.yaml`, `windows/flutter/generated_plugin_registrant.cc`). On Linux or macOS, `find ./ -mmin -120` lists recently changed files.

## Debug Dart and native language code at the same time

This allows you to leverage Flutter's hot reload when editing native code. All sections use the `url_launcher` app above. The sample app has two buttons: **Launch in browser** opens the page in the default browser; **Launch in app** opens the page within your app (iOS or Android only; desktop apps launch a browser).

Starting VS Code first (all platforms): open the app directory (**File** > **Open Folder...**), open `lib/main.dart`, select the device with the command palette **Flutter: Select Device** if you can build for more than one device, then click the debug icon and wait for the debug pane to indicate **Connected**.

### Debug Dart and Android code using Android Studio

Build the Android version of the app:

```console
flutter build appbundle --debug
```

**Start from VS Code:** start the Dart debugger in VS Code as above, then in Android Studio attach to the Flutter process:

1. Click the **Attach debugger to Android process** button. If this button doesn't appear in the **Projects** menu bar, verify that you opened a Flutter _application_ project but _not a Flutter plugin_.
2. The **process** dialog displays one entry for each connected device. Select **show all processes** to display available processes for each device.
3. Choose the process to attach to (for example `com.example.my_app` on the Emulator Pixel_5_API_33).
4. Locate the tab for **Android Debugger** in the **Debug** pane.
5. In the **Project** pane, expand **my_app_android** > **android** > **app** > **src** > **main** > **java** > **io.flutter plugins**, and double click **GeneratedProjectRegistrant** to open the Java code in the **Edit** pane.

**Start from Android Studio:** open the app (**File** > **Open...**), open `lib/main.dart`, choose a virtual Android device from the toolbar dropdown (**Open Android Emulator: \<device\>**; any installed emulator that doesn't include `arm64`), then click **Run 'main.dart'** (Ctrl + Shift + R). After the app displays in the emulator, attach the debugger using the steps above.

At the end, both the Dart and Android debuggers interact with the same process. Use either, or both, to set breakpoints, examine stack, and resume execution.

### Debug Dart and iOS code using Xcode

```console
$ flutter build ios --config-only --no-codesign --debug
```

**Start from VS Code:** start the Dart debugger in VS Code, then in Xcode go to **Debug** > **Attach to Process** and select **Runner** (at the top of the menu under **Likely Targets**).

**Start from Xcode:**

1. Open `ios/Runner.xcworkspace` from your Flutter app directory.
2. Select the correct device using the **Scheme** menu in the toolbar (if you have no preference, choose **iPhone Pro 14**).
3. Run this Runner as a normal app in Xcode. When the run completes, the **Debug** area displays a message with the Dart VM service URI:

   ```console
   2023-07-12 14:55:39.966191-0500 Runner[58361:53017145]
       flutter: The Dart VM service is listening on
       http://127.0.0.1:50642/00wEOvfyff8=/
   ```

4. Copy the Dart VM service URI.
5. In VS Code, open the command palette (View > Command Palette..., or Cmd + Shift + P), type `debug`, click **Debug: Attach to Flutter on Device**, paste the URI into the **Paste an VM Service URI** box, and press Enter.

### Debug Dart and macOS code using Xcode

```console
flutter build macos --debug
```

**Start from VS Code:** start the debugger in VS Code, then in Xcode go to **Debug** > **Attach to Process** > **Runner**.

**Start from Xcode:** open `macos/Runner.xcworkspace`, run the Runner as a normal app, copy the Dart VM service URI shown in the **Debug** area, then use **Debug: Attach to Flutter on Device** in VS Code and paste the URI (same steps as iOS).

### Debug Dart and C++ code using Visual Studio

```console
C:\> flutter build windows --debug
```

**Start from VS Code:** start the debugger in VS Code, then in Visual Studio:

1. Open the project solution file (**File** > **Open** > **Project/Solution...**, or Ctrl + Shift + O) and choose `build/windows/my_app.sln` in your Flutter app directory.
2. Go to **Debug** > **Attach to Process** (Ctrl + Alt + P).
3. From the **Attach to Process** dialog box, choose `my_app.exe`. Visual Studio starts monitoring the Flutter app.

**Start from Visual Studio:**

1. Open `build/windows/my_app.sln`.
2. Set `my_app` as the startup project (in **Solution Explorer**, right-click `my_app` and select **Set as Startup Project**).
3. Click **Local Windows Debugger** (F5). When the Flutter app has started, a console window displays the Dart VM service URI:

   ```console
   flutter: The Dart VM service is listening on http://127.0.0.1:62080/KPHEj2qPD1E=/
   ```

4. Copy the URI, then in VS Code run **Debug: Attach to Flutter on Device** and paste it into the **Paste an VM Service URI** box.
