# Protection levels

Compares the protection levels of Cloud KMS keys: `SOFTWARE`, `HSM` (Multi-tenant Cloud HSM), `HSM_SINGLE_TENANT`, `EXTERNAL` (Cloud EKM over the internet) and `EXTERNAL_VPC` (Cloud EKM over VPC). The protection level is chosen at key creation and can't be changed.

## Signature / Usage

### Create keys with a protection level

Per the gcloud help, `external` and `external-vpc` keys need `--skip-initial-version-creation`, and `external-vpc` keys also need `--crypto-key-backend` (the resource name of the backend where the key resides).

```bash
gcloud kms keys create gimli --location=us-east1 \
  --keyring=fellowship --purpose=encryption --protection-level=hsm
```

```bash
gcloud kms keys create legolas --location=us-central1 \
  --keyring=fellowship --purpose=encryption \
  --default-algorithm=external-symmetric-encryption \
  --protection-level=external --skip-initial-version-creation
```

## Options / Props

| Protection level | Value | Where operations run / key lives | Key origin |
|---|---|---|---|
| Software | `SOFTWARE` | Cryptographic operations in software | Generated by Google or imported |
| Multi-tenant hardware | `HSM` | Google-owned HSM | Generated by Google or imported |
| Single-tenant hardware | `HSM_SINGLE_TENANT` | Single-tenant instance in a Google-owned HSM: a dedicated cluster of HSM partitions you manage | Generated by Google or imported |
| External over the internet | `EXTERNAL` | Key generated and stored in your EKM; Cloud EKM stores extra cryptographic material and a path to the key, accessed over the internet | Your EKM |
| External over VPC | `EXTERNAL_VPC` | Same as above, accessed over a VPC network | Your EKM |

### Features shared by all protection levels

| Feature | Detail |
|---|---|
| CMEK | Usable in CMEK-integrated services. Some services don't support Cloud EKM keys (see the CMEK integrations list and its "Show only EKM compatible services" filter) |
| API | Cloud KMS APIs and client libraries work without code specific to the protection level |
| Access | IAM roles |
| State | Each key version is Enabled or Disabled |
| Logging | Key operations are captured in audit logs; data access logging can be enabled |

### Level-specific facts

| Level | Facts |
|---|---|
| Software | BoringCrypto module (BCM), FIPS 140-3 Level 1 validated; the cheapest level; good where there is no requirement for a higher FIPS 140-3 level |
| Hardware | FIPS 140-2 Level 3 validated HSMs; fully managed; more expensive; each key has an attestation statement with certified key information (verifiable with its certificate chains) |
| Single-tenant hardware | Same functionality as Multi-tenant Cloud HSM plus cryptographic isolation from other customers; instance administrators have administrative control; additional expense versus Multi-tenant |
| External | Keys can be software- or hardware-backed depending on your EKM provider; the most expensive levels; Google Cloud can't access your key material |
| External over the internet | Available in all Cloud KMS locations except `nam-eur-asia1` and `global` |
| External over VPC | Better availability; available in most regional locations; not available in multi-region locations |

## Notes

- Caution from the source: Cloud EKM keys over the internet risk becoming unavailable; for better availability consider Cloud HSM or Cloud EKM over a VPC network.
- Existing external key versions can migrate (Preview) between `EXTERNAL` and `EXTERNAL_VPC` without re-encrypting data and with zero downtime (for example `EXTERNAL` to `EXTERNAL_VPC` for better availability). See https://docs.cloud.google.com/kms/docs/migrate-external-keys. The migration is in Preview according to https://docs.cloud.google.com/kms/docs/ekm.
- Disabling or destroying a CMEK key makes data encrypted with it inaccessible; try on a disposable key first.
