# Import your Google Cloud resources into Terraform state

Terraform can import existing infrastructure created by other means so it comes under Terraform management. Any Google Cloud resource can be imported: one at a time with `terraform import`, in bulk with an `import` block (Terraform 1.5 or later), or in bulk after a bulk export (Preview).

## Signature / Usage

### Import one resource at a time

The command takes the resource address and the ID. The ID format depends on the resource type and is documented in the provider's Import section; use the full identifier including the project ID when supported.

```hcl
resource "google_storage_bucket" "sample" {
 name          = "my-bucket"
 project       = "sample-project"
 location      = "US"
 force_destroy = true
}
```

Address: `google_storage_bucket.sample`. ID format for this type is `project/name`.

```bash
terraform import google_storage_bucket.sample sample-project/my-bucket
```

### Import resources within modules

Each resource in a module must be imported individually by its address.

```hcl
module "gcs_bucket" {
 source  = "terraform-google-modules/cloud-storage/google//modules/simple_bucket"
 version = "~> 3.4"

 name       = "my-bucket"
 project_id = "sample-project"
 location   = "us-east1"
}
```

To find the address, inspect the module contents or apply and read the provider error:

```text
terraform apply
module.gcs_bucket.google_storage_bucket.bucket: Creating...
╷
│ Error: googleapi: Error 409: Your previous request to create the named bucket succeeded and you already own it., conflict
│
│   with module.gcs_bucket.google_storage_bucket.bucket,
```

The ID name is found in the plan output:

```text
module.gcs_bucket.google_storage_bucket.bucket will be created
+ resource "google_storage_bucket" "bucket" {
    + name                        = "my-bucket"
    + project                     = "sample-project"
    ...
  }
```

```bash
terraform import module.gcs_bucket.google_storage_bucket.bucket sample-project/my-bucket
```

### Import in bulk with an `import` block

Requires Terraform 1.5 or later. Imports are previewed in `plan` and executed in `apply`; code can be generated automatically.

```hcl
import {
  # Provider-defined resource ID of the cloud resource to be imported
  id = "projects/PROJECT_ID/global/networks/my-network"

  # Terraform resource address to be created
  to = google_compute_network.my_network
}
```

To have Terraform generate the resource blocks, use `-generate-config-out`, review the code, then run `terraform apply`:

```bash
terraform plan -generate-config-out=generated_resources.tf
```

### Import after a bulk export (Preview)

Prerequisites:

```bash
export GOOGLE_CLOUD_PROJECT=PROJECT_ID
```

```bash
gcloud components install config-connector
```

If the component manager is disabled (`ERROR: (gcloud.components.install) You cannot perform this action because the Google Cloud CLI component manager is disabled for this installation`):

```bash
sudo apt-get install google-cloud-sdk-config-connector
```

```bash
gcloud services enable cloudasset.googleapis.com
```

Generate Terraform code:

```bash
mkdir OUTPUT_DIRECTORY
```

```bash
gcloud beta resource-config bulk-export \
   --path=OUTPUT_DIRECTORY \
   --project=PROJECT_ID \
   --resource-format=terraform
```

Create Terraform modules and an import script:

```bash
gcloud beta resource-config terraform generate-import OUTPUT_DIRECTORY
```

`gcloud-export-modules.tf` points to all modules of the sub-resources:

```hcl
provider "google" {
 project = "PROJECT_ID"
}

module "OUTPUT_DIRECTORY-projects-PROJECT_ID-ComputeFirewall" {
 source = "./OUTPUT_DIRECTORY/projects/PROJECT_ID/ComputeFirewall"
}

module "OUTPUT_DIRECTORY-projects-PROJECT_ID-ComputeBackendService-global" {
 source = "./OUTPUT_DIRECTORY/projects/PROJECT_ID/ComputeBackendService/global"
}
```

An executable script such as `terraform_import_20220331-19-12-33.sh` lists `terraform import` commands:

```bash
#!/bin/sh
# Terraform Import Script generated by gcloud cli

terraform import module.OUTPUT_DIRECTORY-projects-PROJECT_ID-ComputeFirewall.google_compute_firewall.allow_ssh projects/PROJECT_ID/global/firewalls/allow-ssh
```

Import the modules into state:

```bash
terraform init
```

```bash
./terraform_import_20220331-19-12-33.sh
```

## Options / Props

### `import` block arguments

| Argument | Description |
|----------|-------------|
| `id` | Provider-defined resource ID of the cloud resource (see the resource's Import section in the Google provider docs; for example `projects/{project}/global/networks/{name}` for `google_compute_network`) |
| `to` | Terraform resource address to be created, usually `RESOURCE TYPE.NAME` |

### Import methods

| Method | Requirement |
|--------|-------------|
| `terraform import` | One resource at a time |
| `import` block | Terraform 1.5 or later |
| Bulk export then import | Preview; not supported on Windows operating systems |

## Notes

- Bulk export import is Preview: subject to the "Pre-GA Offerings Terms" and available "as is" with possibly limited support. It is not supported on Windows.
- After import, the import output says the resources "are now in your Terraform state and will henceforth be managed by Terraform". The sample bucket sets `force_destroy = true`; the store-state page explains that `false` keeps a bucket from being deleted while it holds objects.
- The source also shows the output of each `terraform import` and of the generated import script (omitted).
- `gcloud resource-config` is in `gcp-foundation`.
