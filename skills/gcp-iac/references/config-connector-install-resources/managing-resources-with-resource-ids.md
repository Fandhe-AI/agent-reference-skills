# Managing resources with the resourceID field

The immutable but optional `resourceID` field lets you explicitly specify the Google Cloud resource ID to create or acquire a resource, which allows names outside Kubernetes naming rules and acquiring resources with service-generated IDs.

## Signature / Usage

### Specify `resourceID`

Config Connector resource `pubsub-topic-sample` manages the Pub/Sub topic `pubsub-topic-id`:

```yaml
apiVersion: pubsub.cnrm.cloud.google.com/v1beta1
kind: PubSubTopic
metadata:
  name: pubsub-topic-sample
spec:
  resourceID: pubsub-topic-id
```

### Create a BigQuery dataset

The value should follow the naming convention of the BigQuery `datasetId` field. Save the following as `bigquery-dataset.yaml`:

```yaml
apiVersion: bigquery.cnrm.cloud.google.com/v1beta1
kind: BigQueryDataset
metadata:
  name: bigquerydataset-sample-for-creation
spec:
  resourceID: bigquerydataset_sample_with_resourceid
  defaultTableExpirationMs: 3600000
  description: "BigQuery Dataset Sample with the ResourceID Field"
  friendlyName: bigquerydataset-sample-with-resourceid
  location: US
```

```bash
kubectl apply --namespace CC_NAMESPACE -f bigquery-dataset.yaml
```

```bash
kubectl describe --namespace CC_NAMESPACE bigquerydataset bigquerydataset-sample-for-creation
```

### Acquire a folder

Replace `ORG_ID`, `ACQUIRED_FOLDER_ID` and `ACQUIRED_FOLDER_DISPLAY_NAME`. Remove the deletion-policy annotation only if it is safe to delete the folder when the resource is deleted from your cluster. Save the following as `folder.yaml`:

```yaml
apiVersion: resourcemanager.cnrm.cloud.google.com/v1beta1
kind: Folder
metadata:
  annotations:
    cnrm.cloud.google.com/organization-id: ORG_ID
    # Remove the deletion-policy annotation if it is safe to delete the
    # folder when the resource is deleted from your cluster.
    cnrm.cloud.google.com/deletion-policy: "abandon"
  name: folder-sample-for-acquisition
spec:
  resourceID: ACQUIRED_FOLDER_ID
  displayName: ACQUIRED_FOLDER_DISPLAY_NAME
```

```bash
kubectl apply --namespace CC_NAMESPACE -f folder.yaml
```

```bash
kubectl describe --namespace CC_NAMESPACE folder folder-sample-for-acquisition
```

## Options / Props

| Resource ID type | Meaning | How to use `resourceID` |
|---|---|---|
| User-specified | Determined and passed in by the user before creation | Create or acquire the resource with `resourceID` |
| Service-generated | Generated by the service during creation; retrievable after creation | Acquire with `resourceID`; leave unspecified to create a new resource |

## Notes

- Immutable but optional: you can choose to set it or not, but you cannot change its value after the manifest is applied.
- Benefits: multiple Config Connector resources of the same kind with the same Google Cloud resource name can exist under different projects, folders, organizations or parent resources within the same namespace, and the Google Cloud name is not restricted by Kubernetes DNS-subdomain naming.
- Config Connector makes the namespace the "owner" of a resource. With `resourceID`, multiple resources with the same Google Cloud name can be created under the same namespace; these cause conflicts that Config Connector cannot manage, and you must resolve them manually.
- For a resource with a service-generated resource ID, Config Connector assumes the resource already exists and tries to acquire it. It acquires when the resource has a user-specified ID and the manifest values and name match an existing resource, or when the resource has a service-generated ID.
- Deleting the acquired folder's Config Connector object without the `abandon` policy deletes the folder; try it on a disposable organization or folder first.
- Replace `CC_NAMESPACE` with the namespace Config Connector manages resources from.
