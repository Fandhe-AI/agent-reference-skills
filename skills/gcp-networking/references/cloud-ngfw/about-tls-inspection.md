# TLS inspection overview (Cloud NGFW)

Cloud NGFW TLS interception and decryption lets firewall endpoints inspect encrypted traffic (inbound and outbound, internet and within Google Cloud) for Layer 7 services such as URL filtering and intrusion detection and prevention, then re-encrypts it. It uses Google-managed Certificate Authority Service (CAS) to generate short-lived intermediate certificates. It is a Cloud NGFW Enterprise feature.

## Signature / Usage

### List TLS inspection policies

A TLS inspection policy (CA pools plus optional trust configs) is attached to the firewall endpoint association, and a rule enables decryption with the `--tls-inspect` flag.

Adapted (not in the official docs): the help example's `$REGION` shell variable is replaced by an upper-case placeholder; replace `REGION` with the region of the policies.

```bash
gcloud network-security tls-inspection-policies list \
    --location=REGION
```

## Options / Props

### Specifications

| Item | Value |
|---|---|
| TLS versions | 1.0, 1.1, 1.2, 1.3 |
| Policy and CA pool scope | Both regional; create a CA pool and a TLS inspection policy per region where inspection is enabled |
| Trust config | Must be in the same region as the TLS inspection policy |
| Intermediate CAs | Regenerated by Cloud NGFW every 24 hours; stored only in memory |

### Limitations

- Enterprise doesn't support HTTP/2, QUIC, HTTP/3 or PROXY protocol traffic with TLS inspection; TLS inspection is supported for TCP traffic that is not HTTPS.
- Only TLS decryption is supported (not SSH or other protocols).
- Inspecting egress traffic from serverless workloads is not supported (Direct VPC egress and Serverless VPC Access connectors).

## Notes

- With `--tls-inspect` on a firewall policy rule, Cloud NGFW generates a server certificate for matched TLS traffic, signed by its intermediate CAs (which are signed by CA pools in CAS); it is cached briefly per host. CAs in CAS are HSM-backed with audit logs; per-certificate issuance by intermediate CAs produces no audit log.
- Issuance policies and name constraints in the CA pool don't apply to server certificates generated by Cloud NGFW; a CA pool with name constraints can yield invalid certificates.
- HTTP Connect: egress HTTPS sent through an intermediate proxy such as Secure Web Proxy is decrypted after the tunnel is established.
- Internal load balancers (Preview): for cross-region internal Application Load Balancers the load balancer terminates TLS and forwards plain text, so the association's `--tls-inspection-policy` is ignored and rules ignore `--tls-inspect` when `--target-type` is `INTERNAL_MANAGED_LB`.
