# Headers

Default response headers for static assets, and the `_headers` file for overriding, removing, or adding headers.

## Signature / Usage

Place a plain text `_headers` file (no extension) in the static assets directory. Rules are multi-line blocks:

```txt
[url]
  [name]: [value]
```

```txt
# This is a comment
/secure/page
	X-Frame-Options: DENY
	X-Content-Type-Options: nosniff
	Referrer-Policy: no-referrer

/static/*
	Access-Control-Allow-Origin: *
	X-Robots-Tag: nosnippet

https://myworker.mysubdomain.workers.dev/*
	X-Robots-Tag: noindex
```

Detach a header with `! `:

```txt
/*
  Content-Security-Policy: default-src 'self';

/*.jpg
  ! Content-Security-Policy
```

Placeholders:

```txt
/movies/:title
  x-movie-name: You are watching ":title"
```

Fingerprinted assets:

```txt
/static/*
  Cache-Control: public, max-age=31556952, immutable
```

## Options / Props

Default headers:

| Header | Description |
|--------|-------------|
| `Content-Type` | Attached if provided during upload; Wrangler determines the MIME type from the file extension. |
| `Cache-Control: public, max-age=0, must-revalidate` | Sent when the request has no `Authorization` or `Range` header; cacheable but revalidated each time. |
| `ETag` | Hash of the asset file; used with `If-None-Match`. |
| `CF-Cache-Status` | `HIT` or `MISS`. Probabilistic: false positives and negatives can occur. |

## Notes

- Cloudflare may attach new default headers at any time.
- `_headers` is not itself served as an asset. Headers defined in it override Cloudflare's defaults.
- Custom headers are NOT applied to responses generated by your Worker code (SSR, `assets.run_worker_first`, or any Worker script); attach them in the Worker `Response` instead. This includes CORS for API endpoints (also for `OPTIONS` requests).
- A request matching multiple rules inherits all matching rules' headers. A header applied twice is joined with a comma separator.
- Limits: up to 100 header rules; each line has a 2,000 character limit (spacing, name and value included).
- Absolute URLs must begin with `https` and cannot specify a port; port and protocol of the incoming request are ignored when matching.
- Matching is the same as `_redirects`, but redirects are applied before headers: if a request matches both, the redirect wins.
- Splat (`*`): greedily matches all characters, only one per URL; the match is available as `:splat`.
- Placeholder (`:name`, `:[A-Za-z]\w*`): each can be referenced once; matches all characters except the delimiter (`.` or `/` in a host, `/` in a path).
- CORS: `Access-Control-Allow-Origin` only allows `*`, `null`, or an exact origin; wildcard patterns within origins are not supported. For specific Version URLs, handle CORS dynamically in Worker code.
- To keep `*.workers.dev` URLs out of search results:

```txt
https://:version.:subdomain.workers.dev/*
	X-Robots-Tag: noindex
```

- Security header example (use Worker `Response` headers instead for SSR):

```txt
/app/*
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
  Referrer-Policy: no-referrer
  Permissions-Policy: document-domain=()
  Content-Security-Policy: script-src 'self'; frame-ancestors 'none';
```
