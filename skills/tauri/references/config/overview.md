# Configuration (root Config)

The Tauri configuration object. It is read from a file where you can define your frontend assets, configure the bundler and define a tray icon. The file is generated by the `tauri init` command that lives in your Tauri application source directory (`src-tauri`); once generated, you may modify it at will.

## Signature / Usage

`src-tauri/tauri.conf.json`

```json
{
  "productName": "tauri-app",
  "version": "0.1.0",
  "identifier": "com.tauri.example",
  "build": {
    "beforeBuildCommand": "",
    "beforeDevCommand": "",
    "devUrl": "http://localhost:3000",
    "frontendDist": "../dist"
  },
  "app": {
    "security": {
      "csp": null
    },
    "windows": [
      {
        "fullscreen": false,
        "height": 600,
        "resizable": true,
        "title": "Tauri App",
        "width": 800
      }
    ]
  },
  "bundle": {},
  "plugins": {}
}
```

## Options / Props

Root properties (`additionalProperties: false`; only `identifier` is required).

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `$schema` | `string \| null` | — | The JSON schema for the Tauri config. |
| `productName` | `string \| null` | — | App name (pattern `^[^/\:*?"<>\|]+$`). The name your app is known by on the user's system, so it must be changed from the default before publishing. Names the generated bundles and is written into platform metadata and install paths that are expected to be unique to your application. |
| `mainBinaryName` | `string \| null` | — | Overrides app's main binary filename. By default Tauri uses the output binary from `cargo`; by setting this, `tauri build` renames that binary and targets `tauri bundle` to it. Should not include the binary extension (e.g. `.exe`). |
| `version` | `string \| null` | — | App version. A semver version number or a path to a `package.json` file containing the `version` field. If removed, the version number from `Cargo.toml` is used. It is recommended to manage the app versioning in the Tauri config. |
| `identifier` | `string` (required) | — | The application identifier in reverse domain name notation (e.g. `com.tauri.example`). Must be unique across applications since it is used in system configurations like the bundle ID and path to the webview data directory. Only alphanumeric characters (A-Z, a-z, 0-9), hyphens (-), and periods (.) are allowed. The default value `com.tauri.dev` is rejected by `tauri build` and must be changed before building. |
| `app` | [AppConfig](./app-config.md) | see below | The App configuration. |
| `build` | [BuildConfig](./build-config.md) | see below | The build configuration. |
| `bundle` | [BundleConfig](./bundle-config.md) | see below | The bundler configuration. |
| `plugins` | [PluginConfig](./plugins-config.md) | `{}` | The plugins config. |

Schema defaults for the nested objects:

| Property | Default |
| --- | --- |
| `app` | `{"enableGTKAppId": false, "macOSPrivateApi": false, "security": {"assetProtocol": {"enable": false, "scope": []}, "capabilities": [], "dangerousDisableAssetCspModification": false, "freezePrototype": false, "pattern": {"use": "brownfield"}}, "windows": [], "withGlobalTauri": false}` |
| `build` | `{"additionalWatchFolders": [], "removeUnusedCommands": false, "windows": {"staticVCRuntime": true}}` |
| `bundle` | `{"active": false, "targets": "all", "createUpdaterArtifacts": false, "useLocalToolsDir": false, "icon": [], ...}` (platform sub-objects omitted here; see the bundle pages) |
| `plugins` | `{}` |

## Notes

- The example on the official config reference omits identifier; it is added here because identifier is the only required root property.
- Platform-specific values by property (from the schema docs):
  - `productName` macOS: names the `.app` bundle and the `.dmg`, and sets `CFBundleDisplayName` and `CFBundleName` (`CFBundleName` can be overridden with `bundle > macOS > bundleName`). Linux: kebab-cased for the Debian and RPM package names, used as the `Name` entry of the desktop file and as the resource directory name under `/usr/lib`. Windows: names the installers, the installation directory, the Start Menu folder and the `HKCU\Software\<publisher>\<product name>` registry key; it also derives the default WiX upgrade code, which can be set explicitly with `bundle > windows > wix > upgradeCode`.
  - `version` macOS: translates to `CFBundleShortVersionString` and is the default `CFBundleVersion` (override with `bundle > macOS > bundleVersion`). iOS: same, override with `bundle > iOS > bundleVersion`; `tauri ios build` has a `--build-number <number>` option to append a build number. Android: version 1.0 is used by default; set a version code with `bundle > android > versionCode`.
- File formats: by default the configuration is a JSON file named `tauri.conf.json`. JSON5 and TOML are supported via the `config-json5` and `config-toml` Cargo features. The JSON5 file name must be `tauri.conf.json` or `tauri.conf.json5`. The TOML file name is `Tauri.toml`.
- Platform-specific configuration: in addition to the default file, Tauri reads `tauri.linux.conf.json`, `tauri.windows.conf.json`, `tauri.macos.conf.json`, `tauri.android.conf.json` and `tauri.ios.conf.json` (or `Tauri.linux.toml`, `Tauri.windows.toml`, `Tauri.macos.toml`, `Tauri.android.toml` and `Tauri.ios.toml` if the `Tauri.toml` format is used), which get merged with the main configuration object.
- Source: `tauri-apps/tauri@tauri-v2.12.4` `crates/tauri-schema-generator/schemas/config.schema.json` (`$id` `https://schema.tauri.app/config/2.12.4`).
