# HTTP Client

Make HTTP requests with the http plugin: a `fetch` API in JavaScript and a `reqwest` re-export in Rust.

## Signature / Usage

### Supported Platforms

Windows, Linux, macOS, Android, iOS: full support (`http-v2.8.3`).

### Setup

```sh
npm run tauri add http
# or: cargo tauri add http
```

Manual. From `src-tauri`:

```sh
cargo add tauri-plugin-http
```

From the project root, install the JavaScript guest bindings:

```sh
npm install @tauri-apps/plugin-http
```

```rust
// src-tauri/src/lib.rs
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_http::init())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

### Usage

JavaScript. First configure the allowed URLs in a capability:

```json
{
  "permissions": [
    {
      "identifier": "http:default",
      "allow": [{ "url": "https://*.tauri.app" }],
      "deny": [{ "url": "https://private.tauri.app" }]
    }
  ]
}
```

The `fetch` method tries to be as close and compliant to the `fetch` Web API as possible:

```javascript
import { fetch } from '@tauri-apps/plugin-http';

// Send a GET request
const response = await fetch('https://test.tauri.app/data.json', {
  method: 'GET',
});
console.log(response.status); // e.g. 200
console.log(response.statusText); // e.g. "OK"
```

Rust, using the `reqwest` crate re-exported by the plugin:

```rust
use tauri_plugin_http::reqwest;

let res = reqwest::get("http://my.api.host/data.json").await?;
println!("{:?}", res.status()); // e.g. 200
println!("{:?}", res.text().await); // e.g Ok("{ Content }")
```

### Permissions

`http:default` enables all fetch operations but does not explicitly allow any origins; origins must be configured manually (see the `allow` / `deny` URL scope above). It includes `allow-fetch`, `allow-fetch-cancel`, `allow-fetch-send`, `allow-fetch-read-body`, `allow-fetch-cancel-body`.

| Identifier | Notes |
| --- | --- |
| `http:allow-fetch` / `http:deny-fetch` | fetch command |
| `http:allow-fetch-cancel` / `http:deny-fetch-cancel` | cancel a request |
| `http:allow-fetch-cancel-body` / `http:deny-fetch-cancel-body` | cancel body |
| `http:allow-fetch-read-body` / `http:deny-fetch-read-body` | read body |
| `http:allow-fetch-send` / `http:deny-fetch-send` | send request |

## Notes

- Tauri plugin (Rust core + system WebView). It is an HTTP client for the app, not a server framework; HTTP server frameworks are covered by the fastify, hono and go-echo skills, and the TanStack Query skill covers data-fetching state.
- [Forbidden request headers](https://fetch.spec.whatwg.org/#terminology-headers) are ignored by default. To use them, enable the `unsafe-headers` feature flag:

```toml
# src-tauri/Cargo.toml
[dependencies]
tauri-plugin-http = { version = "2", features = ["unsafe-headers"] }
```

- The official Rust snippet calls `status()` on the un-awaited `Result`; a `?` is added after `.await` (inside a function returning `Result`) so it compiles.
- The official example fetches `http://test.tauri.app` although the scope only allows `https://*.tauri.app`; the URL is changed to https here so it matches the scope.
- Source: `tauri-apps/plugins-workspace@http-v2.8.3` `plugins/http/Cargo.toml`, `plugins/http/permissions/autogenerated/reference.md`; docs `plugin/http-client.mdx` @ `32f68c5`.
