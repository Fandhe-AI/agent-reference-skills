# Localhost

Expose your app's assets through a localhost server instead of the default custom protocol.

## Supported Platforms

| Platform | Level |
| --- | --- |
| Windows | full |
| Linux | full |
| macOS | full |
| Android | none |
| iOS | none |

(`localhost-v2.4.0`.) This is a Rust-only plugin (no JavaScript guest bindings).

## Setup

```sh
npm run tauri add localhost
# or: cargo tauri add localhost
```

Manual (run in `src-tauri`):

```sh
cargo add tauri-plugin-localhost
```

```rust
// src-tauri/src/lib.rs
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    let port: u16 = 9527;

    tauri::Builder::default()
        .plugin(tauri_plugin_localhost::Builder::new(port).build())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

## Signature / Usage

The localhost plugin is available in Rust. The usage example passes the port to `Builder::new`:

```rust
use tauri::{webview::WebviewWindowBuilder, WebviewUrl};

pub fn run() {
  let port: u16 = 9527;

  tauri::Builder::default()
      .plugin(tauri_plugin_localhost::Builder::new(port).build())
      .setup(move |app| {
          let url = format!("http://localhost:{}", port).parse().unwrap();
          WebviewWindowBuilder::new(app, "main".to_string(), WebviewUrl::External(url))
              .title("Localhost Example")
              .build()?;
          Ok(())
      })
      .run(tauri::generate_context!())
      .expect("error while running tauri application");
}
```

The pinned plugin README (`localhost-v2.4.0`) additionally grants the localhost URL a remote capability outside dev mode and notes that the `main` window must be removed from `tauri.conf.json`:

```rust
#[cfg(not(dev))]
use tauri::{ipc::CapabilityBuilder, Manager, Url};
use tauri::{WebviewUrl, WebviewWindowBuilder};

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    let port = portpicker::pick_unused_port().expect("failed to find unused port");

    tauri::Builder::default()
        .plugin(tauri_plugin_localhost::Builder::new(port).build())
        .setup(move |app| {
            // In `tauri dev` mode you usually use your dev server.
            #[cfg(dev)]
            let url = WebviewUrl::App(std::path::PathBuf::from("/"));

            #[cfg(not(dev))]
            let url = {
                let url: Url = format!("http://localhost:{}", port).parse().unwrap();

                app.add_capability(
                    CapabilityBuilder::new("localhost")
                        .remote(url.to_string())
                        .window("main"),
                )?;

                WebviewUrl::External(url)
            };

            // This requires you to remove the window from tauri.conf.json
            WebviewWindowBuilder::new(app, "main".to_string(), url)
                .title("Localhost Example")
                .build()?;

            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

## Notes

- Tauri plugin (Rust core + system WebView). This plugin brings considerable security risks and should only be used if you know what you are doing. If in doubt, use the default custom protocol implementation.
- The official page's Setup shows `Builder::new()` without a port; the pinned README (localhost-v2.4.0) uses `Builder::new(port)` and also adds a remote capability for the localhost URL, so the Setup here passes a port.
- Source: `tauri-apps/plugins-workspace@localhost-v2.4.0` `plugins/localhost/Cargo.toml`, `plugins/localhost/README.md`; docs `plugin/localhost.mdx` @ `32f68c5`. The plugin has no autogenerated permission reference.
