# Using Plugin Permissions

Add the fs plugin, find its permissions, and scope `fs:allow-write-text-file` to a single file in a Tauri capability (ACL).

Add the plugin

```sh
pnpm tauri add fs
```

Or manually

```sh
cargo add tauri-plugin-fs
```

`src-tauri/src/lib.rs`

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
  tauri::Builder::default()
    .plugin(tauri_plugin_fs::init())
    .run(tauri::generate_context!())
    .expect("error while running tauri application");
}
```

The plugin's `permissions/default.toml` as shown on the official docs page (shows how the `default` set is declared)

```toml
"$schema" = "schemas/schema.json"

[default]
description = """
# Tauri `fs` default permissions

This configuration file defines the default permissions granted
to the filesystem.

### Granted Permissions

This default permission set enables all read-related commands and
allows access to the `$APP` folder and sub directories created in it.
The location of the `$APP` folder depends on the operating system,
where the application is run.

In general the `$APP` folder needs to be manually created
by the application at runtime, before accessing files or folders
in it is possible.

### Denied Permissions

This default permission set prevents access to critical components
of the Tauri application by default.
On Windows the webview data folder access is denied.

"""
permissions = ["read-all", "scope-app-recursive", "deny-default"]
```

`src-tauri/capabilities/default.json` (allow only writing `$HOME/test.txt`)

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capability for the main window",
  "windows": [
    "main"
  ],
  "permissions": [
    "core:default",
    {
      "identifier": "fs:allow-write-text-file",
      "allow": [{ "path": "$HOME/test.txt" }]
    }
  ]
}
```

`src/main.ts`

```ts
import { writeTextFile, BaseDirectory } from '@tauri-apps/plugin-fs';

let greetInputEl: HTMLInputElement | null;

async function write(message: string) {
    await writeTextFile('test.txt', message, { baseDir: BaseDirectory.Home });
}

window.addEventListener("DOMContentLoaded", () => {
  greetInputEl = document.querySelector("#greet-input");
  document.querySelector("#greet-form")?.addEventListener("submit", (e) => {
    e.preventDefault();
    if (!greetInputEl )
      return;

    write(greetInputEl.value == "" ? "No input provided": greetInputEl.value);

  });
});
```

## Notes

- Tauri capabilities / permissions (ACL), not Claude Code or MCP permissions.
- Official plugins list their default permission and permission table on their docs page; for community plugins read `permissions/default.toml` and `permissions/autogenerated` in the plugin source.
- Without the right permission the call is rejected with `fs.write_text_file not allowed. Permissions associated with this command: ...`.
- The official page first shows `"fs:default"` and `"fs:allow-write-text-file"` (diff markers `del` / `ins`), then the scoped form above.
- The official snippet uses the pre-2.0 core identifiers (path:default, event:default, ...); they are replaced with core:default here, and the unscoped fs:allow-write-text-file line removed by the official diff (del={18}) is dropped.
- shell:allow-open from the official snippet is dropped because this sample registers only the fs plugin.
- This default.toml excerpt is from the docs page and predates fs-v2.7.1, whose fs:default is create-app-specific-dirs + read-app-specific-dirs-recursive + deny-default (the app dirs are created by the plugin).
- The official snippet declares run() without pub; it is made pub so main.rs and the mobile entry point can call it.
