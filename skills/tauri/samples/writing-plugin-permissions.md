# Writing Plugin Permissions

Add a command to a new Tauri plugin and expose it through autogenerated and default Tauri permissions (ACL).

Scaffold a plugin

```sh
mkdir -p tauri-learning
cd tauri-learning
cargo tauri plugin new test
cd tauri-plugin-test
pnpm install
pnpm build
cargo build
```

`src/commands.rs`

```rust
use tauri::{AppHandle, command, Runtime, Manager};

use crate::models::*;
use crate::Result;
use crate::TestExt;

#[command]
pub(crate) async fn ping<R: Runtime>(
    app: AppHandle<R>,
    payload: PingRequest,
) -> Result<PingResponse> {
    app.test().ping(payload)
}

#[command]
pub(crate) async fn write_custom_file<R: Runtime>(
    user_input: String,
    app: AppHandle<R>,
) -> Result<String> {
    std::fs::write(app.path().temp_dir().unwrap().join("custom_file.txt"), user_input)?;
    Ok("success".to_string())
}
```

`build.rs` (plugin crate root; generates `allow-write-custom-file` / `deny-write-custom-file`)

```rust
const COMMANDS: &[&str] = &["ping", "write_custom_file"];
```

`src/lib.rs`

```rust
pub fn init<R: Runtime>() -> TauriPlugin<R> {
Builder::new("test")
    .invoke_handler(tauri::generate_handler![
        commands::ping,
        commands::write_custom_file,
    ])
    .setup(|app, api| {
        #[cfg(mobile)]
        let test = mobile::init(app, api)?;
        #[cfg(desktop)]
        let test = desktop::init(app, api)?;
        app.manage(test);
        Ok(())
    })
    .build()
}
```

`guest-js/index.ts`

```ts
import { invoke } from '@tauri-apps/api/core'

export async function ping(value: string): Promise<string | null> {
  return await invoke<{value?: string}>('plugin:test|ping', {
    payload: {
      value,
    },
  }).then((r) => (r.value ? r.value : null));
}

export async function writeCustomFile(user_input: string): Promise<string> {
 return await invoke('plugin:test|write_custom_file',{userInput: user_input});
}
```

`permissions/default.toml`

```toml
"$schema" = "schemas/schema.json"
[default]
description = "Default permissions for the plugin"
permissions = ["allow-ping", "allow-write-custom-file"]
```

## Notes

- Tauri capabilities / permissions (ACL) for a plugin author, not Claude Code or MCP permissions.
- Needs Tauri CLI 2.x (`cargo tauri info` shows the version).
- The Tauri build system generates the `allow-<command>` and `deny-<command>` permissions into `permissions/autogenerated/commands`; the official text says `enable-<command>` in one place, but the permission used in `default.toml` is `allow-write-custom-file`.
- The `invoke` argument keys must be camelCase (`userInput`, not `user_input`).
- Exposing the command in `guest-js/index.ts` is a convenience with no security impact; the command can already be invoked manually once the handler is generated.
- The official snippet calls `app.test1()`, writes to `temp_dir()` itself, labels the file `src/build.rs` and manages an undefined `MyState`; this sample uses the template's `test()` accessor, joins a file name, uses the root `build.rs`, and drops `MyState`.
- `unwrap()` on `temp_dir()` is kept because the template's `crate::Error` has no `tauri::Error` variant.
- The official page then edits the plugin's `examples/tauri-app` Svelte `App.svelte` to call `writeCustomFile` (not reproduced here).
