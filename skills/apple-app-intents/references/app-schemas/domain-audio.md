# Audio domain

Make your audio app's actions available to Apple Intelligence and Siri by adopting schemas for common audio playback actions.

## Signature / Usage

```swift
@AppIntent(schema: .audio.playAudio)
struct PlayAudioIntent: AudioStartingIntent {
    var audioEntity: <#AudioItem#>
    var playbackAttributes: Set<<#PlaybackAttributes#>>
    var warmupAudioQueueResult: <#WarmupAudioQueueResult#>?
    var queueLocation: <#QueueInsertionLocation#>?

    func perform() async throws -> some IntentResult {
        <#code#>
    }
}
```

```swift
@UnionValue
enum AudioItem {
    case song(<#SongEntity#>)
```

## Options / Props

| Schema | Kind | Description | Example phrases |
|--------|------|-------------|-----------------|
| `playAudio` | Intent (`AppSchema.AudioIntent`) | An intent schema that plays an audio item. | "Play music." / "Play hip-hop in the living room." |
| `addToLibrary` | Intent (`AppSchema.AudioIntent`) | Adds an audio item to the person's library. | "Follow this podcast." / "Add this song to my library." |
| `addToPlaylist` | Intent (`AppSchema.AudioIntent`) | Adds an audio item to a playlist. | "Add this song to my running playlist." |
| `createStation` | Intent (`AppSchema.AudioIntent`) | Starts a station based on the now-playing item. | "Create a station based on this song." / "Play more music like this." |
| `recognizeAudio` | Intent (`AppSchema.AudioIntent`) | Finds out what audio is playing nearby. | "What song is this?" / "Shazam." |
| `updateAudioAffinity` | Intent (`AppSchema.AudioIntent`) | Sets the like state of an audio item to liked, unliked, or unset. | "I like this song." / "I don't like this song." |
| `warmupAudioQueue` | Intent (`AppSchema.AudioIntent`) | Warms up an audio item by setting the queue without starting playback. | (none listed) |

## Notes

- The `.audio` domain: protocols `AppSchema.AudioIntent`, `AppSchema.AudioEntity`, `AppSchema.AudioEnum`. Each member is `var <name>: some AppSchemaIntent` / `AppSchemaEntity` / `AppSchemaEnum`.
- `AppSchema.AudioIntent` and `playAudio`: iOS 27.0+, iPadOS 27.0+, Mac Catalyst 27.0+, macOS 27.0+, visionOS 27.0+ (no tvOS / watchOS on the member pages). Domain page itself carries no platform metadata.
- Xcode generates a template implementation when you type `audio_` and select a schema from the suggestions list.
- The Media Intents framework provides the types that describe a person's audio search and playback request. Your app implements an `IntentValueQuery` to receive these types, find matching audio content, and return app entities.
- Use-case group (playback): the `playAudio` schema and the `IntentValueQuery` that returns matching audio form a use-case group. Xcode reports a build warning if your app supports one without the other. To integrate with Apple Intelligence and bring the app to Siri AI, adopt both parts.
- The sample conforms to `AudioStartingIntent`, which is listed as deprecated in the App Intents documentation (replacement not stated on that page). The `@UnionValue` enum is generated by typing `audio_audioItem` in Xcode; keep the cases your app supports and remove the rest.
- The `playAudio` schema supports Siri and Shortcuts per its page.
- Related sample article: "Integrating your music app with Apple Intelligence" (audio and clock schemas).
- Distinct from the Foundation Models framework (`LanguageModelSession` / `Tool`) and from the audio recording / playback intent protocols (`AudioPlaybackIntent` etc.) in intent-types.
