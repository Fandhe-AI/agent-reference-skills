# Theme variables

Using utility classes as an API for your design tokens.

## Signature / Usage

```css
@import "tailwindcss";

@theme {
  --color-mint-500: oklch(0.72 0.11 178);
}
```

```html
<div class="bg-mint-500">
  <!-- ... -->
</div>
<div style="background-color: var(--color-mint-500)">
  <!-- ... -->
</div>
```

## Options / Props

Theme variable namespaces (each maps to utilities or variants):

| Namespace | Utility classes |
|-----------|-----------------|
| `--color-*` | Color utilities like `bg-red-500`, `text-sky-300`, and many more |
| `--font-*` | Font family utilities like `font-sans` |
| `--text-*` | Font size utilities like `text-xl` |
| `--font-weight-*` | Font weight utilities like `font-bold` |
| `--tracking-*` | Letter spacing utilities like `tracking-wide` |
| `--leading-*` | Line height utilities like `leading-tight` |
| `--tab-size-*` | Tab size utilities like `tab-github` |
| `--breakpoint-*` | Responsive breakpoint variants like `sm:*` |
| `--container-*` | Container query variants like `@sm:*` and size utilities like `max-w-md` |
| `--spacing-*` | Spacing and sizing utilities like `px-4`, `max-h-16`, and many more |
| `--radius-*` | Border radius utilities like `rounded-sm` |
| `--shadow-*` | Box shadow utilities like `shadow-md` |
| `--inset-shadow-*` | Inset box shadow utilities like `inset-shadow-xs` |
| `--drop-shadow-*` | Drop shadow filter utilities like `drop-shadow-md` |
| `--blur-*` | Blur filter utilities like `blur-md` |
| `--perspective-*` | Perspective utilities like `perspective-near` |
| `--zoom-*` | Zoom utilities like `zoom-compact` |
| `--aspect-*` | Aspect ratio utilities like `aspect-video` |
| `--ease-*` | Transition timing function utilities like `ease-out` |
| `--animate-*` | Animation utilities like `animate-spin` |

## Notes

- Theme variables are special CSS variables defined with `@theme` that influence which utility classes exist. Tailwind also generates regular CSS variables for them.
- Use `@theme` when a token should map to a utility class; use `:root` for regular CSS variables that should not have utilities. Theme variables must be defined top-level, not nested under selectors or media queries.
- Some utilities are static (`flex`, `object-cover`); many exist only because of theme variables. `--font-poppins` makes `font-poppins` available; `--breakpoint-3xl: 120rem` makes the `3xl:*` variant available.
- The official docs typography example writes `font-size: var(--text-2xl--line-height);`, a typo since that variable is a unitless line-height (`calc(2 / 1.5)`). This page corrects it to `font-size: var(--text-2xl);`; use `line-height: var(--text-2xl--line-height);` when a line height is needed.

### Default theme variables

`@import "tailwindcss"` includes (in `node_modules/tailwindcss/index.css`):

```css
@layer theme, base, components, utilities;

@import "./theme.css" layer(theme);
@import "./preflight.css" layer(base);
@import "./utilities.css" layer(utilities);
```

### Extending and overriding

```css
@import "tailwindcss";

@theme {
  --font-script: Great Vibes, cursive;
  --breakpoint-sm: 30rem;
}
```

Reset an entire namespace with `--color-*: initial;`, or the whole default theme with `--*: initial;`:

```css
@import "tailwindcss";

@theme {
  --*: initial;

  --spacing: 4px;

  --font-body: Inter, sans-serif;

  --color-lagoon: oklch(0.72 0.11 221.19);
  --color-coral: oklch(0.74 0.17 40.24);
  --color-driftwood: oklch(0.79 0.06 74.59);
  --color-tide: oklch(0.49 0.08 205.88);
  --color-dusk: oklch(0.82 0.15 72.09);
}
```

### Defining animation keyframes

Define `@keyframes` for `--animate-*` variables inside `@theme` to include them in output. To always include custom `@keyframes` regardless of use, define them outside `@theme`.

```css
@import "tailwindcss";

@theme {
  --animate-fade-in-scale: fade-in-scale 0.3s ease-out;

  @keyframes fade-in-scale {
    0% {
      opacity: 0;
      transform: scale(0.95);
    }
    100% {
      opacity: 1;
      transform: scale(1);
    }
  }
}
```

### Referencing other variables (`inline`)

With `@theme inline` the utility uses the variable value instead of referencing the theme variable. Without `inline`, `var(--font-sans)` is resolved where `--font-sans` is defined, so a variable defined deeper in the tree can be missed.

```css
@import "tailwindcss";

@theme inline {
  --font-sans: var(--font-inter);
}
```

```css
.font-sans {
  font-family: var(--font-inter);
}
```

### Generating all CSS variables (`static`)

By default only used CSS variables are generated. Use `static` to always generate all of them:

```css
@import "tailwindcss";

@theme static {
  --color-primary: var(--color-red-500);
  --color-secondary: var(--color-blue-500);
}
```

### Sharing across projects

Put theme variables in their own CSS file and `@import` it (a monorepo package or an npm package works):

```css
@import "tailwindcss";
@import "../brand/theme.css";
```

### Using theme variables

```css
@import "tailwindcss";

@layer components {
  .typography {
    p {
      font-size: var(--text-base);
      color: var(--color-gray-700);
    }

    h1 {
      font-size: var(--text-2xl);
      font-weight: var(--font-weight-semibold);
      color: var(--color-gray-950);
    }

    h2 {
      font-size: var(--text-xl);
      font-weight: var(--font-weight-semibold);
      color: var(--color-gray-950);
    }
  }
}
```

In arbitrary values, combine with `calc()`:

```html
<div class="relative rounded-xl">
  <div class="absolute inset-px rounded-[calc(var(--radius-xl)-1px)]">
    <!-- ... -->
  </div>
  <!-- ... -->
</div>
```

In JavaScript, use the CSS variables directly (for example with Motion), or read a resolved value:

```jsx
<motion.div animate={{ backgroundColor: "var(--color-blue-500)" }} />
```

```js
let styles = getComputedStyle(document.documentElement);
let shadow = styles.getPropertyValue("--shadow-xl");
```
