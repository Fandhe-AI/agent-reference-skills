# Oracle Database@Google Cloud IAM overview and roles

Oracle Database@Google Cloud integrates with Identity and Access Management (IAM) to control user and group access to Exadata Database and Autonomous AI Database resources. Roles are defined at the Google Cloud project level, so a `viewer` grant on Exadata Infrastructure gives viewer access to all Exadata Infrastructure instances and Exadata VM Clusters in that project. This page also merges the "grant access using IAM" steps.

## Signature / Usage

### Grant, modify or remove roles (Console steps summarized)

Roles are granted on the project IAM page: select **View by Principals**, then **GRANT ACCESS** (add principals and roles, **Save**), **Edit** (add or delete roles, **Save**) or **REMOVE ACCESS** (select principals, **Confirm**). You need the `Owner` or `Admin` role on the project to grant roles to another account. Principals are users, groups, domains or service accounts.

### Check access with a read-only command

Listing entitlements needs `oracledatabase.entitlements.list`, which is in `roles/oracledatabase.viewer` and `roles/oracledatabase.admin` (see the table below). Snippet taken from https://docs.cloud.google.com/sdk/gcloud/reference/oracle-database/entitlements/list (gcloud 593.0.0 help):

```bash
gcloud oracle-database entitlements list --location=us-east4
```

## Notes

- Source inconsistency: the source says "Broader roles include the more narrowly defined roles", while its own table gives `roles/oracledatabase.viewer` permissions that `roles/oracledatabase.admin` lacks (`*.listEffectiveTags` and `*.listTagBindings` on autonomousDatabases, cloudExadataInfrastructures, cloudVmClusters, dbSystems and entitlements, and `oracledatabase.pluggableDatabases.*` / `.get` / `.list`), and leaves the `.use` permission of the matching User role out of `cloudExadataInfrastructureAdmin` (`cloudExadataInfrastructures.use`), `exascaleDbStorageVaultAdmin` (`exascaleDbStorageVaults.use`), `goldenGateConnectionAdmin` (`goldenGateConnections.use`) and `goldenGateDeploymentAdmin` (`goldenGateDeployments.use`). Check the table for each permission you need; the IAM roles and permissions reference gives the same role assignments for these permissions (for example, `oracledatabase.cloudExadataInfrastructures.use` is in `roles/oracledatabase.admin`, `roles/oracledatabase.cloudExadataInfrastructureUser` and `roles/oracledatabase.cloudVmClusterAdmin`, not in `roles/oracledatabase.cloudExadataInfrastructureAdmin`).
- Role names in the source carry the prefix "Oracle Database@Google Cloud" (for example "Oracle Database@Google Cloud Autonomous Database Admin"); the Network / ODB Network / ODB Subnet / GoldenGate Connections User / GoldenGate Deployments User roles carry the prefix "Oracle Database@Google" instead. The prefix is dropped in the table above.
- Predefined roles can be granted to individuals, groups or service accounts; multiple roles can be granted to the same member and changed at any time. Granting at project level applies to all instances, clusters and databases in the project.
- Before granting, confirm that you hold `Owner` or `Admin` on the project (project IAM page, View by Principals).
- Removing access (REMOVE ACCESS) takes effect for the selected principals on the whole project; check which principals are selected before you confirm.
- IAM concepts in general (principals, policies, roles) are in `gcp-foundation`.
- Snippet taken from https://docs.cloud.google.com/sdk/gcloud/reference/oracle-database/entitlements/list (gcloud 593.0.0 help); the source page has no code. A role-listing command from the IAM gcloud group is intentionally not used here.
