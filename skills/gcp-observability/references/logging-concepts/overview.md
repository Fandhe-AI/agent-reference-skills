# Cloud Logging overview

Cloud Logging is a real-time log-management system with storage, search, analysis, and monitoring support. It automatically collects log data from Google Cloud resources; applications, on-premises resources, and resources from other cloud providers can also send log data to it. You can configure alerting policies so that Cloud Monitoring notifies you when certain kinds of events are reported in your log data, and you can determine where your log data is stored for regulatory or security reasons.

## Signature / Usage

### Write a test entry

Snippet taken from https://docs.cloud.google.com/logging/docs/write-query-log-entries-gcloud

```bash
gcloud logging write my-test-log "A simple entry."
```

### Collect log data

- Instrument your application with a client library, or let the Ops Agent send data written to `stdout` or `stderr` to your project.
- Collect logs of third-party applications such as `nginx` by installing the Ops Agent and configuring it for that application.

### Query, view, and analyze

- Logs Explorer: view individual log entries and find related ones. Entries are annotated when they are part of an error group or when trace data is available. Recommended for troubleshooting.
- Observability Analytics: query log data with SQL to find trends and patterns (for example, average latency of HTTP requests to a URL over time).

### Visualize and monitor

- Log-based alerting policy: notifies you when a particular message is part of a log entry (important but rare events, such as an audit log entry for a user accessing the security key of a service account, or a deployment message).
- Log-based metric plus an alerting policy: notifies you when a trend occurs. A log-based metric either counts the log entries that match a criterion, or extracts and organizes information such as response times into histograms.
- A preconfigured Cloud Logging dashboard shows the error rates of your Google Cloud services.

## Options / Props

### Log routing destinations

| Destination | Notes |
|---|---|
| Google Cloud project | A destination can be in a different resource from where the log data originates (for example, a log bucket in a different project). |
| Log bucket | |
| BigQuery dataset | |
| Cloud Storage bucket | Except for Rapid storage. |
| Pub/Sub topic | Supports third-party integrations such as Splunk or Datadog. |

### Categories of log data

| Category | Description |
|---|---|
| Platform | Written by Google Cloud services; help debug and troubleshoot issues. |
| Component | Generated by Google Cloud-provided software components that run on your systems (for example GKE components on your own VMs or data center); often used for user support. |
| Security | Answers "who did what, where, and when": Cloud Audit Logs and Access Transparency logs. |
| User-written | Written by custom applications and services via the Ops Agent, the Cloud Logging API, or the client libraries. |
| Multicloud and Hybrid-cloud | Log data from other cloud providers such as Microsoft Azure and from on-premises infrastructure. |

## Notes

- Categories of log data: The categories are not mutually exclusive.
- By default, Google Cloud projects, billing accounts, folders, and organization resources automatically store the log data that originates in the resource; you don't have to configure the storage location.
- Log entries are stored for a specified length of time and are then deleted (see the logs retention periods on the Cloud Logging quotas and limits page).
- IAM permissions and roles control access to log buckets; you can grant predefined roles or create custom roles.
- Pricing: see the Google Cloud Observability pricing page (https://cloud.google.com/products/observability/pricing).
- Cloud Logging is the log backend; the `pino` skill covers the pino logger itself.
- The source also links to the instrumentation guidance at https://docs.cloud.google.com/stackdriver/docs/instrumentation/choose-approach.
