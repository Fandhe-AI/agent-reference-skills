# About Application Monitoring

Application Monitoring is the Google Cloud solution for application observability. It creates dashboards for App Hub applications, services and workloads, and shows a topology view of the application. App Hub tells you which resources the application uses; Application Monitoring tells you how they perform and helps diagnose issues, starting the investigation from the application rather than from resources.

## Signature / Usage

### Application label format in log entries

The source page has no code block. Snippet taken from https://docs.cloud.google.com/stackdriver/docs/observability/application-monitoring-labels: when the application runs on supported infrastructure, Application Monitoring attaches application-specific labels to telemetry, for example the `apphub` field of a `LogEntry`:

```text
apphub: {
  application: {
    container: "projects/my-project"
    id: "my-app"
    location: "my-app-location"
  }
  workload: {
    criticalityType: "MEDIUM"
    environmentType: "STAGING"
    id: "my-workload-id"
  }
}
```

## Options / Props

### What the dashboards display

| Data | Source |
|---|---|
| Application information | Location, criticality, owners. |
| Open alerts | Alerting policies associated with the application. |
| Log and metric data | Generated by supported infrastructure; metrics include golden signals (error rates, traffic) and select metrics. |
| Trace data | Generated by instrumented applications: span and service names, latency, error rates. |

### Get started

| Step | Action |
|---|---|
| 1 | Create the application and register services and workloads in App Hub (or deploy with Application Design Center). |
| 2 | Configure the observability scope (see Set up Application Monitoring). |
| 3 | Instrument with OpenTelemetry or use Google Cloud Managed Service for Prometheus so application-generated metrics and traces include application labels. |
| 4 | Open the Application Monitoring dashboards. |
| 5 | View the application topology graph. |

## Notes

- Dashboards support search and filtering, and telemetry can be filtered by criticality and environment. Once deployed, the service discovers the application and builds dashboards automatically.
- For workloads on Google Kubernetes Engine, the dashboards show OpenTelemetry-defined metrics for traffic, latency and error rate golden signals.
- The Logs Explorer, Metrics Explorer and Trace Explorer pages can filter and aggregate data by the application labels.
