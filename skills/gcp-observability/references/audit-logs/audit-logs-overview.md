# Cloud Audit Logs overview

Google Cloud services write audit logs that record administrative activities and resource access ("who did what, where, and when"). Cloud Audit Logs provides four audit log types for each Google Cloud project, folder, and organization: Admin Activity, Data Access, System Event, and Policy Denied. Log entries written by Cloud Audit Logs are immutable.

## Signature / Usage

### Audit log names

```text
projects/PROJECT_ID/logs/cloudaudit.googleapis.com%2Factivity
projects/PROJECT_ID/logs/cloudaudit.googleapis.com%2Fdata_access
projects/PROJECT_ID/logs/cloudaudit.googleapis.com%2Fsystem_event
projects/PROJECT_ID/logs/cloudaudit.googleapis.com%2Fpolicy

folders/FOLDER_ID/logs/cloudaudit.googleapis.com%2Factivity
folders/FOLDER_ID/logs/cloudaudit.googleapis.com%2Fdata_access
folders/FOLDER_ID/logs/cloudaudit.googleapis.com%2Fsystem_event
folders/FOLDER_ID/logs/cloudaudit.googleapis.com%2Fpolicy

billingAccounts/BILLING_ACCOUNT_ID/logs/cloudaudit.googleapis.com%2Factivity
billingAccounts/BILLING_ACCOUNT_ID/logs/cloudaudit.googleapis.com%2Fdata_access
billingAccounts/BILLING_ACCOUNT_ID/logs/cloudaudit.googleapis.com%2Fsystem_event
billingAccounts/BILLING_ACCOUNT_ID/logs/cloudaudit.googleapis.com%2Fpolicy

organizations/ORGANIZATION_ID/logs/cloudaudit.googleapis.com%2Factivity
organizations/ORGANIZATION_ID/logs/cloudaudit.googleapis.com%2Fdata_access
organizations/ORGANIZATION_ID/logs/cloudaudit.googleapis.com%2Fsystem_event
organizations/ORGANIZATION_ID/logs/cloudaudit.googleapis.com%2Fpolicy
```

### Query all audit logs in the Logs Explorer

Either query selects all audit logs:

```text
logName:"cloudaudit.googleapis.com"
```

```text
protoPayload."@type"="type.googleapis.com/google.cloud.audit.AuditLog"
```

### Read audit logs with gcloud

Supply a valid resource identifier in each log name. The project identifier must refer to the currently selected project.

```bash
gcloud logging read "logName : projects/PROJECT_ID/logs/cloudaudit.googleapis.com" \
    --project=PROJECT_ID
```

```bash
gcloud logging read "logName : folders/FOLDER_ID/logs/cloudaudit.googleapis.com" \
    --folder=FOLDER_ID
```

```bash
gcloud logging read "logName : organizations/ORGANIZATION_ID/logs/cloudaudit.googleapis.com" \
    --organization=ORGANIZATION_ID
```

```bash
gcloud logging read "logName : billingAccounts/BILLING_ACCOUNT_ID/logs/cloudaudit.googleapis.com" \
    --billing-account=BILLING_ACCOUNT_ID
```

Add the `--freshness` flag to read logs that are more than 1 day old (default `1d`).

### Read audit logs with the Logging API

Request body for the `entries.list` method:

```json
{
  "resourceNames": [
    "projects/PROJECT_ID"
  ],
  "pageSize": 5,
  "filter": "logName : projects/PROJECT_ID/logs/cloudaudit.googleapis.com"
}
```

## Options / Props

### Audit log types

| Type | Log name suffix | Written when | Configurable | Chargeable |
|------|-----------------|--------------|--------------|------------|
| Admin Activity | `%2Factivity` | User-driven API calls or other actions that modify the configuration or metadata of resources | No; always written. You can't configure, exclude, or disable them, even if the Cloud Logging API is disabled | No |
| Data Access | `%2Fdata_access` | API calls that read configuration or metadata, and user-driven calls that create, modify, or read user-provided data | Yes; disabled by default except for BigQuery, must be explicitly enabled | Yes |
| System Event | `%2Fsystem_event` | Google Cloud systems and managed service agents modify resource configuration (not driven by direct user action, for example MIG autoscaling) | No; always written. You can't configure, exclude, or disable them | No |
| Policy Denied | `%2Fpolicy` | A service denies access to a user or service account because of a security policy violation | Generated by default and can't be disabled; you can use exclusion filters to prevent storage in Cloud Logging | Yes (project is charged for log storage) |

### Roles to view audit logs

| Role | What it allows |
|------|----------------|
| Logs Viewer (`roles/logging.viewer`) | Read-only access to Admin Activity, Policy Denied, and System Event audit logs. Cannot view Data Access audit logs in the `_Default` bucket |
| Private Logs Viewer (`roles/logging.privateLogViewer`) | Access to all logs in the `_Required` and `_Default` buckets, including Data Access logs. Includes the Logs Viewer permissions |

### Caller identity and IP redaction

| Case | Behavior |
|------|----------|
| Successful access or any write operation | Caller's principal email address isn't redacted |
| Read-only operation failing with "permission denied" | Principal email might be redacted unless the caller is a service account |
| Legacy App Engine API | Identities aren't collected |
| BigQuery | Caller identities, IP addresses, and some resource names are redacted unless certain conditions are met |
| Cloud Storage usage logs enabled | The generated Data Access audit log for the bucket has its caller identity redacted |
| Firestore | With a JWT for third-party authentication, `thirdPartyPrincipal` includes the token's header and payload (for Firebase Authentication, the request's auth token) |
| VPC Service Controls (Policy Denied) | Parts of caller emails might be replaced by `...`; some `google.com` caller emails are replaced by `google-internal` |
| Organization Policy | Parts of caller emails might be replaced by `...` |

| `RequestMetadata.callerIp` | Value |
|----------------------------|-------|
| Caller from the internet | Public IPv4 or IPv6 address |
| Calls inside the internal production network from one Google Cloud service to another (including service agents) | Redacted to "private" |
| Compute Engine VM with an external IP (including Google-managed VMs such as GKE nodes) | External address of the VM; in multi-service flows (for example Cloud Logging calling Cloud KMS) the immediate caller's origin is propagated unless identity delegation is configured, so an external address might appear instead of "private" |
| Compute Engine VM without an external IP, same organization or project as the accessed resource | VM's internal IPv4 address |
| Compute Engine VM without an external IP, otherwise | Redacted to "gce-internal-ip" |

## Notes

- Admin Activity and System Event audit logs are always stored in the `_Required` bucket of the project where they were generated; you can't prevent their storage or configure the sink that routes them to `_Required`. This page does not state the `_Required` retention period; it refers to [Quotas and limits: Logs retention periods](https://docs.cloud.google.com/logging/quotas#logs_retention_periods). The best-practices page says Cloud Logging can be configured to retain logs between 1 day and 3650 days with custom retention rules.
- If you route Admin Activity and System Event audit logs to a different project, they don't pass through the destination project's `_Default` or `_Required` sink and aren't stored there; create a log sink in the destination project to store them.
- `_Default` buckets by default store enabled Data Access audit logs and Policy Denied audit logs. To keep Data Access logs out of `_Default`, disable them; to keep Policy Denied logs out, exclude them by modifying the sink filter. Excluded logs are not stored in the bucket, so try exclusion changes on a disposable project first.
- Data Access audit logs are written to the project whose data is accessed and can generate large volumes; enabling them might add log-usage charges. They also help the Cloud Customer Care team troubleshoot, so keeping them enabled is recommended. Resources with `allUsers` or `allAuthenticatedUsers` policies, or accessible without logging in, don't generate audit logs.
- Audit log entries are `LogEntry` objects whose `protoPayload` holds an `AuditLog` object; the caller identity is in `AuthenticationInfo`. Audit logs can contain principal emails, IP addresses, and request / response data; grant `roles/logging.privateLogViewer` sparingly.
- Google Cloud MCP servers write Data Access audit logs in the format `SERVICE_NAME.googleapis.com/mcp`; enable them by turning on audit logging for `mcp.googleapis.com` in the IAM `AuditConfig` object.
- Billing-account audit logs can only be viewed with the Google Cloud CLI or the Logging API, not the console.
- The source also shows the Logs Explorer console steps and the "Try this API" form for `entries.list`. Pricing is not copied; see Google Cloud Observability pricing.
