# Find and explore traces

The Trace Explorer page shows aggregate latency, filters spans and lets you inspect individual traces. It queries the trace data of your project by default, or of several projects through a trace scope. For custom SQL aggregate analysis use Observability Analytics or BigQuery.

## Signature / Usage

### Find MCP server spans

Add an attribute filter with key `mcp.method.name` and value `tools/call`. Matching span names follow the OpenTelemetry semantic conventions for MCP:

```text
tools/call NAME
```

`NAME` is the invoked endpoint, for example `roll_dice`.

### Filter bar attribute keys

Custom filter keys use the same syntax as span attribute keys, for example `host.id` or `/http/status_code` with value `200`.

## Options / Props

### Span filters

| Filter | Source |
|---|---|
| OpenTelemetry service | `service.name` attribute |
| Span name | Name of the span |
| Span status | OpenTelemetry SpanStatus |
| Duration | Duration of the span |
| Span kind | OpenTelemetry SpanKind |
| App Hub application | `gcp.apphub.application.id` resource attribute |
| App Hub service | `gcp.apphub.service.id` resource attribute |
| App Hub workload | `gcp.apphub.workload.id` resource attribute |

### Span details tabs

| Tab | Content |
|---|---|
| Inputs/Outputs | Events following the OpenTelemetry GenAI semantic conventions; shown only when the span has them |
| Attributes | Attributes attached to the span; GenAI attributes begin with `gen_ai` |
| Logs \& Events | Events and log entries whose `trace_id` and `span_id` match the span; only entries you may view |
| Stacktraces | Available stacktraces |
| Metadata \& Links | Span ID (64-bit integer other than 0), parent span ID, project ID, start / end time, links, instrumentation scope, schema |

### Required permissions

| Purpose | Permission |
|---|---|
| Select a trace scope | `cloudtrace.traceScopes.[get, list]` |
| Read the default trace scope | `observability.scopes.get` |

## Notes

- Grant Cloud Trace User (`roles/cloudtrace.user`) on the project. It can take several minutes after the first trace is written before data is visible.
- Scope: the default trace scope of a new project lists the `_AllSpans` view of the project. Setting the first Scope menu to Project or `_Default` is equivalent. Data from projects where you lack permission on the view is not displayed. A valid trace ID with an empty result may be stored in a project that is not searched; update the Scope.
- Span data is stored for 30 days.
- Filtering by App Hub application requires `gcp.apphub.application.{container,id,location}` and `gcp.apphub.{workload,service}.{criticality_type,environment_type,id}` resource attributes generated by instrumentation.
- Find in Trace searches plain text in span name, service or workload name and attributes only, not logs, events or metadata; matching is case-insensitive.
- Prompts and responses can be text attributes or multimodal data in a Cloud Storage bucket correlated through trace and log data. They can contain personal data; limit who can view them. Viewing log entries requires `logging.logEntries.list`.
- The source also shows Console click-paths, charts (span duration percentiles 50th / 90th / 95th / 99th, span rate) and DAG view; omitted.
