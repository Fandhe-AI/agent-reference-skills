# `drizzle-kit migrate`

Applies SQL migrations generated by `drizzle-kit generate` (code-first migrations approach).

## Signature / Usage

```bash
npx drizzle-kit migrate --dialect=postgresql --url=postgresql://user:password@host:port/dbname
```

Requires `dialect` and database connection credentials, either via `drizzle.config.ts` or CLI options.

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  dbCredentials: {
    url: "postgresql://user:password@host:port/dbname"
  },
});
```

It reads `.sql` migration files in the migrations folder, fetches applied-migration history from the database, decides which new migrations to run, applies them, and logs them to the migrations table.

## Options / Props

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `dialect` | string | — (required) | Database dialect |
| `migrations.table` | string | `__drizzle_migrations` | Migrations log table name |
| `migrations.schema` | string | `drizzle` | Migrations log table schema |
| `config` | string | `drizzle.config.ts` | Configuration file path |

## Notes

- Migration (v0 → v1): the migrations log table gained two new columns — `name` (full migration folder name, e.g. `20250220153045_brave_wolverine`) and `applied_at` (timestamp; pre-existing rows backfilled with `NULL`). Migrations are now matched by full folder name instead of timestamp, and the migrator applies **every** missing migration regardless of timestamp ordering (previously only migrations newer than the last applied one were considered). Running `drizzle-kit up` performs the table upgrade/backfill.
