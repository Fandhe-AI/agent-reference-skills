# TypeScript 5.8

Granular checks for branches in return expressions, `require()` of ESM under `nodenext`, `--module node18`, `--erasableSyntaxOnly`, `--libReplacement`, and preserved computed property names in declaration files.

## Signature / Usage

```ts
declare const untypedCache: Map<any, any>;

function getUrlObject(urlString: string): URL {
    return untypedCache.has(urlString) ?
        untypedCache.get(urlString) :
        urlString;
    //  ~~~~~~~~~
    // error! Type 'string' is not assignable to type 'URL'.
}
```

## Options / Props

| Feature | Description |
|---------|-------------|
| Return-expression branch checks | Each branch of a conditional directly inside a `return` is checked against the declared return type |
| `--module nodenext` + `require()` of ESM | No error on `require()` of ES modules (Node.js 22 behavior; not allowed for ESM with top-level `await`) |
| `--module node18` | Stable Node.js 18 reference: `require()` of ESM disallowed; import assertions allowed |
| `--erasableSyntaxOnly` | Errors on TypeScript-only constructs with runtime behavior (enums, runtime namespaces, parameter properties, `import =` / `export =`) |
| `--libReplacement` | `--libReplacement false` disables lookup of `@typescript/lib-*` replacement packages |
| Computed property names in `.d.ts` | Entity names (`propName`, `a.b.c`) are preserved in class computed property names |

## Notes

- `--erasableSyntaxOnly` is typically combined with `--verbatimModuleSyntax`; it matches Node.js 23.6 `--experimental-strip-types` limits.

```ts
class C {
    constructor(public x: number) { }
    //          ~~~~~~~~~~~~~~~~
    // error! This syntax is not allowed when 'erasableSyntaxOnly' is enabled.
}
```

- Under `--module nodenext`, import assertions (`assert { type: "json" }`) are an error; use `with { type: "json" }`.
- A declaration file generated by 5.8 with preserved computed property names may not be backward compatible with 5.7 or earlier. Such code remains an error under `--isolatedDeclarations`.
- Added (5.8): `--libReplacement`; 5.8 notes "in the future `--libReplacement false` may become the default" (it became the default in 6.0).
- Optimizations: path normalization without array allocation; skipping option re-validation on edits that do not change project structure.
