# Errors and exceptions

Workers error codes, common runtime errors, upload errors, and how to debug them with metrics, Workers Logs, `wrangler tail`, and third-party logging.

## Signature / Usage

Third-party logging with `ctx.waitUntil()` so the log request completes:

```js
export default {
	async fetch(request, env, ctx) {
		function postLog(data) {
			return fetch("https://log-service.example.com/", {
				method: "POST",
				body: data,
			});
		}

		try {
			return await fetch(request);
		} catch (err) {
			// Without ctx.waitUntil(), the `postLog` function may or may not complete.
			ctx.waitUntil(postLog(err.stack));
			return new Response("Internal Server Error", { status: 500 });
		}
	},
};
```

Go to origin on error:

```js
export default {
	async fetch(request, env, ctx) {
		ctx.passThroughOnException();
		// an error here will return the origin response, as if the Worker wasn't present
		return fetch(request);
	},
};
```

Avoid losing `this` (the "Illegal invocation" error): do not destructure `ctx`.

```js
export default {
	async fetch(request, env, ctx) {
		// directly calling the method on ctx avoids the error
		ctx.waitUntil(somePromise);

		// alternatively re-binding to ctx via apply, call, or bind avoids the error
		const { waitUntil } = ctx;
		waitUntil.apply(ctx, [somePromise]);
		waitUntil.call(ctx, somePromise);
		const reboundWaitUntil = waitUntil.bind(ctx);
		reboundWaitUntil(somePromise);

		return fetch(request);
	},
};
```

Failing version (destructuring loses `this`):

```js
export default {
	async fetch(request, env, ctx) {
		// destructuring ctx makes waitUntil lose its 'this' reference
		const { waitUntil } = ctx;
		// waitUntil errors, as it has no 'this'
		waitUntil(somePromise);

		return fetch(request);
	},
};
```

"The script will never generate a response" (Cause 1, unresolved Promise; uncommenting `setTimeout(resolve, 0)` fixes it):

```js
export default {
	fetch(req) {
		let response = new Response("Example response");
		let { promise, resolve } = Promise.withResolvers();

		// If the promise is not resolved, the Workers runtime will
		// recognize this and throw an error.

		// setTimeout(resolve, 0)

		return promise.then(() => response);
	},
};
```

Cause 2, WebSocket never closed:

```js
async function handleRequest(request) {
	let webSocketPair = new WebSocketPair();
	let [client, server] = Object.values(webSocketPair);
	server.accept();

	server.addEventListener("close", () => {
		// This missing line would keep a WebSocket connection open indefinitely
		// and results in "The script will never generate a response" errors
		// server.close();
	});

	return new Response(null, {
		status: 101,
		webSocket: client,
	});
}
```

"Cannot perform I/O on behalf of a different request" (caching an I/O object in global scope fails; store data instead):

```js
let cachedData = null;

export default {
	async fetch(request, env, ctx) {
		if (cachedData) {
			return new Response(cachedData);
		}
		const response = new Response("Hello, world!");
		cachedData = await response.text();
		return new Response(cachedData, response);
	},
};
```

## Options / Props

Error pages generated by Workers:

| Error code | Meaning |
| --- | --- |
| `1101` | Worker threw a JavaScript exception. |
| `1102` | Worker exceeded CPU time limit. |
| `1103` | Worker execution is blocked. Check whether a Workers spending limit was reached. If no spending limit explains the block, contact Cloudflare Support. |
| `1019` | Worker hit loop limit. |
| `1021` | Worker has requested a host it cannot access. |
| `1022` | Cloudflare has failed to route the request to the Worker. |
| `1024` | Worker cannot make a subrequest to a Cloudflare-owned IP address. |
| `1027` | Worker exceeded free tier daily request limit. |
| `1042` | Worker tried to fetch from another Worker on the same zone, which is only supported when the `global_fetch_strictly_public` compatibility flag is used. Also returned for a `workers.dev` URL with no Worker serving it, such as a Worker with its `workers.dev` route disabled. |
| `10162` | Module has an unsupported Content-Type. |

Errors on Worker upload:

| Error code | Meaning |
| --- | --- |
| `10006` | Could not parse your Worker's code. |
| `10007` | Worker or workers.dev subdomain not found. |
| `10015` | Account is not entitled to use Workers. |
| `10016` | Invalid Worker name. |
| `10021` | Validation Error (top-level scope failed to load/run; e.g. `SyntaxError`, script startup exceeded CPU time limit (1s) or memory limit (128 MB)). |
| `10026` | Could not parse request body. |
| `10027` | The uploaded Worker exceeded the Worker size limits. |
| `10035` | Multiple attempts to modify a resource at the same time |
| `10037` | An account has exceeded the number of Workers allowed. |
| `10052` | A binding is uploaded without a name. |
| `10054` | A environment variable or secret exceeds the size limit. |
| `10055` | The number of environment variables or secrets exceeds the limit/Worker. |
| `10056` | Binding not found. |
| `10057` | An `inherit` binding could not be resolved. |
| `10068` | The uploaded Worker has no registered event handlers. |
| `10069` | The uploaded Worker contains event handlers unsupported by the Workers runtime. |

Runtime errors (no error page; visible in logs):

| Error message | Meaning |
| --- | --- |
| `Network connection lost` | Connection failure. Catch a `fetch` or binding invocation and retry it. |
| `Memory limit`<br>`would be exceeded`<br> `before EOF` | Trying to read a stream or buffer that would take you over the memory limit. |
| `daemonDown` | A temporary problem invoking the Worker. |

Metrics: **Errors by invocation status**

| Error | Meaning |
| --- | --- |
| `Uncaught Exception` | Your Worker code threw a JavaScript exception during execution. |
| `Exceeded CPU Time Limits` | Worker exceeded CPU time limit or other resource constraints. |
| `Exceeded Memory` | Worker exceeded the memory limit during execution. |
| `Internal` | An internal error occurred in the Workers runtime. |

**Client disconnected by type**

| Client Disconnects | Meaning |
| --- | --- |
| `Response Stream Disconnected` | Connection was terminated during the deferred proxying stage of a Worker request flow. Commonly appears for longer-lived connections such as WebSockets. |
| `Cancelled` | The client disconnected or canceled the request before the Worker finished responding. |

## Notes

- Other `11xx` errors generally indicate a Workers runtime problem; check https://www.cloudflarestatus.com.
- Loop limit: a Worker cannot call itself or another Worker more than 16 times. The `CF-EW-Via` header holds an integer of invocations left, decremented per invocation; at zero a `1019` error is returned.
- "The script will never generate a response" is a `1101` raised when all code for the request has executed, no events remain in the event loop, and no Response was returned. Cause 1: a Promise never resolved/rejected (enforce the `no-floating-promises` ESLint rule). Cause 2: a WebSocket server side never closed; with the `web_socket_auto_reply_to_close` compatibility flag (enabled by default on compatibility dates on or after `2026-04-07`) the runtime completes the close handshake, so the example applies to older compatibility dates.
- "Illegal invocation" (`TypeError: Illegal invocation: function called with incorrect this reference`) is typically from destructuring runtime objects such as `ctx` and losing `this`.
- "Cannot perform I/O on behalf of a different request": I/O objects (streams, request/response bodies) created in one request cannot be used from another request's handler; commonly from caching a Request/Response in global scope. For shared state use Durable Objects; for caching data use Workers KV.
- Inherit binding errors (10057): an `inherit` binding copies a binding from an earlier version. Script upload endpoints (Upload Worker Module, Upload Version) inherit from the most recently uploaded version (not always the deployed one) and return 10057 when `version_id` is anything other than `"latest"`, or when no earlier version exists or lacks the binding and the request sets `bindings_inherit=strict`. Without `strict` they drop an unresolvable `inherit` binding. The beta Workers API Versions endpoints accept a version ID and return 10057 when `version_id` is not a version ID, a version ID prefix of at least eight characters, or `"latest"`, the version does not exist, or lacks the binding.
- Workers Logs filter for errors: `$metadata.error EXISTS`; to find uncaught exceptions: `$workers.outcome = "exception"`. Outcome values are listed in the Workers Trace Event reference (https://developers.cloudflare.com/logs/logpush/logpush-job/datasets/account/workers_trace_events/#outcome).
- `wrangler tail`: exceptions appear in the `exceptions` field of the returned JSON.
- Floating promises (neither awaited, returned, nor passed to `ctx.waitUntil()`) may be canceled when the invocation completes; a Worker invocation is not complete while it is still streaming a response body.
- `ctx.passThroughOnException()` forwards requests for unhandled exceptions in Worker code, not errors from the origin `fetch()`. When proxying to an origin wrap `fetch(request)` in `try...catch` and return a `5xx`; if the origin `fetch()` throws after consuming the request body, the body cannot be replayed.
- Rust Workers: the Wasm Coredump Service (https://github.com/cloudflare/wasm-coredump) collects coredumps persisted to logs, Sentry, or R2 for analysis with wasmgdb.
- Enable source maps so exception stacks point to original files and lines.
- Service Workers syntax variants are deprecated; use Module Workers.
- The client can be any application or service, including another Worker or a Pages Function. For example, if Worker A stops waiting for Worker B, Worker B may report Client Disconnected too. The official page points to "Find out why a request was canceled" in the service bindings HTTP docs (see cloudflare-workers) to check both sets of logs.
