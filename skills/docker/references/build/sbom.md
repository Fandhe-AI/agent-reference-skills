# SBOM attestations

SBOM attestations verify the software artifacts an image contains and the artifacts used to create it (name, version, license type, authors, unique package identifier). SBOMs generated by BuildKit follow the SPDX standard and attach to the image as a JSON-encoded SPDX document in the in-toto SPDX predicate format.

## Signature / Usage

```console
$ docker buildx build --tag <namespace>/<image>:<version> \
    --attest type=sbom --push .
```

`--sbom=true` is a shorthand for `--attest type=sbom`.

Verify before pushing by building with the `local` exporter; the SBOM is written as `sbom.spdx.json` in the output root:

```console
$ docker buildx build \
  --sbom=true \
  --output type=local,dest=out .
$ ls -1 ./out | grep sbom
sbom.spdx.json
```

## Notes

### Arguments

By default BuildKit scans only the final stage, so build-time dependencies from earlier stages or the build context are not included. Set the `BUILDKIT_SBOM_SCAN_CONTEXT` and `BUILDKIT_SBOM_SCAN_STAGE` build arguments to widen the scope. They can be global (after the syntax directive, before the first `FROM`) or per stage.

```dockerfile
# syntax=docker/dockerfile:1
ARG BUILDKIT_SBOM_SCAN_CONTEXT=true
FROM alpine AS build
# ...
```

```console
$ docker buildx build --tag <image>:<version> \
    --attest type=sbom \
    --build-arg BUILDKIT_SBOM_SCAN_CONTEXT=false .
```

| Value | Description |
| --- | --- |
| `BUILDKIT_SBOM_SCAN_STAGE=true` | Enables scanning for the current stage |
| `BUILDKIT_SBOM_SCAN_STAGE=false` | Disables scanning for the current stage |
| `BUILDKIT_SBOM_SCAN_STAGE=base,bin` | Enables scanning for the stages named `base` and `bin` |

```dockerfile
# syntax=docker/dockerfile:1
FROM alpine as hugo
ARG BUILDKIT_SBOM_SCAN_STAGE=true
WORKDIR /src
COPY <<config.yml ./
title: My Hugo website
config.yml
RUN apk add --upgrade hugo && hugo

FROM scratch
COPY --from=hugo /src/public /
```

With the `local` exporter this produces `sbom.spdx.json` and `sbom-hugo.spdx.json`.

### Inspecting SBOMs

```console
$ docker buildx imagetools inspect <namespace>/<image>:<version> \
    --format "{{ json .SBOM.SPDX }}"
$ docker buildx imagetools inspect <namespace>/<image>:<version> \
    --format "{{ range .SBOM.SPDX.packages }}{{ .name }}@{{ .versionInfo }}{{ println }}{{ end }}"
```

For a multi-platform image: `--format '{{ json (index .SBOM "linux/amd64").SPDX }}'`.

### SBOM generator

BuildKit uses a scanner plugin; by default the BuildKit Syft scanner (built on Anchore's Syft). Choose another with the `generator` option, an image implementing the BuildKit SBOM scanner protocol:

```console
$ docker buildx build --attest type=sbom,generator=<image> .
```

### Other notes

- `BUILDKIT_SBOM_SCAN_CONTEXT` and `BUILDKIT_SBOM_SCAN_STAGE` are special: no variable substitution, and they cannot be set from `ENV`; the only way is an explicit `ARG` in the Dockerfile. Passing `--build-arg` without declaring the `ARG` has no effect.
- Only stages that are built are scanned; stages that are not dependencies of the target are skipped.
- An SBOM attestation uses `predicateType` `https://spdx.dev/Document` with `spdxVersion` `SPDX-2.2` in the official example.
