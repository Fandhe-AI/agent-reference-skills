# Windows App SDK: Deploy Framework-Dependent Packaged Apps

Deployment guidance for MSIX-packaged (framework-dependent) apps that use the Windows App SDK: declaring the Framework package dependency and calling the Deployment API.

## Signature / Usage

```csharp
using Microsoft.Windows.ApplicationModel.WindowsAppRuntime;

// Check current deployment status, then install missing runtime packages
var deploymentResult = DeploymentManager.Initialize();
if (deploymentResult.ExtendedError != 0)
{
    // handle installation failure
}
```

## Options / Props

| Requirement | Detail |
| --- | --- |
| VCLibs framework package | Required dependency for packaged apps. |
| .NET 6+ | Required for C# apps. |
| `PackageDependency` element | Auto-generated by WinUI 3 project templates; declare manually via `PackageReference` in `.wapproj` when building the package manually. |
| Deployment API | `Microsoft.Windows.ApplicationModel.WindowsAppRuntime.DeploymentManager` — `GetStatus` and `Initialize`. Required to deploy the Main and Singleton packages (not declarable via package manifest). |
| `packageManagement` restricted capability | Required (or full trust) to call the Deployment API to install Main/Singleton package dependencies. |

Common Deployment API error codes:

| Error code | Name | Common cause |
| --- | --- | --- |
| `0x80070005` | ACCESS_DENIED | App isn't full trust / missing `packageManagement` capability |
| `0x80073CF0` | ERROR_INSTALL_OPEN_PACKAGE_FAILED | MSIX package corrupted or inaccessible |
| `0x80073CF3` | ERROR_INSTALL_PREREQUISITE_FAILED | Missing/incompatible dependency (e.g. VCLibs) |
| `0x80073D06` | ERROR_PACKAGES_IN_USE | Packages in use; close apps using the runtime and retry |
| `0x80073CFB` | ERROR_PACKAGE_ALREADY_EXISTS | Informational — version already registered |
| `0x80073CF9` | ERROR_INSTALL_FAILED | General failure — check Event Viewer logs |

## Notes

- Call `DeploymentManager.Initialize` after process init but before using Singleton-dependent features (e.g. push notifications); call it only once.
- The Visual Studio project property `<WindowsAppSdkDeploymentManagerInitialize>` defaults to `true`, auto-generating this call — set it to `false` to call `Initialize` explicitly.
- Diagnostic event logs live under **Event Viewer > Applications and Services Logs > Microsoft > Windows > AppxDeployment-Server**.
