# samples

| Name | Description | Path |
| --- | --- | --- |
| Vector Add Kernel | Define a `__global__` kernel, launch it with `<<<>>>` grid/block configuration, and check for launch errors. | [vector-add-kernel.md](./vector-add-kernel.md) |
| Explicit Memory Transfer | Allocate device memory with `hipMalloc`, copy explicitly with `hipMemcpy`, and use pinned host memory (`hipHostMalloc`) to speed up transfers. | [explicit-memory-transfer.md](./explicit-memory-transfer.md) |
| Shared Memory Tiled Matmul | Tile a matrix multiplication kernel through `__shared__` memory with `__syncthreads()` barriers between the load and compute phases. | [shared-memory-tiled-matmul.md](./shared-memory-tiled-matmul.md) |
| Dynamic Shared Memory | Declare an `extern __shared__` array whose size is determined at launch time rather than compiled in, and pass the byte size as the third `<<<>>>` launch parameter. | [dynamic-shared-memory.md](./dynamic-shared-memory.md) |
| Unified Memory | Allocate memory accessible from both host and device with `hipMallocManaged`, then use `hipMemPrefetchAsync` and `hipMemAdvise` to steer the migration behavior of the unified memory pages. | [unified-memory.md](./unified-memory.md) |
| Stream Ordered Allocation | Allocate and free device memory with stream-ordered semantics using `hipMallocAsync` / `hipFreeAsync`, and tune a memory pool's retention behavior with `hipMemPoolSetAttribute`. | [stream-ordered-allocation.md](./stream-ordered-allocation.md) |
| Stream Overlap | Use multiple `hipStream_t` streams so that per-stream memory transfers and kernel launches on independent data can overlap instead of serializing on the default stream. | [stream-overlap.md](./stream-overlap.md) |
| HIP Graph Stream Capture | Record a sequence of asynchronous operations on a stream into a `hipGraph_t` with `hipStreamBeginCapture`/`hipStreamEndCapture`, then instantiate and replay it with `hipGraphLaunch`. | [hip-graph-stream-capture.md](./hip-graph-stream-capture.md) |
| HIP Graph Explicit Nodes | Build a `hipGraph_t` node-by-node with `hipGraphAddKernelNode`, `hipGraphAddMemcpyNode1D`, and friends, wiring explicit dependency arrays between nodes instead of relying on stream capture. | [hip-graph-explicit-nodes.md](./hip-graph-explicit-nodes.md) |
| Cooperative Groups Reduction | Use `cooperative_groups::thread_block` and `tiled_partition<>()` to express a reduction generically over a whole block or over sub-block tiles, without hard-coding warp-level shuffles. | [cooperative-groups-reduction.md](./cooperative-groups-reduction.md) |
| Warp Shuffle Reduction | Exchange values between threads in the same wavefront/warp with `__shfl`, and query the architecture's actual `warpSize` at runtime rather than assuming a fixed width. | [warp-shuffle-reduction.md](./warp-shuffle-reduction.md) |
| Multi-GPU Peer-to-Peer | Check peer access support with `hipDeviceCanAccessPeer` before enabling it with `hipDeviceEnablePeerAccess`, then copy device memory directly between two GPUs without staging through the host. | [multi-gpu-peer-to-peer.md](./multi-gpu-peer-to-peer.md) |
| Occupancy Tuning | Use `hipOccupancyMaxPotentialBlockSize` to have the runtime suggest a block size for a kernel, and `hipOccupancyMaxActiveBlocksPerMultiprocessor` to compare the resulting theoretical occupancy against a manually-chosen block size. | [occupancy-tuning.md](./occupancy-tuning.md) |
| Hipify CUDA to HIP | Port a `.cu` CUDA source to portable HIP by mapping `cuda*` API names to their `hip*` equivalents one-for-one, as `hipify-perl`/`hipify-clang` do automatically. | [hipify-cuda-to-hip.md](./hipify-cuda-to-hip.md) |
| Event Timing | Bracket device work with `hipEvent_t` records and measure elapsed time with `hipEventElapsedTime`, synchronizing on the stop event before reading the result. | [event-timing.md](./event-timing.md) |
| Device Query | Read GPU capabilities at runtime with `hipGetDeviceProperties`, including the architecture identifier `gcnArchName` and the portable `warpSize`. | [device-query.md](./device-query.md) |
| HIPRTC Runtime Compilation | Compile a kernel from source text at runtime with `hiprtcCreateProgram`/`hiprtcCompileProgram`, targeting the current device's architecture, then load the resulting code into a module and launch it. | [hiprtc-runtime-compilation.md](./hiprtc-runtime-compilation.md) |
| rocBLAS GEMM | Perform a matrix-matrix multiply on device memory with `rocblas_sgemm`, using a `rocblas_handle` created once and reused across calls. | [rocblas-gemm.md](./rocblas-gemm.md) |
