# Callbacks

Callbacks are an advanced feature that hooks into a specific agent's execution with Python code, to observe, customize and control agent behavior at predefined points of a conversational turn. Each callback type requires a specific primary function name; helper functions can have any name. Multiple callbacks of one type run in the order defined.

## Signature / Usage

### before_agent_callback

| X | X |
|---|---|
| Name | before_agent_callback |
| Execution | Called before the agent is invoked. |
| Purpose | Useful for setting up resources or state needed for the agent, performing validation checks on the session state, or avoiding agent invocation. |
| Arguments | CallbackContext |
| Return | Content (optional): If set, agent is not invoked, and the provided response is used. |
| ADK callback | [before agent callback](https://google.github.io/adk-docs/callbacks/types-of-callbacks/#before-agent-callback) |

### after_agent_callback

| X | X |
|---|---|
| Name | after_agent_callback |
| Execution | Called after the agent completes. |
| Purpose | Useful for cleanup tasks, post-execution validation, modifying final state, or updating the agent response. |
| Arguments | CallbackContext |
| Return | Content (optional): If set, replace the agent's output with the provided output. |
| ADK callback | [after agent callback](https://google.github.io/adk-docs/callbacks/types-of-callbacks/#after-agent-callback) |

### before_model_callback

| X | X |
|---|---|
| Name | before_model_callback |
| Execution | Called before model request. |
| Purpose | Useful for inspection/modification of the model request, or to avoid model use. |
| Arguments | CallbackContext, LlmRequest |
| Return | LlmResponse: If set, model call is skipped, and the response is used as if it came from the model. |
| ADK callback | [before model callback](https://google.github.io/adk-docs/callbacks/types-of-callbacks/#before-model-callback) |

The official page says only that "In your Python callback code, you have access to certain classes and functions that help you write the code" and points to the Python runtime reference (https://docs.cloud.google.com/gemini-enterprise-cx/cx-agent-studio/reference/python) without listing them; the examples on this page use `CallbackContext`, `LlmRequest`, `LlmResponse`, `Content`, `Part`, `FunctionCall`, `Tool`, `Optional` and `Any` without imports, which is not stated in the official docs, so they assume the CX Agent Studio Python runtime provides them.

```python
def before_model_callback(
  callback_context: CallbackContext,
  llm_request: LlmRequest
) -> Optional[LlmResponse]:
  """
  This callback executes *before* a request is sent to the LLM.

  By returning an `LlmResponse` object, we are intercepting the call to the
  LLM. The LLM will *not* be called, and the framework will instead use the
  `LlmResponse` we provide as if it came from the model.

  This is the core mechanism for implementing input guardrails, prompt
  validation, or serving responses from a cache. Here, we force the agent to
  call a function instead of thinking with the LLM.
  """
  # Modify the shared session state.
  callback_context.variables['foo'] = 'baz'

  # Skip the LLM call and return a custom response telling the agent to
  # execute a specific function.
  return LlmResponse(
    content=Content(parts=[Part(
      function_call=FunctionCall(
        name="function_name", args={"arg_name": "arg_value"}))],
      role="model"))
```

### after_model_callback

| X | X |
|---|---|
| Name | after_model_callback |
| Execution | Called after a model response is received. |
| Purpose | Useful for reformatting model responses, censoring sensitive information generated by the model, parsing structured data from the model for use in variables, and model error handling. |
| Arguments | CallbackContext, LlmResponse |
| Return | LlmResponse: If set, replace the model response with the provided response. |
| ADK callback | [after model callback](https://google.github.io/adk-docs/callbacks/types-of-callbacks/#after-model-callback) |

```python
def after_model_callback(
  callback_context: CallbackContext,
  llm_response: LlmResponse
) -> Optional[LlmResponse]:
  """
  This callback executes *after* a response has been received from the LLM,
  but before the agent processes it.

  The `llm_response` parameter contains the actual data from the LLM.
  By returning `None`, we are approving this response and allowing the agent
  to use it as-is.

  If we returned a new `LlmResponse` object, it would *replace* the original,
  which is useful for redacting sensitive information, enforcing output
  formatting, or adding disclaimers.
  """
  # Returning None allows the LLM's actual response to be used.
  return None
```

### before_tool_callback

| X | X |
|---|---|
| Name | before_tool_callback |
| Execution | Called before tool calls. |
| Purpose | Useful for inspection and modification of tool arguments, authorization checks before tool execution, or implementing tool-level caching. |
| Arguments | Tool, Dict\[str,Any\]: tool inputs, CallbackContext |
| Return | Dict\[str,Any\] : If set, tool execution is skipped and this output is provided to the model. |
| ADK callback | [before tool callback](https://google.github.io/adk-docs/callbacks/types-of-callbacks/#before-tool-callback) |

```python
def before_tool_callback(
  tool: Tool,
  input: dict[str, Any],
  callback_context: CallbackContext
) -> Optional[dict[str, Any]]:
  """
  This callback executes *before* a specific tool is called by the agent.

  Here, we modify the input arguments intended for the tool and then return
  a dictionary. By returning a dictionary instead of `None`, we are
  overriding the default behavior. The actual tool function will *not* be
  executed. Instead, the dictionary we return will be treated as the
  llm.tool's result and passed back to the LLM for the next step.

  This is ideal for validating tool inputs, applying policies, or returning
  mocked/cached data for testing.
  """
  # Modify the shared session state.
  callback_context.variables['foo'] = 'baz'

  # Modify the arguments for the tool call in-place.
  input['input_arg'] = 'updated_val1'
  input['additional_arg'] = 'updated_val2'

  # Override the tool call and return a mocked result.
  return {"result": "ok"}
```

### after_tool_callback

| X | X |
|---|---|
| Name | after_tool_callback |
| Execution | Called after tool completion. |
| Purpose | Useful for inspection and modification of tool response before sending back to the model, post-processing of tool results, or saving specific parts of a tool response to variables. |
| Arguments | Tool, Dict\[str,Any\]: tool inputs, CallbackContext, Dict\[str,Any\]: tool response |
| Return | Dict\[str,Any\]: If set, this overrides the tool response which is provided to the model. |
| ADK callback | [after tool callback](https://google.github.io/adk-docs/callbacks/types-of-callbacks/#after-tool-callback) |

### Custom payload from after_model_callback

Adapted (not in the official docs): the callback returns `None` (keeps the model response) when `llm_response.content` is missing or has no parts, instead of reading `parts[0]` unconditionally, the payload is added when any part has text (`any(part.text is not None for part in llm_response.content.parts)`) instead of only when the first part has text, so a response whose text follows a non-text part also gets the payload, and the new response keeps all original parts in order (and the content's `role`) and appends the payload, instead of keeping only the first text part.

```python
import json

def after_model_callback(callback_context: CallbackContext, llm_response: LlmResponse) -> Optional[LlmResponse]:
 """
 Adds a custom payload to every model response which is a text
 """
 if llm_response.content is None or not llm_response.content.parts:
   return None
 if any(part.text is not None for part in llm_response.content.parts):
   # construct payload
   payload_dict = { "custom_payload_key": "custom_payload_value"}
   payload_json_string = json.dumps(payload_dict)

   new_parts = []
   # Keep the origial agent response part, as model only sees text in the historical context.
   new_parts.extend(llm_response.content.parts)

   # Append custom payload
   new_parts.append(Part.from_json(data=payload_json_string))

   return LlmResponse(content=Content(role=llm_response.content.role, parts=new_parts))
```

## Notes

- Sandbox: Python callback code runs in a sandboxed environment. No Private network access (PNA): callbacks cannot reach private IP addresses or resolve private DNS domains, even if Service Directory is configured; use a tool type that supports Private network access (OpenAPI or MCP tools) instead. Callbacks can only access endpoints publicly available on the internet.
- Create a callback: open the agent settings, **Add code**, select a callback type, provide Python code, **Save**. Classes and functions available to callback code are in the Python runtime reference; the channel or modality of a conversation can be checked with the `_session` global variable.
- Custom payloads: supplementary non-textual structured data (typically JSON) in an agent's response, for example agent escalation/handoff routing instructions (such as a queue), or rich content and client-side actions (image URLs, quick-reply chips). They can be returned alone deterministically, with an LLM-generated text response, or with a static text response. The payload value is not visible to the LLM. Payloads are generated and set only in callbacks (`before_model_callback` or `after_model_callback`), as a Blob with `mime_type` `application/json`, created with `Part.from_json(data=payload_string)`.
- At runtime the payload is populated as a Struct in the `payload` field of both `RunSession` and `BidiRunSession` of the `ces` v1 SessionService (https://docs.cloud.google.com/gemini-enterprise-cx/cx-agent-studio/reference/rpc/google.cloud.ces.v1#google.cloud.ces.v1.SessionService.RunSession).
- Corrected from the official docs: the custom payload sample reads `if (llm_response.content.parts[0].text is not None):` without checking that `content` and `parts` exist, so it raises `IndexError` on a response with an empty parts list (and fails if `content` or `parts` is unset; in ADK, `LlmResponse.content` is `types.Content | None` in `google-adk` 2.15.0 `llm_response.py`, which is an analogy not confirmed for the CX Agent Studio runtime), and rebuilds the response as `new_parts.append(Part(text=llm_response.content.parts[0].text))` plus the payload in `LlmResponse(content=Content(parts=new_parts))`, which drops every other part (later text parts, function calls) and the content's `role`. The page returns `None` when there are no parts (the `after_model_callback` sample above says returning `None` keeps the response as-is), copies all parts in order with `new_parts.extend(llm_response.content.parts)`, and passes `role=llm_response.content.role`. The source's docstring says the callback "Adds a custom payload to every model response which is a text", but its condition checks only `parts[0].text`, so a response with a non-text first part followed by a text part gets no payload; the page checks every part with `any(part.text is not None for part in llm_response.content.parts)`, keeping the source's `is not None` test (in `google-genai` 3.6.1 `types.py`, `Part.text` is `Optional[str]` and `Content.parts` is `Optional[list[Part]]`; an analogy, not confirmed for the CX Agent Studio runtime).
- The source's `before_tool_callback` sample overrides the tool and returns a mocked result; the `before_model_callback` sample skips the LLM call and forces a function call.
- The source also has code samples for `before_agent_callback` (set a default `username` variable), `after_agent_callback` (increment a per-agent counter), `after_tool_callback` (override a `get_user_info` response) and a `before_model_callback` custom payload when an `escalate` tool is called; they are omitted here.
- Source: https://docs.cloud.google.com/gemini-enterprise-cx/cx-agent-studio/callback (retrieved 2026-11-21; CC BY 4.0, code samples Apache 2.0)
