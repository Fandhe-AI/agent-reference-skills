# Diff engines: pg-delta and migra

A diff engine compares two database states and generates the SQL that turns one into the other. It powers `supabase db diff`, `supabase db pull`, and `supabase db schema declarative`. The CLI ships `pg-delta` (open source, default for recent `supabase init`) and the legacy `migra`.

## Signature / Usage

```toml
# supabase/config.toml  (written by a recent `supabase init`)
[experimental.pgdelta]
enabled = true
```

```bash
# Switch an existing project to pg-delta: add the section above, remove
# [db.migrations].schema_paths if used, then create a catch-up migration
supabase db pull
supabase db schema declarative sync   # replaces `db diff` for declarative files
supabase db reset                     # verify the full chain locally
supabase db diff --strict-coverage    # optional CI check
```

## Options / Props

Per-run engine selection (without changing `config.toml`):

| Command | Flag to use `pg-delta` | Flag to use `migra` |
|---------|------------------------|---------------------|
| `db diff` | `--use-pg-delta` | `--use-migra` |
| `db pull` | `--diff-engine pg-delta` | `--diff-engine migra` |
| `db schema declarative generate` and `sync` | `--experimental` | Not available |

Behavior differences:

| Behavior | `pg-delta` | Legacy `migra` |
|----------|------------|----------------|
| What `db diff` compares | Live database vs a shadow database built from migrations; never reads `supabase/schemas/` | Live database vs migrations, unless `supabase/schemas/` has declarative files (then those vs migrations) |
| Migrations from declarative files | `supabase db schema declarative sync` | `supabase db diff` with the local stack stopped |
| Export database to declarative files | `supabase db schema declarative generate` | Not available; use `supabase db dump` and split by hand |
| Declarative file ordering | Automatic by statement dependencies; `[db.migrations].schema_paths` ignored (CLI warns) | Lexicographic; `schema_paths` overrides; `supabase/schemas/` used even if the setting is empty |
| Initial `db pull` (empty history) | Diffs remote vs empty shadow DB; includes customizations in managed schemas (e.g. triggers on `auth.users`, RLS on `storage.objects`) | Seeds with `pg_dump` (skips managed schemas) then appends a diff of triggers and RLS policies in `auth` / `storage` |
| Later `db pull` | Diffs remote vs migrations | Same |
| `db pull --declarative` | Replaces `supabase/schemas/` from the selected database without creating a migration | Runs, but don't use it (points `schema_paths` at the written tree; the next `db diff` can fail on ordering) |
| Untracked objects | Warnings, never silently dropped; `--strict-coverage` makes them failures | Silently omitted; `--strict-coverage` has no effect |
| Generated SQL | Uppercase keywords wrapped at 180 chars; `[experimental.pgdelta] format_options` | Engine default |
| Migration files per run | Usually one; may write ordered `_1`, `_2` files across transaction boundaries; non-transactional files start with `-- pg-delta: transaction=false` | One file |

## Notes

- Engine selection: `[experimental.pgdelta]` with `enabled = true` means `pg-delta`; missing section or `enabled = false` means `migra`. `SUPABASE_EXPERIMENTAL_PG_DELTA=1` (shell or `supabase/.env`) equals `enabled = true` for `db diff` / `db pull`; an explicit engine flag wins. Set `enabled = false` to opt out.
- `pg-delta` loads each state into a real Postgres instance and reads the catalog; it models comments, domains, roles, publication membership, and the security invoker setting on views, supports Postgres 14 through 18, and is pre-1.0 under the `[experimental.pgdelta]` namespace.
- `migra` is `djrobstep`'s Python library; the CLI has shelled out to it since before `pg-delta`. Existing projects without the section keep it.
- The first `db pull` after switching captures objects the legacy engine didn't track in one catch-up migration. Accept the prompt to record it as applied (remote already has them). If the baseline came from the legacy `pg_dump` path it reports "No schema changes found".
- Replace `supabase db diff` with `db schema declarative sync` in scripts, CI, and AI prompt files; no `supabase stop` needed first.
- The GitHub integration (branching) runs every migration in a transaction and doesn't honor `-- pg-delta: transaction=false`; such a migration applies with `supabase db push` but fails under branching.
- Migrations already generated by `pg-delta` are plain SQL and work on either engine.
