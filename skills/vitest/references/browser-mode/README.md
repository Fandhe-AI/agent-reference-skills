# Browser Mode

| Name | Description | Path |
|------|-------------|------|
| ARIA Snapshots | Experimental (Vitest 4.1.4+). Assert against the accessibility tree with `toMatchAriaSnapshot()` / `toMatchAriaInlineSnapshot()`. | [aria-snapshots.md](./aria-snapshots.md) |
| Assertion API (expect.element) | DOM assertions forked from `@testing-library/jest-dom`, with locator support and built-in retry via `expect.element`. | [assertions.md](./assertions.md) |
| Browser Config (browser.*) | All `test.browser.*` options in one place: enabling, providers (`playwright` / `webdriverio` / `preview`), instances, UI, locators, screenshots, tracing and commands. | [browser-config.md](./browser-config.md) |
| Commands | A command is a function that runs on the Vitest server and passes the result back to the browser. | [commands.md](./commands.md) |
| Component Testing | Test individual UI components in isolation using Browser Mode (real browsers via Playwright, WebdriverIO or preview). | [component-testing.md](./component-testing.md) |
| Context API | The `vitest/browser` entry point exports `userEvent`, `commands`, `page`, `cdp`, `server` and `utils` for use in browser tests. | [context-api.md](./context-api.md) |
| Interactivity API | `userEvent` from `vitest/browser` implements a subset of `@testing-library/user-event` using Chrome DevTools Protocol or WebDriver instead of faking events. | [interactivity-api.md](./interactivity-api.md) |
| Locators | A locator represents one or more elements via a selector string generated by `page.getBy*` methods. | [locators.md](./locators.md) |
| Multiple Setups | Run several browser setups with `browser.instances`; all share one Vite server, so transforms and dependency pre-bundling happen once (better caching than test projects). | [multiple-setups.md](./multiple-setups.md) |
| Browser Mode (Getting Started) | Run tests natively in the browser, with access to browser globals like `window` and `document`. | [overview.md](./overview.md) |
| Playwright Traces | Generate Playwright trace files (`.trace.zip`) for browser tests by setting `browser.trace`. Playwright provider only. | [playwright-traces.md](./playwright-traces.md) |
| Render Function (vitest-browser-react / vue / svelte) | Community packages that render framework components in Browser Mode and return locators scoped to the rendered `baseElement`. | [render-function.md](./render-function.md) |
| Trace View | Experimental (Vitest 5.0.0+). `browser.traceView` records browser interactions as DOM snapshots (rrweb) and replays them step by step in the browser UI, Vitest UI or HTML reporter. | [trace-view.md](./trace-view.md) |
| Visual Regression Testing | Capture screenshots of components or pages and compare them with reference images using the `toMatchScreenshot` assertion. | [visual-regression-testing.md](./visual-regression-testing.md) |
| Why Browser Mode | Motivation and drawbacks of running Vitest tests in a real browser instead of a simulated one (jsdom / happy-dom). | [why.md](./why.md) |
