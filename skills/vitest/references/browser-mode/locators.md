# Locators

A locator represents one or more elements via a selector string generated by `page.getBy*` methods. Based on Ivya (a fork of Playwright locators), available for every provider.

## Signature / Usage

```ts
function getByRole(role: ARIARole | string, options?: LocatorByRoleOptions): Locator
function getByAltText(text: string | RegExp, options?: LocatorOptions): Locator
function getByLabelText(text: string | RegExp, options?: LocatorOptions): Locator
function getByPlaceholder(text: string | RegExp, options?: LocatorOptions): Locator
function getByText(text: string | RegExp, options?: LocatorOptions): Locator
function getByTitle(text: string | RegExp, options?: LocatorOptions): Locator
function getByTestId(text: string | RegExp): Locator

function nth(index: number): Locator
function first(): Locator
function last(): Locator
function and(locator: Locator): Locator
function or(locator: Locator): Locator
function filter(options: LocatorFilterOptions): Locator
```

```ts
import { expect } from 'vitest'
import { page } from 'vitest/browser'

const deleteButton = page
  .getByRole('row')
  .filter({ hasText: 'Vitest' })
  .getByRole('button', { name: /delete/i })

await deleteButton.click()
await expect.element(deleteButton).toBeEnabled()
```

Custom locators (3.2.0+, advanced):

```ts
import { locators } from 'vitest/browser'

locators.extend({
  getByArticleTitle(title) {
    return `[data-title="${title}"]`
  },
})

declare module 'vitest/browser' {
  interface LocatorSelectors {
    getByArticleTitle(title: string): Locator
  }
}
```

## Options / Props

`getByRole` options:

| Name | Type | Description |
|------|------|-------------|
| name | string \| RegExp | Accessible name; matched exactly (case-sensitive, whole-string) by default because `browser.locators.exact` defaults to `true`; use `exact: false` or a RegExp for case-insensitive substring matching |
| exact | boolean | Case-sensitive whole-string match; defaults to `browser.locators.exact`; ignored for RegExp |
| checked | boolean | `aria-checked` / checkbox state filter |
| disabled | boolean | Disabled state (inherited) |
| expanded | boolean | `aria-expanded` filter |
| includeHidden | boolean | Include elements excluded from the accessibility tree |
| level | number | `aria-level` / heading level |
| pressed | boolean | `aria-pressed` filter |
| selected | boolean | `aria-selected` filter |

`filter` options:

| Name | Type | Description |
|------|------|-------------|
| has | Locator | Match elements containing the locator (queried relative to the parent) |
| hasNot | Locator | Match elements not containing the locator |
| hasText | string \| RegExp | Match elements containing text (case-insensitive substring for strings) |
| hasNotText | string \| RegExp | Match elements not containing text |

`findElement` options: `timeout` (ms, defaults to test timeout), `strict` (default `true`; `false` returns the first match). Properties: `selector` (provider-specific string, only for the Commands API) and `length` (`locator.elements().length`).

## Notes

- The upstream `name` option text still says matching is case-insensitive substring by default, but in v5 `browser.locators.exact` defaults to `true` (see migration-v5), so exact matching applies unless `exact: false` or a RegExp is used.
- `getBy*` return locators, not DOM elements; chain (`.getBy*`, `.filter`, `.nth`) instead of testing-library's `within(...)`. All action methods are async and must be awaited (tests fail if not, since Vitest 3).
- `getByRole` matches roles by string equality without ARIA role hierarchy (`checkbox` does not match `switch`). Prefer `getByRole` over `getByText` for interactive elements; use `getByTestId` last (attribute configurable via `browser.locators.testIdAttribute`).
- `getByTitle` cannot find `title` elements inside SVG. `getByText` normalizes whitespace even with `exact`.
- `query()` / `element()` are strict and throw on multiple matches (`element()` also throws on none); `elements()` never throws; `findElement()` retries with increasing intervals (0, 20, 50, 100, 100, 500ms).
- `or()` matching multiple elements makes single-element methods throw.
- `selector` is Playwright syntax with `playwright`, CSS with `preview` / `webdriverio`; do not use it in tests. Locator arguments to commands are serialized automatically.
- `screenshot` returns base64 when `save` is `false` (3.2.0+); default path uses `browser.screenshotDirectory`.
- Source: https://vitest.dev/api/browser/locators (Vitest v5.0.5)
